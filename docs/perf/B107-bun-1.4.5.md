# B107: webhook `list_ids` on Bun 1.4.5

Decision: [D115](../design/09-decisions.md#d115-bun-145-and-json-arrays-from-sqlite-are-converted-explicitly-lead-2026-11-20).

## Root cause reproduction

A minimal `bun:sqlite` script, one subscriber with two list memberships, run on each runtime. The
first column is the SQL the webhook queries use, `json_object('list_ids', (SELECT json_group_array(list_id) …))`;
the second wraps the subquery in `json(...)`.

| Runtime | Bundled SQLite | Scalar subquery | Subquery wrapped in `json()` |
|---|---|---|---|
| `oven/bun:1.4.4` | 3.53.4 | `{"list_ids":[1,2]}` | `{"list_ids":[1,2]}` |
| `oven/bun:1.4.5` | 3.54.1 | `{"list_ids":"[1,2]"}` | `{"list_ids":[1,2]}` |
| macOS host, Bun 1.4.5 | 3.54.0 | `{"list_ids":[1,2]}` | `{"list_ids":[1,2]}` |

The aggregate shape that `webhook-blocklisted` and `webhook-deleted` use, `json_group_array` over
`json_object` with the subquery inside, gives `[{"list_ids":"[1,2]"}]` on 1.4.5 and
`[{"list_ids":[1,2]}]` once wrapped. On 1.4.4 the wrapped and unwrapped forms are byte-identical, so
the wire format does not change on the older runtime.

The mechanism: a scalar subquery's `json_group_array` result lost its JSON subtype on the 1.4.5
bundle, so `json_object` stored it as text. The 3.54.1 change itself is not confirmed; the fix does
not depend on it.

## Tests before and after the fix

Scope: `test/webhooks/webhooks.test.ts` and `test/bounces/bounces.test.ts` together, 48 tests, run
in `oven/bun:1.4.5` unless stated.

| Commit | What it is | Result |
|---|---|---|
| `8c51b46` | new `list_ids` array test, no fix | 43 pass, 5 fail: the four named tests and the new test |
| `250068a` | `json()` in `src/subscribers/store.sql` | `test/webhooks`, `test/bounces`, `test/sends`: 107 pass, 0 fail |
| `8c51b46` | no fix | on `oven/bun:1.4.4`: 48 pass, 0 fail |
| `250068a` | the fix | on `oven/bun:1.4.4`, full `bun run check`: 1539 pass, 0 fail |

The four named tests are `a stored bounce delivery is cleared by the delete action and by a wipe`,
`every listed event reaches the receiver correctly signed`, `a public wipe stores and delivers only
the numeric ID and UUID, on older rows too`, and `bulk actions queue the bytes a single action would,
each with its own id`.

## Cost

The change is one `json()` around two subqueries in a statement that runs once per admitted bulk
action or subscriber event. It re-encodes a short array and adds no read, write or transaction, so no
timing was measured.
