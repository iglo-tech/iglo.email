# M2.5 public pages: before and after

Required by AGENTS.md: this work changes sending and storage. "Before" is reviewed head `ae8ba23`; "after" is the fix branch. Reproduce with `bun run public:measure`, copying `test/public/measure.ts` into a checkout of the other commit.

Setup: Bun 1.4.4 on the shared 16 GiB development VM, file-backed database on `/dev/sda1` at FULL synchronous, one process, requests through the router without a socket. Runs alternated in pairs. The third pair ran under host disk contention, visible in both columns, so compare within a pair. These are synthetic results, not a capacity claim.

## Signup answer by subscriber state

Median milliseconds over 150 interleaved rounds of `POST /api/public/subscription`.

| Run | State | Before | After |
|---|---|---:|---:|
| 1 | new address | 8.54 | 6.12 |
| 1 | pending | 5.43 | 6.21 |
| 1 | confirmed | 5.06 | 6.12 |
| 1 | blocklisted | 4.84 | 6.12 |
| 2 | new address | 9.15 | 6.26 |
| 2 | pending | 5.88 | 6.30 |
| 2 | confirmed | 5.86 | 5.97 |
| 2 | blocklisted | 5.45 | 5.88 |
| 3 | new address | 16.47 | 9.89 |
| 3 | pending | 9.18 | 10.41 |
| 3 | confirmed | 8.55 | 10.74 |
| 3 | blocklisted | 8.55 | 10.24 |

Before, a new address took about 3 ms longer than every other state, and about 8 ms longer under contention. After, the states differ by at most 0.33 ms in the quiet runs and 0.85 ms in the contended run, with no state consistently slowest. The other states take about 0.5 ms longer than before because every signup now enters the queue and all share one path.

Mail preparation left the request path. In this run the fixture clock does not advance, so the table excludes it. It runs on a one-second tick, at most 20 mails per tick, and is never woken by a request. Opt-in mail can start up to a second later than before. The queue holds at most 5,000 subscribers.

## Journal and storage

| Measurement | Before (runs 1, 2, 3) | After (runs 1, 2, 3) |
|---|---|---|
| Unlinked transactional enqueues, commits per second | 1,032, 1,039, 215 | 954, 1,018, 214 |
| Journal storage per unlinked row, bytes | 321 | 355 |
| Database with 100,000 unlinked rows, MiB | 33.16 | 35.73 |
| Bulk insert of 100,000 rows, ms | 703, 738, 883 | 755, 780, 937 |
| Wipe with 100 linked sends in that journal, median ms | 7.60, 6.41, 11.20 | 7.66, 8.36, 15.97 |
| Wipe, p95 ms | 11.86, 11.88, 18.54 | 15.20, 16.47, 22.91 |

Migration 9's partial index costs about 34 bytes per unlinked send, about 8% more bulk-insert time, and no measurable change to single-commit enqueues beyond run noise. Linked sends are outside the partial index, so their storage does not change. A wipe now rewrites its sends: about 1 to 5 ms for 100 linked rows, in the wipe's transaction. The unlinked lookup goes through the index, so its cost follows the matches, not the journal size.
