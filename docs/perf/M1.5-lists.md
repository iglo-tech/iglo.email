# M1.5 lists: bounded synthetic storage measurements

Measured 2026-10-28 on Linux, Bun 1.4.4, `/dev/sda1` ext4, SQLite WAL,
`foreign_keys=ON`, `synchronous=FULL`, 5 s busy timeout. Each repetition used a
fresh disk-backed directory under the worktree, a compiled server and synthetic
bootstrap/login/API-user provisioning, then removed its own temporary data.
No concurrent password hashing or timing threshold was used. `TMPDIR` was set to
an ext4 directory: this host's default `/tmp` is tmpfs. The three repetitions
were sequential, control first, candidate second, then synthetic fixtures. The
candidate repetitions were rerun after the query-ID overflow and lossless ID projection corrections; the
same control build and configuration were retained.

Control: M1.4 merge `b60a0e8ab96822d2415c181bb95569387082e3d9`, executable
SHA-256 `d6a8745b120b6027972d3867f800475e0c33c6b161ef0cd3be85c63ae924fe4f`.
Candidate: M1.5 implementation built on `5912eaf`, executable SHA-256
`b5beea156ccb94d1feec1040b77c85d32ee1e3089b29507429877a45b5d35ba4`.
The equivalent control is authenticated `GET /api/health`, 10 warmups then 100
samples per run. Mean milliseconds by repetition:

| Path | 1 | 2 | 3 |
|---|---:|---:|---:|
| M1.4 protected health | 0.424 | 0.490 | 0.491 |
| M1.5 protected health | 0.419 | 0.398 | 0.411 |

New paths have no equivalent in the control; these are candidate measurements,
not claimed improvements. Each repetition has five warmups; means in ms:

| Path and samples | 1 | 2 | 3 |
|---|---:|---:|---:|
| create + update + delete, 20 cycles | 6.918 | 6.935 | 7.301 |
| filtered query, 40 lists, 50 samples | 0.798 | 0.832 | 0.795 |
| filtered bulk delete, 3 lists, 10 samples | 1.801 | 2.073 | 1.889 |
| labelled fixture: filter + count sort, 20 lists / 100 memberships, 50 samples | 0.555 | 0.613 | 0.869 |

The fixture uses synthetic memberships of all three membership statuses and
varied global subscriber statuses. It is not a production subscriber API.
This small sequential experiment is not a throughput or scaling guarantee.
The current live count implementation aggregates memberships and filters list
rows before pagination; larger datasets need separate profiling when subscriber
CRUD and caching are implemented.

Reproduction: build the exact control in an isolated source archive, build the
candidate, and run `TMPDIR=<empty-ext4-directory> bun test/lists/measure.ts
<control-executable> control` followed by the same command with the candidate
executable and `candidate`. The latter also runs the labelled count fixture.
Each invocation creates and deletes only its own generated data. `bun run
lists:measure` runs the candidate half; explicitly set `TMPDIR` to an ext4
location if the default temporary filesystem is not disk-backed.

The lead's D34 disposition adds only policy labels and public-boundary
regressions, with no runtime/SQL/dependency change. The same implementation
measurements therefore remain the storage evidence. The additional high-ID
fixture checks safe role-input rejection without mutation, exact list
read/update/delete and preservation of an unrelated list; it does not certify
individual high-ID role grants or large-dataset scaling.

Lead verification after D34 labels/coverage: full bun run check passed 162 tests / 1796 assertions; the focused list fixture had 2 passing tests / 41 assertions; compiled and pinned-reference list corpora and the compiled restart case passed.

## Round-1 lead selector fix

The shared raw-selector regressions passed pinned upstream before changing
production (test commit e266b14). Before the fix compiled contract:lists failed
delete-empty-tag-retained: an explicit empty tag selected and removed an owned
list. The lead separated DELETE's raw first URL fields/all raw tags from
collection cleanup and removed DELETE form-body selection. Afterward the
compiled list corpus/restart and both focused list tests (41 assertions), lint
and typecheck pass. Cases include empty/padded/repeated tags, padded enum
filters, an empty first query and ignored body-only query/all/repeated tags;
every destructive probe is bounded to unique invocation-owned names.

This is not final acceptance for the pending XML/tag decoder changes. The
completion fixer must retain the regressions and add exact before/after
FULL/WAL measurements for the complete D35 implementation.
