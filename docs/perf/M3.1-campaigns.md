# M3.1 campaign test-send measurements

Serial in-process observations from `bun run campaigns:measure` (`test/campaigns/measure.ts`): `POST /api/campaigns/:id/test` through the campaigns fixture (production owners, fake clock, loopback SMTP sink). Bun 1.4.4 on Linux x86-64 6.12.113+deb13, AMD Ryzen 5 1600, shared host that was not reserved. Median of three runs per row. These are not a CI threshold or a hard memory bound: RSS growth is read when the response returns, after rendering and before the queued messages are delivered, and includes allocator noise.

The realistic campaign uses the default template with about 8 KiB of HTML with Liquid fields, five tracked links, the view pixel, an alt body and three templated custom headers (12,748 bytes per delivered message).

"Before" is PR #27 at `b597e77`; "after" is the round-1 fix: every part of a message shares one render budget, a request may render at most 32 MiB and 1,000,000 work units across its recipients (400, nothing queued), and a campaign has at most 32 custom header values.

| Case | Recipients | Before: status / response / delivered / RSS growth | After: status / response / delivered / RSS growth |
|---|---:|---|---|
| Realistic | 1 | 200 / 10.1 ms / 17.2 ms / 0.9 MiB | 200 / 9.0 ms / 15.4 ms / 1.0 MiB |
| Realistic | 10 | 200 / 15.5 ms / 35.8 ms / 3.1 MiB | 200 / 12.7 ms / 32.4 ms / 2.8 MiB |
| Realistic | 100 | 200 / 82.0 ms / 227.2 ms / 11.4 MiB | 200 / 70.0 ms / 202.6 ms / 6.2 MiB |
| Realistic | 1,000 | 200 / 590.4 ms / 1,667.7 ms / 26.0 MiB | 200 / 640.8 ms / 1,747.3 ms / 28.7 MiB |
| Review: ten headers, each `{% for i in (1..512) %}` of 1,024 bytes | 1 | 200 / 11.1 ms / 91.0 ms / 6.1 MiB; 5,247,452-byte message delivered | 500 `Error sending test: invalid template` / 7.5 ms / nothing sent / 2.9 MiB |

The realistic campaign is unchanged within noise up to the 1,000-address maximum and stays far below the aggregate limits (about 12 MiB rendered at 1,000 recipients). Before the fix the review's case grew linearly with recipients (about 5 MiB of headers each, so about 5 GiB retained for 1,000 recipients before SMTP); after it, one message is bounded by the renderer's 4 MiB message budget and one request by 32 MiB of rendered output, with at most four concurrent test sends.
