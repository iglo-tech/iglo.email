## Completion fix: concurrent password proof isolation

The labelled HTTP barrier stops a verified password before session creation.
With the M1.4 starting head, updating account B's display name while account
A's proof was paused made A's login return the login form (HTTP 200, no
session), even though A was unchanged. With account-scoped, bounded active
proofs, the same test issues A's session and its protected profile returns
200. A second barrier case disables and re-enables A before release: the stale
proof does not issue a session, and a fresh password login succeeds. Proof
entries exist only while requests are in flight and are capped at 4,096; a
challenge issuance no longer invalidates proofs belonging to other accounts.
These are observable HTTP tests, not a benchmark or a replacement for the
FULL/WAL measurements above.

## Council round-1 permission-array corrections

The paired role corpus was extended and passed against pinned upstream before
changing production. On the pre-fix candidate, compiled contract:roles failed
D32-POST-omitted-status (200 instead of the decided 400). The focused synthetic
list HTTP test also failed before the fix: clearing an actual list grant with
omitted child permissions returned 400 instead of 200. After the validation
change both pass, including null and explicit [] controls, unchanged user-role
state after rejection, and effective list access changing from true to false.
No SQL, schema, transaction or durability setting changed; invalid user-role
replacements are rejected before storage and list-child clearing reuses the
existing atomic replacement path. The shared corpus retains reference 500 for
missing/null user-role arrays and marks the precise D32 normal 400 correction.

bun test test/users/auth.test.ts -t 'list roles project' before and after;
