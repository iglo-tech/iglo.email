## Sending comparison

`TMPDIR=<owned-ext4-dir> bun run reference:run -- bun test/messaging/measure.ts`
compares M0.8-style non-pooled transports with the actual createEmailer production
owner under Bun. Compiled caller/HTTP correctness is verified separately; this
timing run imports the owner. Both modes use the same generated UTF-8 plain
messages and fresh synthetic 2048-bit RSA key, four producers and a four-physical-
connection cap. Each warms up 100 sends, then three serial 1,000-send repetitions
in ten 100-message windows. Owner: maxMessages 100, maxRequeues 0, idle 30s. Control
waits for observed socket close before the next send, including it in latency.
This differs from M0.8's eight-producer spike and prevents transient socket overlap.
SMTP auth is none here; these timings make no AUTH-handshake latency claim.

## Protected SMTP-test cost

measured compiled production with one sequential client, five warmups/30 samples.
All 35 requests were fully accepted, with 35 distinct IDs and 35 messages removed.

p99/max 16.039 ms. This includes API authentication,
rendering and a temporary SMTP connection with SMTP auth:none. It is not a
campaign or AUTH-handshake measurement; failed/partial cases are correctness gates.
