# M1.6 subscriber storage measurements

Measured 2026-10-28 on Linux with Bun 1.4.4, `/dev/sda1` ext4 and fresh
synthetic disk-backed databases. The production connection uses SQLite WAL,
`foreign_keys=ON`, `synchronous=FULL` and a 5 s busy timeout. Each run starts
its own compiled server, provisions a synthetic bootstrap and API credential,
and removes its data on shutdown. No real mail or production data was used.
All six repetitions were serial, after acceptance and password workloads.
`TMPDIR` pointed to the owned ext4 directory; the directory was removed afterward.

Control source: M1.5 merge `da66ca0b46dff4ef1638ce63d43d72a68d1bec2e`,
compiled executable SHA-256
`3905f83d4cc232e68c8dee0eca8823518f14989da33094894d86bbb388e19046`.
Candidate source: `5b7dd5badb4a5da6af999fa3f9193f4e8a09313f`, compiled
executable SHA-256
`2c05a019c9676c7ef0276eeca5eeb9ffc4b11d471336fe181cc16eb0204ec044`.
The control was built from a `git archive` of the exact source and a frozen
install; both builds used `bun run build`.

Equivalent control and candidate workloads, mean milliseconds:

| Workload | Control 1 / 2 / 3 | Candidate 1 / 2 / 3 |
|---|---|---|
| Protected health, 50 samples | 0.464 / 0.309 / 0.380 | 0.419 / 0.394 / 0.513 |
| List create + update + delete, 20 cycles | 8.355 / 5.379 / 7.543 | 5.293 / 7.775 / 6.367 |
| Filtered list query, 20 lists, 50 samples | 0.873 / 0.821 / 0.785 | 0.943 / 0.786 / 0.721 |

Subscriber operations have no equivalent M1.5 endpoint; these are new costs,
not a before/after comparison. Means in milliseconds:

| Candidate workload | 1 | 2 | 3 |
|---|---:|---:|---:|
| Create + PUT + delete, 20 cycles | 6.583 | 6.819 | 5.659 |
| PATCH, 30 samples | 2.053 | 1.987 | 1.566 |
| Single-ID unsubscribe, 30 samples | 1.501 | 1.701 | 1.388 |
| Single-ID blocklist, 30 samples | 1.102 | 1.463 | 1.076 |
| Remove three memberships, 10 samples | 1.819 | 1.820 | 1.380 |
| List query sorted by count, 50 samples | 0.784 | 0.820 | 0.475 |

Every workload used five warmups. The count workload starts with 100 synthetic
subscribers in two lists (200 memberships); earlier unsubscribe, blocklist and
bulk operations change statuses and remove some memberships before the count
samples. This is a bounded sequential experiment, not a throughput or
large-dataset guarantee, and has no timing threshold. Reproduce using
`test/subscribers/measure.ts` with the control executable and `control`, then
the candidate executable and `candidate`, setting `TMPDIR` to an empty ext4
location. The harness owns and cleans each process and temporary database.

## Round-2 council fixes: before and after

Measured 2026-10-28 with Bun 1.4.4, owned `/dev/sda1` ext4 data and
production WAL/FULL, foreign keys and 5-second busy timeout. Before is the
retained executable from reviewed head `05afd1fa67f586e5946fef1840acdd38dd555ca3`
(runtime equal to `c9dddcf3101e24f8b79980f33f69ec7c18e83e29`), SHA-256
`357d4007892e7a3e3d20eac80d7b4f24b1e00470448c2d87dbe71e396a735c3c`.
After source is `666ebff5f18ef72de3ab2191ea1f5d6836e5a14f`, built by
`bun run build`, SHA-256
`f8e820e169dbcce5fd3574a0c5dbb944b91a717ab9d7f3b21c60edc6a55643f1`.
Both hashes were checked before timing; subsequent report-only commits do
not change runtime/build inputs.

The shared council corpus first passed pinned reference and failed the old
compiled executable at the persisted digraph-name assertion. Expanded
reference/compiled regressions then passed full-value digraph, Greek,
ligature, cased-mark, numeral and word-boundary projections; localized
missing/nonpositive bulk-delete errors and no deletion; D43 NUL create,
retry, recursive keys/values, numeric PUT/PATCH/external atomicity, ignored
metadata and overwritten/null-reset final binding. The implementation uses
pinned Go 1.27.2 Unicode 17 title ranges and Unicode 17 full casing/word-break
data with x/text v0.42.0's actual title-state rules. Its Unicode-3.0 notice
and existing Go BSD notice are embedded and checked through compiled GET/HEAD.
No runtime dependency or schema change.

Before timing, frozen install/assets, JSX/UI, full `bun run check` (162 tests,
1,811 assertions), focused server/contract/list/subscriber tests (69/361),
all compiled normal/auth/roles/fixture/lists/subscribers and pinned
core/auth/roles/lists/subscribers/server/smoke commands passed. The added
compiled notice gate also passed `ui:verify`, format, lint and strict types.
All password, build and acceptance workloads had finished before timing.

Three before repetitions ran serially, then three after repetitions, both
with unchanged `test/subscribers/measure.ts` in candidate mode, five warmups
and the same workloads/sample counts. TMPDIR was owned
`upstream/round2-source/measure-data` on ext4, not `/tmp` tmpfs; each harness
run cleaned its process/database. No other workload was started by this lead
during timing; exclusive host occupancy was not established. Reproduce with
