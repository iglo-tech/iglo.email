# M1.3 authentication and session storage

Initial observations were collected on 2026-10-28 on Linux x86_64, kernel
6.12.113, Bun 1.4.4, with six visible CPUs. Their temporary filesystem was not
recorded and these initial timings do not establish disk-backed performance.
The corrected ext4 comparison below is the disk-backed storage evidence.
Reproduce on the selected disk filesystem from the repository:

```sh
bun install --frozen-lockfile
mkdir -p .auth-measure
df -T .auth-measure
TMPDIR="$PWD/.auth-measure" flock /home/t3-code/.local/state/iglo-email-cos/measurement.lock bun run auth:measure
rmdir .auth-measure
```

The command builds the executable and performs three sequential repetitions.
Each uses fresh synthetic data below the explicit TMPDIR; production opens SQLite in WAL mode
with `synchronous=FULL`. The owned helper stops its process and removes only
its temporary directory. Bootstrap time spans helper startup through the first
successful public health response; it includes process startup, migrations and
the dummy Argon2 hash. The bootstrapped process additionally creates the
primordial role and hashes and inserts the first admin. It is a cold-start
comparison, not an isolated SQL benchmark.

Historical initial timings (temporary filesystem unverified):

| Repetition | Unprovisioned startup ms | Admin bootstrap startup ms | Public `/health` ms/request | Protected `/api/health` ms/request | Login form ms | Password login + session creation ms | Logout ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 413.59 | 481.89 | 0.321 | 0.474 | 0.700 | 148.31 | 0.682 |
| 2 | 422.84 | 491.80 | 0.241 | 0.419 | 0.649 | 151.87 | 0.680 |
| 3 | 337.97 | 570.59 | 0.204 | 0.362 | 1.117 | 133.76 | 0.665 |

Within each bootstrapped process the API user was created through a real login
and the protected user API. Five requests to each health endpoint warmed the
connection and then 80 requests per endpoint ran serially. Both return exactly
`{"data":true}\n`; the public endpoint has no authorization while the protected
endpoint validates a token against SQLite on every request. They have different
security semantics, so the comparison estimates incremental protected-read
overhead only. The observed per-request differences were +0.153, +0.178 and
+0.158 ms; these small samples are sensitive to local scheduling and are not a
throughput or CI threshold.

One login/logout warmup preceded three serial samples per repetition. Login
includes HTTP password verification and the session insert; logout includes the
session delete. Bun's selected Argon2id default was `m=65536,t=2,p=1` (64 MiB
per active hash). Only one hash ran at a time in this measurement; the runtime
policy permits at most four concurrent hashes and 32 queued operations. No
sustained workload, SMTP, forwarding service, or external endpoint was used.
The command prints aggregate durations only and never prints generated tokens,
passwords, hashes, nonces or session IDs.

## Round-3 concurrent-update correction and ext4 controls

Opus reproduced a concurrent disable being overwritten after password hashing.
The lead's four deterministic HTTP cases failed on the reviewed implementation
(status reverted to enabled; an explicit role/status case also lost its list
role). A labelled test route wraps the production auth hash to gate completion;
all updates and observations use public HTTP and production handlers/stores.
No source inspection, timing sleep or production test hook is involved.

Fix `2d75b710c172a5b06dc96179e045d6948cc5344e` resolves all omitted fields and
credential/type-dependent defaults synchronously from the current target inside
BEGIN IMMEDIATE. Hashing remains outside the transaction. Current role
validation, the final-human-admin guard, update and revocation share that write
boundary. All 13 focused user tests pass after the fix, including concurrent
disable/demotion/list-role/type changes, preserved revocation, the new password
and intentional explicit role/status overrides.

The measurement command now adds one invocation-owned human through the real
API, warms one metadata and one password update, then runs ten serial metadata
PUTs and three serial password PUTs per repetition. Role/status are omitted;
responses must retain enabled Super Admin authority. It deletes that user
through HTTP. Both controls use the same script, frozen dependencies, FULL/WAL
and three fresh processes. No timing threshold or concurrency capacity is
claimed; deterministic gates separately establish correctness.

On this host /tmp is tmpfs. The disk controls explicitly set TMPDIR to the
worktree's .auth-measure directory on ext4 /dev/sda1, verified with df -T.
The JSONL records include that selected temporary root. An initial overlapping
fixture/measurement attempt and default-temp runs were discarded; the recorded
baseline and fixed repetitions ran serially under the shared measurement lock
with no concurrent lead tests. Other host scheduling remains uncontrolled. The
empty temporary parent was removed after all owned processes/data cleaned up.
