# M2.6 outbound webhooks

Changes to the unsubscribe and send paths add writes, so this records their cost. Serial, opt-in, not a CI threshold. `bun test/webhooks/measure.ts <executable> <hooks> [n]`: a compiled build over real HTTP on ext4, 1,500 subscribers, then 1,500 events and 1,500 one-click unsubscribes, one client at a time, with a loopback receiver.

Host: shared VM, load average 3 to 4, Bun 1.4.4. `before` is main at afd74d6 and `after` is this branch. All rows below come from one contiguous window, because the same `before` binary measured earlier at a quieter time gave ingest p50 1.8 to 2.2 ms and unsubscribe p50 6.6 to 8.8 ms. Compare within the window, not with those.

| Build | Webhooks | Ingest p50 / p95 / p99 ms | Unsubscribe p50 / p95 / p99 ms | Delivered | Drained after last request |
|---|---:|---|---|---:|---:|
| before | 0 | 5.60 / 8.60 / 11.46 | 10.80 / 17.81 / 21.80 | | |
| after | 0 | 5.71 / 9.39 / 11.78 | 10.88 / 17.93 / 21.72 | | |
| after | 0 | 5.44 / 7.68 / 11.73 | 12.31 / 17.99 / 21.82 | | |
| after | 1 | 5.75 / 9.70 / 12.69 | 17.51 / 26.97 / 31.90 | 1,500 | 27 ms |
| after | 1 | 5.05 / 7.03 / 10.81 | 16.30 / 25.03 / 29.40 | 1,500 | 28 ms |
| after | 20 | 5.69 / 9.28 / 12.04 | 46.16 / 68.39 / 77.96 | 30,000 | 77 ms |

- **Event ingest** does not touch the webhook path; it stays within noise at every webhook count.
- **Unsubscribe with no webhooks** stays within noise: only the extra lookups in the consent path and one read of the enabled webhooks.
- **Unsubscribe with webhooks** adds the delivery rows to its transaction, and the serial client then shares the single writer with the loop's claim and settle commits. Delivery itself stays asynchronous; the request never waits for a receiver.
- **Settling:** the first build committed each outcome separately and took unsubscribe p50 to 148.94 ms with 20 webhooks, 24.10 ms with 1. Finished attempts now settle together in the next claim's commit, which gave the numbers above and is why the outcome of a finished attempt can be lost to a crash (the delivery repeats with the same `id`).

Bulk blocklisting and deletion by query write one delivery per subscriber and webhook inside their existing batches. They were not measured here.
