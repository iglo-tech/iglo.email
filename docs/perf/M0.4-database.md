# M0.4 database measurement

The parent has no application storage. The before measurement is a native
`bun:sqlite` primitives baseline, not an existing-product benchmark.

Command: `bun test/db/measure.ts` (before implementation). Bun 1.4.4,
SQLite 3.53.4, Linux 6.12.113+deb13-amd64 x86_64. Three sequential fresh
databases, each inserting 10,000 synthetic rows in 100 transactions of 100
rows with `BEGIN IMMEDIATE`, bound inserts, WAL, foreign keys, FULL sync and
a 5000 ms busy timeout. Then 10,000 bound lookups and a `VACUUM INTO`
snapshot. Count (10,000), ID sum (50,005,000), all lookup values and snapshot
contents were checked. Temporary directories were owned and removed by the run.

| Native repetition | Insert ms | Lookup ms | Snapshot ms | Main bytes | WAL bytes | Snapshot bytes |

| 1 | 13.211 | 21.739 | 1.209 | 4,096 | 951,752 | 188,416 |
| 2 | 9.397 | 20.885 | 1.153 | 4,096 | 951,752 | 188,416 |
| 3 | 9.359 | 23.240 | 1.158 | 4,096 | 951,752 | 188,416 |
