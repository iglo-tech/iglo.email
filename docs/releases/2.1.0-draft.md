# 2.1.0 release notes (draft)

Draft written by B150e for the 2.1.0 release task, which corrects it against the released head and
puts it in its PR body. It is not a published document.

### Upgrade

2.1.0 reads a 2.0.x data directory and applies project migrations 36 and 37 at start, adding the
source stream's tables and the sequence and enrollment columns for external sources. There is no
manual step. A project without a source behaves as in 2.0.x. As with every upgrade, take a backup
first ([Upgrades](docs/operations.md#upgrades)).

### New features

- **External sources: PocketBase** (D169 to D174). A project can read its users and their activity
  from the application's own PocketBase instead of receiving pushed events. PocketBase stays the
  only store of the events: iglo.email copies none of them. The events API is unchanged, and a
  sequence uses one or the other. Setup is in
  [External sources](docs/operations.md#external-sources) in the operations guide.
- **Source settings and Test connection** (D170). The project Settings page has a "Source" tab
  (the `source.*` project keys): the URL, a service account (the password is masked like the SES
  secret), the events collection and its field mapping, the recipients view, an optional users
  collection with a leaving filter, and grant rules. "Test connection"
  (`POST /api/settings/source/test`) signs in, reads the collections, names any missing field and
  fails when a guest can read the events collection or the recipients view.
- **Private source hosts** (D169). The instance key `sources.private_hosts` (instance Settings →
  Security) lists host names a source URL may use to reach a private address while
  `webhooks.block_private_addresses` stays on. Webhooks never use it.
- **Live records** (D171). Each project with a source subscribes to PocketBase's realtime stream
  for the event names its external sequences and grant rules use. It catches up after any
  reconnect with a 15-second lookback and dedupe, and queues records that fail transiently for up
  to 72 hours. Reconnects are routine and not logged. A stream that cannot connect for 15 minutes,
  or that the source refuses, writes an attention line.
- **Grant rules** (D173). "An event named E (with these `data.*` values) adds the user to these
  lists". The user's subscriber is created or updated from the recipients view (address and name)
  when a record grants a list or starts a sequence. A grant never overrides an unsubscribe, a
  suppression, a blocklist or the view's opt-out field, and never adds to a double opt-in list.
- **External sequences** (D172). `"source": "external"` sequences start on source records, with
  strict `data.*` matching and an optional `trigger.condition` read from the source when the record
  arrives (for example "the second paid order within 180 days"). Step conditions and aggregates
  query PocketBase with the same condition language, re-checked strictly on the rows read. A new
  condition kind, `recipient`, reads a recipients-view field. A source failure is never read as
  false: it is retried for up to 72 hours of one outage, then the enrollment ends `source_error`.
  A trigger record that was deleted ends it `trigger_missing`. The step preview, test sends and
  manual enrollments take a `trigger_external_id`.
- **Address conflicts** (D173). A new address another subscriber holds is resolved: a holder whose
  user moved is moved, and a holder whose user is gone hands over its blocklist and unsubscribes
  and is deleted. Two live users with one address are reported, never merged.
- **Leaving** (D173, D174). A user matching the leaving filter is removed at once. A user deleted
  outright, which PocketBase does not broadcast, is removed when mail would next go to them. A
  person who had unsubscribed or been blocklisted leaves a suppression, so a returning user is not
  mailed marketing again without opting in.
- **Fresh address and name at send time** (D174). With a source, every sequence step and campaign to
  a subscriber with an `external_id` reads the recipients view just before rendering, so mail goes
  to the address and name the application has now. A campaign whose source is down hands the
  current batch back unsent and waits, staying `running`, then sends every recipient once when the
  source answers. A refused recipients view pauses the campaign.
- **`first_name` Liquid filter** (D170). The first word of a name when it is a plausible first name
  (starts with a letter, no `@`, at most 24 characters), else empty:
  `{{ subscriber.name | first_name | default: "there" }}`.

### Changed behaviour and API changes

- **Sequences** carry `source` (`events` by default, or `external`), and enrollments of external
  sequences carry `trigger_external_id` and `trigger_occurred_at`. There are new exit reasons,
  `source_error` and `trigger_missing`. A pushed-event sequence's requests and answers are unchanged
  ([07-api-and-ui](docs/design/07-api-and-ui.md)).
- **Settings.** New project keys `source.*` and the instance key `sources.private_hosts`. A project
  `PUT /api/settings` naming the instance key is `400`, as for every instance key.
- **Campaigns and steps to source-linked subscribers** may change the subscriber's stored address
  and name at send time, and may remove a subscriber the source no longer has (a campaign delivery
  `skipped` with `subscriber_unavailable`; the enrollment ends `canceled`, `subscriber_deleted`).
  Without a source nothing changes; campaign throughput without one is unchanged (measured).

### Measured

- Catch-up: 100,000 records through the stream at 182 records/s on disk (B150b, commit-bound, heap
  under 25 MiB), and 164 records/s on disk through the full record handler (B150d).
- Conditions: one condition at about 0.1 s, ten aggregates at the 10,000-event limit at about 3.5 s
  (B150c).
- Send time: a 10,000-recipient campaign with every recipient looked up at about 2,000 recipients/s
  on disk (B150e).

The performance notes are in `docs/perf/B150*.md`.
