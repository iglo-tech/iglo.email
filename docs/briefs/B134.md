# B134: adopt @cloudflare/oxlint-config and fix what it reports

Owner request 2026-11-21: "implement https://npmx.dev/package/@cloudflare/oxlint-config and fix all the issues it reports". Decision record: D132 (lead, 2026-11-21), appended at the END of `09-decisions.md`. Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, reference recipe, file rules, task-PR acceptance).

The preset (`@cloudflare/oxlint-config` 0.1.0, Apache-2.0, npm provenance from cloudflare/oxlint-config) extends `@nkzw/oxlint-config` 3.0.0 and needs `oxlint` ≥ 1.94 (we pin 1.90.0) and `tsrs` (the type-aware backend). Its README and the migration workflow ship in the package at `skills/migrate-oxlint-config/SKILL.md`; read both from `node_modules` after installing. All three are **dev dependencies** only; nothing reaches the compiled executable.

## Lead probe (main e7b5a65, macOS, `oxlint .` with the preset and our globals/ignores)

21,616 findings: src 10,873, test 10,702, scripts 41. After `oxlint --fix`: 11,451. Largest after the fix: `react/no-unknown-property` 2,424 (src), `no-unsafe-member-access` 2,334 (126 src, 2,208 test), `no-unsafe-type-assertion` 1,347 (368/979), `no-unsafe-assignment` 962 (157/805), `no-non-null-assertion` 921 (385/536). Almost all test-side unsafe findings are in `test/contract/*.ts` and fixtures, which are test code but not named `*.test.ts`, so the preset's test relaxations miss them.

## Lead decisions (record in D132)

1. **Config:** `oxlint.config.ts` at the root replaces `.oxlintrc.json`, spreading the preset as its README says, and carries forward our `no-undef: error`, `env`, the `Bun`/`HTMLRewriter` globals and the three ignore patterns. Pin exact versions (`oxlint`, `tsrs`, `@cloudflare/oxlint-config`); `bun.lock` updated. `bun run lint` stays `oxlint .`; `typecheck` stays as is. It must run in the CI container image (oven/bun:1.4.5, linux arm64 and the x64 CI runner): prove it, including type-aware rules actually running (an unsafe-member-access probe fails).
2. **React rules do not fit and stay off, with the reason beside them:** `react/no-unknown-property`, `react/jsx-key`, `react/checked-requires-onchange-or-readonly`, `react-hooks/*`. The admin and public pages use our in-house JSX runtime rendering HTML strings (AGENTS.md: no client framework): `class`, Alpine's `x-*`/`@*`/`:*` attributes and other HTML attributes are correct there, and there is no reconciliation that keys or hooks serve. `jsx-a11y/*` stays on (fix the two `alt-text` findings).
3. **Test code is test code:** extend the preset's `typeScriptTests` override to every file under `test/` (contract scripts, fixtures, helpers), with the same relaxed rules and no others. `scripts/` stays under the source rules.
4. **`no-console`:** AGENTS.md allows CLI command output and attention/error lines. Scope overrides to the CLI command modules and the one module that writes attention lines, by path; everything else follows the rule (an informational `console.log` in application code is a finding to remove, per AGENTS.md).
5. **Every other rule is fixed, not disabled.** A rule may stay off (scoped as narrowly as possible) only where a fix would change observable behaviour, wire format or a listmonk-compatible result, or cannot be expressed in TypeScript without a lie (for example a cast replaced by an equally unchecked cast). Each such exception is a line beside its config with the reason, listed in the PR and D132; the lead decides on them at review. Silencing with inline `oxlint-disable` comments counts as disabling and needs the same reason.
6. **No behaviour change.** Narrow with real checks (a type guard, a `typeof`/`in` test, a schema-validated parse) rather than a new cast; replace `!` with an explicit check that throws or handles the case already handled implicitly. Do not change error messages, HTTP results, SQL or stored formats. Where a fix needs a guard on a hot path (sending, rendering, the runner), keep it O(1) and say so.

Lead decisions on the first worker's exceptions (recorded in D132):

- `@nkzw/no-instanceof` off for the twelve listed files: accepted. Those checks are for own error classes, Promise, Response, Uint8Array and liquidjs Output/Drop, where a duck-type check would also accept thenables and look-alikes and so change behaviour.
- `typescript/no-explicit-any` off for the seven JSX-runtime and settings files: accepted for now. Typing props and settings as `unknown` gives 479 and 128 type errors; a per-key settings schema and typed component props are a design change, not a lint fix.
- `quality/no-chained-type-assertions` off for `src/messaging/email.ts`: accepted (the Nodemailer envelope boundary, where @types/nodemailer lacks the address objects).
- `quality/no-conditional-empty-object-spread` (B134d): JSON key order of an API response, webhook payload or stored JSON is observable. Fix where the object never reaches a wire or stored format; where it does, keep the spread and scope the rule off by file with that reason. Never replace it with `: undefined` (that only hides the pattern and can add a key).
