## Behavior

1. **Routes and permissions.** All `/api/campaigns` routes above, with upstream's permissions (`campaigns:get_all`/`get`, `manage_all`/`manage`, `send`), list-scoped visibility, response envelopes, paging, search and ordering.
2. **Content.**
   - Content types `richtext`, `html`, `markdown`, `plain` (and `visual` if upstream's pinned commit supports it), converted between types as upstream does for real dashboard requests (`POST /:id/content`).
   - Templates render with the M1.8 Liquid renderer using listmonk-compatible campaign data. Preview renders with a sample or the requesting user's subscriber context, as upstream does.
   - Archive settings and archive preview work as upstream.
3. **Status changes** follow upstream's state machine (`draft`, `scheduled`, `running`, `paused`, `cancelled`, `finished`) and validation (`send_at` for scheduled; no edits while running). Moving to `running` or `scheduled` only records the state. The runner (M3.2) picks it up later. Don't send to lists here.
4. **Test sends** (`POST /:id/test`) render per recipient and send directly through the emailer to the given addresses, as upstream does, with the marketing unsubscribe URL and headers and tracking links. They don't touch the campaign's counters or cursor.
5. **Deletion and bulk deletion** follow upstream, including restrictions on running campaigns.
