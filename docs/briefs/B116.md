# B116: every skipped send or enrollment carries a visible reason

Branch `task/B116-skip-reasons`. PR title "B116: visible skip reasons". Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, reference recipe, file rules, task-PR acceptance = the whole `ci.yml` check job with one valid `bun run check`; decision records appended at the END of `09-decisions.md`). Source: the first adopter's scenario and visual audit of main 08ac50f (53 real sends, 8 step tests, 219 screenshots at 1280 and 390 px). For any ported route or mail you change, read pinned upstream (GitHub, 6fcd95f) and list resulting differences in `07-api-and-ui.md` with reasons. Also source: B103 fault injection (campaign consent skip journaled `skipped` with no reason).

## Findings

1. A campaign consent skip (subscriber unsubscribed between selection and send) is journaled `skipped` with no reason; nothing in the product shows it.
2. A blocklisted subscriber's sequence events start no enrollment and record nothing, for marketing and transactional steps alike; the operator cannot see why mail did not go.

## Task

- Every send row journaled `skipped` carries a machine-readable `reason` (existing reasons where they exist, plus `unsubscribed`, `blocklisted`, `late`, `capped`, `render_failed`, `suppressed` once B124 lands; enumerate from the code), exposed on `GET /api/sends`, the subscriber's sends, and the admin send views (B127 shows them).
- A sequence event that would start or advance an enrollment but cannot because the subscriber is blocklisted (or, after B124, suppressed for marketing) records that outcome visibly: the event's response (`enrollments` / a `skipped` entry with reason, if the events API returns per-sequence outcomes; otherwise an enrollment row in a terminal `skipped` state with the reason, whichever fits the data model with the least new surface; decide and record in a decision appended at the end of `09-decisions.md`), and the subscriber's timeline in the admin shows it.
- No attention line: these are normal outcomes (AGENTS logging rule).
- OpenAPI schemas and `07-api-and-ui.md` updated.

## Tests (through HTTP)

Each skip path produces its reason visible through the API: consent skip during a campaign (unsubscribe between selection and send with the injected clock), blocklisted subscriber's event for a marketing and a transactional sequence, late, capped.
