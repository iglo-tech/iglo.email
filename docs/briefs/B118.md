## B118a: send path and runtime edges

Branch `task/B118a-runtime-edges`, PR title "B118a: send-rate restart, tx yield and runtime races". Decision D140 (lead, 2026-11-23) for the decided items.

1. Send-rate restart boundary. The limiter is in memory, so after a restart the first send can follow the last pre-restart send at once (B120 trace: 50 ms apart at 1/s). Make the first send after start wait one interval. Add a test and a perf note under `docs/perf/`. A throttled marketing send is failed, never retried.
2. A transactional send to several recipients converts them back to back without yielding: 4 recipients of the worst allowed template blocked `/health` for 1.49 s. Either yield between recipients or lower the held cap, and measure the effect.
3. An SMTP server that accepts the connection and never answers leaves a send `unknown` (`src/messaging/email.ts`, around line 751). For marketing that is the at-most-once rule. Decide whether a transactional send counts as "not sent" when nothing after the greeting was written, document the decision in 04, and test it. Never retry anything that may have reached the server.
4. A marketing step's send is recorded but its enrollment has not advanced yet when an unsubscribe ends the enrollment, so a transactional step after it does not send (B130 r3). Decide, document in 05 and test.
5. Release script port race. The script picks a free port, closes it, then starts the server on it, so a parallel test can take the port. Bind port 0 and read the bound port, or hold the socket.
6. `reference:smoke` failed once with "Invalid startup runner PID". Find the race in the smoke script and fix it.
7. `backup` fails on macOS system SQLite with "output file already exists", because `src/backup/snapshot.ts` creates the empty target before `VACUUM INTO`. Let `VACUUM INTO` create the file.
8. Shutdown does not cancel the start-up webhook target check (up to 10 s).
9. Under amd64 emulation, timed-out test bodies keep running. Make `cli.test.ts` and `query-limits.test.ts:53` abort their own work on timeout and assert the deadline outcome, not a count.
10. The 5 s compiled-server readiness budget is the remaining flake source on a loaded host. Make readiness event-driven, or raise the budget with a stated reason; then try `--parallel=8` and record the result in `docs/perf/test-speed.md`.

Owns: `src/messaging/*`, `src/tx/*` (conversion loop), `src/scheduler/*` (item 4 only), `src/backup/snapshot.ts`, `src/main.ts` shutdown, `scripts/release*`, the reference smoke script, `test/production-build.ts` and the readiness helper, related tests, D140, 04, 05, `docs/perf/`. Acceptance: `contract:messaging`, `contract:tx`, `contract:sequences`, `contract:maintenance`, `reference:smoke` (reference recipe), `contract:normal`. On macOS, also `bun run check` once.

## B119: media buffer reachable after GC under load

Branch `task/B119-media-buffer`, PR title "B119: media buffer held after GC". Decision D141 (lead, 2026-11-23) if it is accepted rather than fixed.

Under load, a media upload's buffer stays reachable after GC. Find the holder with a heap snapshot (`Bun.generateHeapSnapshot`, or `bun:jsc` `heapStats`) taken after a forced `Bun.gc(true)`, in a test that drives uploads through HTTP. Then either fix it, with a test that fails before the fix (the bytes are not reachable after N uploads and GC), or accept it with evidence: the bound, why it is bounded, and a perf note under `docs/perf/`.

Owns: `src/media/*`, `test/media/*`, `docs/perf/`. Acceptance: `contract:media`, `contract:media:reference`, `contract:normal`.
