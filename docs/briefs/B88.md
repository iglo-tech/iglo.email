# B88: `number` Liquid filter

Common rules: [_B84-common.md](_B84-common.md). Branch `task/B88-number-filter`. PR title "B88: number Liquid filter". Decision record: D102. Depends on B85 (merged). Ships in 1.2.0 with B84–B86.

## Problem

B85 gives templates computed totals (`aggregates.*`), but the allowed filters (`default`, `upcase`, `strip`, `raw`, `t`, `date`, `track_link`) cannot format a number, so a summary email reads "you pulled 1234567 items". Apps used to pre-format numbers into event data; they cannot for numbers iglo.email computes.

## Decided (D102)

One new filter, `number`, registered in `src/templates/renderer.ts` beside the others with the same treatment (scalar input only, bounded work and output, counted like the other filters):

- `{{ 1234567 | number }}` → `1,234,567`; `{{ 1234.5678 | number }}` → `1,234.568` (en-US grouping, `Intl.NumberFormat("en-US")` defaults: at most 3 fraction digits, rounded half-expand); negatives `-1,234`; `0` → `0`.
- Input: a finite JavaScript number. Anything else (string, including a numeric string, boolean, nil, object, array) passes through unchanged, as the value would render without the filter (nil renders empty). Document it.
- No arguments; any argument is a render/compile error like other filters' bad arguments. No locale argument: the app ships English only (D89 defers translations); when translations exist, the filter may follow the app language. Say so in D102.
- Output is bounded by the number's size (≤ ~40 characters); state it.
- Applies wherever the shared renderer runs (campaign, transactional, sequence step, opt-in and other templates), since they share the filter set.

## Tests

Through public boundaries: a tx send (`POST /api/tx`) or a sequence step rendered into the SMTP sink, and template preview/validation API: integer grouping, fraction rounding, negative, zero, large safe integer, numeric string unchanged, nil empty, object/array unchanged as without the filter, an argument refused, combined with `default` (`{{ x | default: 0 | number }}`), and `aggregates.items | number` from a B85 step.
