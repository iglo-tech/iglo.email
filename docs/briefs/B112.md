# B112: test-send unsubscribe link opens an explanatory page

Branch `task/B112-test-unsubscribe-page`. PR title "B112: test-send unsubscribe page". Decision record: D116 (lead, 2026-11-20). Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, file rules, acceptance = the whole `ci.yml` check job). Source: the first adopter's full Gmail pass of 10 sequence step tests on v1.4.0 (all render correctly).

## Finding

In a marketing step's test send (and its preview), `unsubscribe_url` is `<root>/m/00000000-0000-0000-0000-000000000000/unsubscribe/<subscriber uuid>` (the nil UUID placeholder of D105; `src/sequences/step-preview.ts:57`). Opening it answers 404, so a person checking a test mail who clicks Unsubscribe to see the flow hits a dead page. `manage_url` (`…?manage=true`) does the same.

## D116 (implement exactly this)

- `GET /m/00000000-0000-0000-0000-000000000000/unsubscribe/:subUUID` (any `:subUUID`, with or without `?manage=true`) answers **200** with the public page layout (same styling as the real unsubscribe page, `src/unsubscribe/routes.tsx`) and a short message: "This link is from a test send. Unsubscribing from a test does nothing; in a real message this link opens the unsubscribe page." Use the i18n mechanism the public pages use (English string; key added to the embedded translations like the other public strings).
- It reads and writes nothing: no subscriber lookup (so it reveals nothing about whether `:subUUID` exists), no tracking, no webhook. `POST` and the one-click `List-Unsubscribe-Post` path to the nil send UUID answer the same page / a 200 no-op respectively, again writing nothing, so a mail client's one-click unsubscribe on a test does not error or unsubscribe anyone.
- The nil UUID is never a real send UUID (sends use random v4 UUIDs), so real links are unchanged; every other `/m/:sendUUID/…` path behaves exactly as before (listmonk contract).
- Campaign test sends: check whether they use the same placeholder; if so they get the same page; if they carry a real-looking UUID, leave them and say so in the PR.
- Considered: documenting the placeholder only (a dead link in a mail is the confusing part; the page costs one route); making a test unsubscribe real (a test must not change a subscriber, D105).

## Tests (first, through HTTP)

GET of the placeholder unsubscribe and manage URLs → 200 with the message, for an existing and a non-existing subscriber UUID (identical bodies); POST and one-click POST → 200, subscriber's lists unchanged, no webhook queued, no unsubscribe event; a real send UUID path unchanged (existing tests keep passing); a step test send's `unsubscribe_url` in the sink mail opens the page.
