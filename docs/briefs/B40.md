# B40: Remove inert settings controls from the admin UI (D89)

Common rules: [_state-common.md](_state-common.md). Branch `task/B40-settings-ui`. Lines from main at f402f7a.

## Source

B36 audit ([12-completeness-audit.md](../design/12-completeness-audit.md), #88) and D89: one way per job, and no control that suggests a feature which does not exist. B35 removed the inert bounce-provider controls the same way (#87). These settings are stored and round-tripped for listmonk API compatibility (D57) but nothing reads them, and the admin page still shows them, mostly inside "Not available in this version" cards (`Unavailable`, `src/admin/views/settings.tsx:102`):

- the Media S3 card, `upload.provider` and `upload.s3.*` (`settings.tsx:569-619`);
- the Messengers tab (`settings.tsx:990-1005`, tab entry at `:1078`);
- the `app.check_updates` switch (`settings.tsx:219`);
- the SMTP `max_msg_retries` / `msg_retry_delay` inputs (`settings.tsx:839-849`). These sit in the live SMTP editor, so an operator can edit values that do nothing.
- `app.lang` (`settings.tsx:217`): translations are deferred (D89). Verify whether anything reads `app.lang` (grep `src/`). If nothing reads it, remove the control too; if something does, leave it and say what reads it.

## What to do

1. Verify each key is unread by runtime code (grep `src/`, excluding settings defaults, validation, OpenAPI and the admin view). If one is read, keep its control and report it in the PR.
2. Remove those controls from `src/admin/views/settings.tsx` and `assets/admin/js/views/settings.js`. If the `Unavailable` component and the Messengers tab end up unused, delete them. Remove i18n keys in `i18n/en.json` that nothing uses any more, including the search `keywords` attributes that mention the removed fields.
3. **Values must still round-trip.** Saving the settings page must not drop or reset these keys. Check how B35 kept the hidden bounce keys (`test/e2e/specs/settings.e2e.js` around :522, and the full-object save in `assets/admin/js/views/settings.js`). Apply the same approach.
4. Docs: list these keys as "accepted and stored for listmonk API compatibility; no effect; no admin control (D89)" in `docs/design/07-api-and-ui.md` and `src/openapi/differences.ts`, next to the B35 bounce keys, and remove any doc text that describes them as configurable in the UI.
