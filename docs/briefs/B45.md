# B45: Backup polish (review backlog from #85)

Common rules: [_state-common.md](_state-common.md). Branch `task/B45-backup-polish`. Lines from main at the commit that queued this brief.

## Source

B33 (#85, round 3) made `backup --output` create missing parent folders (`src/backup/snapshot.ts:316`, `mkdirSync(dirname(wanted), { recursive: true, mode: 0o700 })`), which fixed fresh installs. The review left three items (`gh pr view 85 --comments`, round 3):

1. **Empty folders left behind on refusal.** The parents are created before the checks that can refuse:
   - `checkDestination` (:319);
   - "no schema yet" (:327);
   - output inside the upload directory (:330);
   - not enough free space (:336).

   A refused backup therefore leaves the folders it created. Fix: create the missing parents only after the checks that do not need them. If a check needs the real parent path, find the nearest existing ancestor with `realpath` for the boundary checks. Alternatively, record which folders this call created (deepest first) and remove exactly those, only if still empty, on any refusal or failure before publication. Never remove a folder that existed before the call.
2. **Raw `ENOENT` / `ENOTDIR: mkdir` messages.** When a parent path goes through a broken symlink, or a path component is a regular file, the operator sees a raw Node error. Fix: catch these around the parent creation and throw a clear message naming the offending path component and what it is: "is a file, not a folder", or "is a symlink to a missing target".
3. **Docs: repeated `docker cp` nests folders.** `docker cp container:/data/backups/latest ./backup` copies into `./backup/latest` when `./backup` already exists. In `docs/operations.md` (Docker / backups), say to copy into a fresh path or use `docker cp container:/data/backups/latest/. ./backup`, and check which form is right with the Docker docs. Do not run Docker for this.

5. A successful backup into new nested folders still works, and the folders are created with mode 0700.
