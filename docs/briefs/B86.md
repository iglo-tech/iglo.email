2. **External-ID lookup: 404 when absent (D101, deliberate native contract).** `GET/PUT/DELETE /api/subscribers/external/:external_id` and `…/external?external_id=…` answer a missing subscriber with `400 {"message":"Subsubscriber not found"}`, the status a malformed selector also gets, so clients must match message text. These routes are native (D38/D39, no listmonk counterpart), so the D39 "generic missing-target 400" serves no compatible client. Change: a well-formed selector that matches no subscriber (or one outside the caller's list scope where the code today reports not-found) → `404 {"message":"Subscriber not found."}` using the i18n not-found message; a malformed/missing/duplicate selector stays 400. Also find and fix why the message reads "Subsubscriber" (the `{globals.terms.subscriber}` substitution in `src/subscribers/routes.ts` `required`), for the external routes. Numeric `/api/subscribers/:id` stays listmonk's 400 (D57). Do not change scope/permission outcomes otherwise (a 403 stays 403). Update D39's text with a pointer to D101, 07-api-and-ui.md (endpoint rows and deliberate differences if applicable), OpenAPI responses, existing tests that assert 400 for a missing external ID, and contract marks if any contract case covers it.

3. **Test enrollment from an existing event (D101).** `POST /api/enrollments` accepts optional `trigger_event_id` (manual and test enrollments). The event must belong to that subscriber and its `name` must equal the sequence's `trigger.event`, else 400 `Invalid fields: trigger_event_id` with no write. The enrollment records it as its trigger, so `since: "trigger"` conditions and aggregates measure from that event's `occurred_at` and the template's `trigger` data is that event. Waits still start from now (a test keeps its 1-minute cap); `reentry`, `force` and test rules are unchanged. This lets a sequence such as "no download since the purchase" be tested against events recorded before the test. Document it in 05-sequences.md (Test mode and the manual enroll sentence) and the OpenAPI schema. Do not add a "run the step now" endpoint (one way per job; reschedule plus the test cap covers it).

## Tests

- External routes: absent → 404 for GET/PUT/DELETE on both forms; malformed/empty/duplicate selector → 400; existing scoped-token cases unchanged; PUT/DELETE of an absent ID write nothing.
- `trigger_event_id`: wrong subscriber, wrong event name, unknown ID → 400 no write; a test enrollment with an event recorded before it, a `not event download_finished since trigger` condition: false when a download happened after that event, true otherwise (scheduler with the injected clock, mail in Mailpit); the template's `trigger` data is the event.
