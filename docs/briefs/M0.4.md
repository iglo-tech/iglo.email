## Connection and transaction behavior

- Production opens exactly the file iglo-email.db beneath bootstrap dataDir, creating the directory as needed. Use bun:sqlite only, explicit dependencies and per-instance ownership.
- File-backed connections use WAL, foreign_keys=ON, synchronous=FULL and busy_timeout=5000 ms (D19). Check the applied settings, rather than relying on silent PRAGMA typos. Preserve 64-bit integer values without JavaScript rounding.
- No runtime dependency, ORM, global connection, automatic transaction replay or global prepared-statement registry.
- The write helper starts BEGIN IMMEDIATE, commits a synchronous successful callback and rolls back on failure, preserving the original error and connection usability. Reject nested use clearly, rather than silently changing transaction semantics.
- Synchronous types must disallow async callbacks; runtime misuse with async callbacks/thenable results must fail clearly and roll back any active transaction. No await, SMTP/webhook/network work, or automatic callback retry inside a write transaction.
- All statement/db handles have explicit owners and disposal. Startup/listen failures close a connection already opened. Quiet successful startup and existing signals/CLI remain intact. No public backup command until M6.2.

## Migrations and backups

- The runner accepts an explicit ordered manifest of numbered SQL sources embedded into the executable; it must not discover files from the working directory at runtime. Migration SQL contains schema/body statements, not its own transaction/version control.
- Validate unique contiguous positive versions, nonempty sources and the database's version before migration. Reject malformed catalogs or a database ahead of the executable; never downgrade or silently skip a version.
- Apply each pending file inside its own short transaction and update PRAGMA user_version in that same transaction. A failure leaves that file's changes rolled back and retains the previous successfully committed version. Earlier successful files in the batch remain committed, as the design specifies one transaction per file.
- A non-empty database means user_version > 0 or existing non-internal user schema objects. Before the first pending migration in a startup batch on such a database, create a consistent snapshot under dataDir/backups using SQLite-aware backup/snapshot behavior that includes committed WAL contents. Never copy only a live .db file with an ordinary filesystem copy.
- One pre-batch snapshot suffices. Nothing pending means no new backup. Fresh empty installation needs none. Backup failure aborts before any migration; no overwriting an earlier backup or deleting the source. Make incomplete output distinguishable from a completed usable snapshot and remove only output owned by that failed attempt.
- Inject the clock for backup timestamps; avoid collisions even if the clock does not advance. A snapshot must reopen and contain the prior data/version. Use a primitive available in Bun 1.4.4 and document its limits; do not add an external SQLite CLI, shell backup dependency or a second database server.
- Production stays at user_version 0 with no domain tables until M1.1. Demonstrate real migrations with compiled synthetic fixture assets; do not create an artificial production schema to make the test pass.

## Loop helper

- Receive the real M0.3 Clock contract and explicit database/logger/owning-store callbacks. No process-global state, real-time domain sleeps, table-name interpolation, service locator or new durable queue table.
- The owning store's synchronous claim callback selects due/eligible rows and updates their lease atomically inside the helper's BEGIN IMMEDIATE boundary. It receives one injected now and lease-until value for the claim. Domain SQL, eligibility, status transitions and expiry/recovery policy stay in that store.
- Process claimed work outside the transaction. Keep work bounded and serial by default, with explicit validated interval/lease/batch options. No speculative concurrency pool, scheduler engine or generic retry/backoff layer.
- A lease expiry grants no permission to resend a marketing email. The helper must not reset status, release/requeue work automatically, replay a failed callback or decide how stale sends recover. Later sending modules enforce D12, unknown-state handling and fencing/conditional finalization.
- Graceful stop cancels an idle clock wait immediately, stops new claims and does not start unstarted items after stop. Work already started can settle; its owner supplies bounded I/O/timeouts. Stop/completion must be awaitable and idempotent without unhandled rejections. Handle an already-stopped signal and failures clearly; report unexpected errors through the injected logger and expose failure to the caller.
- No background loop starts in the production server before an owning feature/table exists.
