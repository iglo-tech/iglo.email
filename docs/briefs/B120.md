# B120: generated text/plain alternative without hidden content

Branch `task/B120-plain-alternative`. PR title "B120: generated plain-text alternative". Decision record: D118 (lead, 2026-11-20), appended at the end of `09-decisions.md`. Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, file rules, task-PR acceptance). Source: the first adopter's 1.4.0 end-to-end matrix (23 events, 0 failures, this one finding).

## Finding (lead-verified in code)

A sequence mail whose HTML starts with a hidden preheader (`<div style="display:none;max-height:0;overflow:hidden;opacity:0;">Buy a pack only when you need an export.&#847;&zwnj;&nbsp;…×90</div>`) showed, in Mailpit's text view, the preheader plus ~270 invisible padding characters on the first line. iglo.email does not send a text part for it: `src/messaging/email.ts:316-318` adds `text` only when an explicit alt body exists; the sequence path never sets one, tx only when the request has one, campaigns only from their stored `altbody`. The message is HTML-only, and Mailpit (like any client that derives text from HTML) rendered the hidden content. HTML-only mail is also a mild spam signal (for example SpamAssassin `MIME_HTML_ONLY`), and a text-only reader gets the client's own conversion.

## D118 (implement exactly this)

- Every outgoing HTML message without an explicit alt body (sequence steps, tx without `altbody`, campaigns without stored `altbody`, test sends of each, opt-in and other system mail if HTML) is sent as `multipart/alternative` with a generated `text/plain` part. An explicit alt body (tx request, campaign `altbody`) is used unchanged, as today.
- The converter, one function used by every path, built on Bun's native `HTMLRewriter` (no new dependency):
  - drops elements hidden by inline style: `display:none` (any spacing/case), also `visibility:hidden`, `max-height:0` with `overflow:hidden`, `mso-hide:all`; and `<head>`, `<style>`, `<script>`, `<title>`, comments;
  - removes preheader padding runs: sequences of U+034F, U+200B–U+200D, U+FEFF, U+00A0, U+2007, U+00AD (and their entities) that carry no visible text; a run of these is dropped, a single NBSP inside words becomes a space;
  - renders links as `text (URL)` (URL only once when text equals the URL), keeps tracked-link URLs as rendered, block elements (`p`, `div`, `br`, `li`, headings, `tr`, `hr`) as line breaks, list items with `- `, collapses whitespace, wraps nothing (no hard wrap), trims the result;
  - bounded: output ≤ input length, charged to the existing message budget; linear time.
- Unchanged: HTML part, headers, tracking, Message-ID, at-most-once, and message size limits (the text part counts toward the outbox payload bound; check `src/messaging/payload.ts`).
- Deliberate difference from listmonk for campaign and tx mail without alt body (listmonk sends HTML only): list it in `07-api-and-ui.md` with the reason (deliverability and text-only readers; the explicit alt body still wins) and mark it in the contract suite as the rules require.
- Considered (record): no text part (status quo; the finding); a third-party html-to-text library (new dependency, not needed with HTMLRewriter); hard-wrapping at 78 (format=flowed complications, clients wrap).

## Tests (first, through HTTP + SMTP sink)

The adopter's exact preheader shape in a sequence step mail: the received mail is `multipart/alternative`, the text part's first line is the visible body text, it contains none of U+034F/ZWNJ/NBSP padding and not the preheader sentence; a tx send without altbody and a campaign send without altbody get the same treatment; tx with `altbody` and a campaign with `altbody` keep exactly their given text; a link renders as `text (URL)`; a hidden `<span style="DISPLAY: NONE">` inside a paragraph is dropped; a large realistic newsletter converts within the budget and in bounded time (add to the perf note). The B106 Markdown pins are unaffected (HTML part unchanged).
