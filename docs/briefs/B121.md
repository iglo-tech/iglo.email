## 1. `/m/` pages ignore branding (major; blocks the adopter's go-live)

`src/unsubscribe/routes.tsx` (around lines 80 and 95) renders its pages with `siteName` only and never passes `site: deps.settings()`, so `PublicShell` takes its no-site branch: the iglo.email logo, the default favicon, and no `/public/custom.css`. Affected: every customer-facing `/m/:send/unsubscribe/:sub` page, its `?manage=true` view, the B112 "Test send" page, and every error/message page those routes render. The `/subscription/*` routes in `src/public/routes.tsx` brand correctly (they pass `site: settings`, line ~68).

Fix: the `/m/` routes (and every other public route; audit `src/public/*`, `src/unsubscribe/*`, the archive, opt-in, link/view routes that render HTML, and any error page) render through the same branded shell with the current site settings: `app.logo_url`, `app.favicon_url`, `appearance.public.custom_css`, site name. One code path for "public page with site settings"; no route may render the unbranded shell when settings exist.

Tests (first, through HTTP rendered pages): with `app.logo_url`, `app.favicon_url` and `appearance.public.custom_css` set, GET of a real `/m/:send/unsubscribe/:sub` page, its `?manage=true` view, the placeholder "Test send" page, an invalid-UUID error page from the same routes, and a POST result page each contain the custom logo URL, the custom favicon and the `/public/custom.css` link, and not the default logo. Without those settings, today's default output is unchanged (existing tests). Verify one branded `/m/` page with `agent-browser`.

## 2. Empty public subscription form answers 500

With `app.enable_public_subscription_page` true and no public lists, `GET /subscription/form` answers 500 "No lists available to subscribe". Read upstream at 6fcd95f (`cmd/public.go`, from GitHub) for what listmonk answers. An empty state is not a server error: answer **200** with the branded message page (same text). If upstream answers 500, list it as a deliberate difference in `07-api-and-ui.md` with the reason (an empty list set is a configuration state, not a fault; 5xx triggers monitoring alerts) and record D119; mark it in the contract suite as the rules require. Test through HTTP.
