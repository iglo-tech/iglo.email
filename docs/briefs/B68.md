## Tests (new `test/e2e/specs/public.e2e.js`, about 10 tests)

Take every tracking and web-view URL from a received mail (sink), never built from API UUIDs, except where a test deliberately alters one.

1. The archive index lists archived campaigns and not unarchived ones.
2. The archive detail page renders the body with the archive template, and Liquid subscriber fields use the archive meta, not a real person.
3. `/archive/latest` and `/archive.xml` show the newest archived campaign; the XML parses and links to it.
4. With the public archive turned off, `/archive`, `/archive/<slug>` and `/archive.xml` answer not-found; restore in `afterEach`.
5. A hostile campaign name or subject renders as text on the archive pages (no element injected, no script run; reuse `test/e2e/hostile-html.js` if it fits).
6. The web-view link in a received mail opens the message for that subscriber and records a view (stats through the API move by one).
7. The open pixel from a received mail answers a PNG (content type and signature bytes) and records a view; with `privacy.disable_tracking` on, it still answers a PNG and records nothing.
8. With `privacy.individual_tracking` off, a view or click is counted but not tied to the subscriber (check the subscriber-level data the API exposes); with it on, it is.
9. A tracked link from a received mail redirects to the original URL and records a click; an unknown link UUID answers not-found and records nothing.
10. The `/m/…` message page from a received mail shows the message text.

Restore every setting the spec changes in `afterEach`. If a test reveals a real product bug, do not fix product code: mark it `test.fail()` naming the bug and report it prominently in the PR.
