## What to do

1. **arm64 executable.** Build `iglo.email-linux-arm64` with Bun's `bun-linux-arm64` target beside `iglo.email-linux-x64`. Both go in `SHA256SUMS`, the draft release and the package step. Check the installed Bun and its docs for the exact target names (`bun build --help`, https://bun.sh/docs/bundler/executables); do not recall them.
2. **Native arm64 verification in CI.** `release.yml` gets a matrix (or second job) on `ubuntu-24.04-arm` that runs the same `bun run check`, `release:verify` and the owned production contract on arm64, and builds that arch's executable natively. `ci.yml` stays `workflow_dispatch` only; give it the same arm64 job. CI is not a merge gate: the lead dispatches one dry-run release (`workflow_dispatch`) on your branch after you push and records the result. You do not wait or watch it.
3. **Docker image.** A `Dockerfile` that takes the already-built executable for `TARGETARCH` (amd64 → linux-x64, arm64 → linux-arm64) and copies it into a small glibc base pinned by digest (for example `gcr.io/distroless/cc-debian12` or `debian:12-slim`; check that the compiled Bun executable runs on it). Non-root user, data directory as a `VOLUME` (match the data-directory flag/env the executable already uses; read `docs/operations.md`), `EXPOSE` the default port, `ENTRYPOINT` the executable. A `HEALTHCHECK` only if it needs no shell or extra tool (else document `GET /health` for the orchestrator). OCI labels (source, version, license AGPL-3.0).
4. **Publish.** On a `v*` tag the publish job builds one multi-arch image (`linux/amd64,linux/arm64`) from the two verified executables with Buildx and pushes `ghcr.io/iglo-tech/iglo.email:<version>` (and `:latest` only for a tag without `-`). `packages: write` only on that job; actions pinned by full SHA like the existing ones. A manual run builds the image without pushing.
5. **Docs.** `docs/operations.md`: install from the release (both arches), run with Docker (`docker run` with the volume, port and first-account env), upgrade, backup from a container. Remove macOS mentions anywhere in `docs/`.

## Host limits

Read `/home/t3-code/AGENTS.md`. This host has no arm64 emulation; verify arm64 only by cross-compiling and checking the file type (`file`), and leave runtime proof to the lead's CI dispatch. You may run at most one local `docker build` of the amd64 image and one `docker run` to hit `/health`, then remove that container and image. Never run `docker system df`, any prune, or a multi-arch/emulated build locally.
