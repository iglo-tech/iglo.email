## Implement D26 and its actual tests

- Bootstrap only when no users exist. A complete env pair initializes an enabled human admin and the primordial role atomically, with password hashing outside the database transaction and a transactional recheck. Initial reserved email is initial-admin@localhost.invalid. Missing both inputs keeps public health available but leaves login denied/unprovisioned; a partial pair fails clearly. Existing users ignore/bootstrap inputs and are never reset. Preserve D25: automatic IDs, no old/lower explicit IDs. Handle unexpected prior bootstrap state safely, not by clearing tables or silently granting an unrelated role.
- Receive database, clock, logger/root URL and an explicit auth policy. Use the seven-day session default until M1.2 supplies persisted settings; do not query another owner's settings table. No hidden runtime registry, environment-reading store or placeholder settings module. Module instances own caches/maps and lifecycle.
- Explicit nonempty Authorization wins over a cookie; invalid explicit credentials never fall back. Confirm the pinned cookie-precedence behavior and D26's deliberate correction with real reference/normal cases. Keep the Basic/token header error bodies/order actually observed elsewhere.
- Password input remains exact on creation/login/change, including surrounding spaces. Confirm the accepted-created-password/upstream-trimmed-login inconsistency before porting its D26 normal expectation. Username normalization follows the source. Unknown/disabled/non-password-login identities must not disclose account existence through an avoidable cheap verification path; use comparable verification work with bounded memory and never put asynchronous hashing in a transaction.
- SQLite-backed sessions use opaque high-entropy IDs, an expiry governed by injected time, fresh session identity on login, and the D26 cookie attributes. Validate live user status/identity on access and preserve sessions across process restart within TTL. Test expiry, logout, password changes, disable/re-enable and delete/recreate so a retained identity never becomes another account. Self-profile password changes keep the current session and revoke other sessions; admin password changes revoke all target sessions. Deletion/disabling/authentication identity changes revoke relevant sessions. TOTP-marked users fail closed until M1.4; no password-only bypass.
- Enforce pre-login nonce and session-bound CSRF on all unsafe cookie-authenticated API/forms, including logout. Existing login field is nonce; document X-CSRF-Token and the readable, session-bound CSRF-cookie path for API forms. Reject a foreign supplied Origin on unsafe requests; preserve header-authenticated non-browser clients without cookie CSRF requirements. Guard every route consistently; do not attach CSRF to Basic/token-only requests or trust a request to label itself as a fixture. Test wrong/missing/other-session tokens and Origin as observable denials without unintended writes.
- Login POST default: 20 attempts per transport peer IP per minute; at most 4,096 unexpired peer records, bounded opportunistic expiry and conservative refusal when full. Use the actual Bun peer address passed explicitly at the request boundary; ignore spoofable forwarded/client-IP headers. Tests advance the injected clock and use labelled fixture peer controls, not sleeps. Rate-limit before costly hashing. No pruning goroutine, real-time sleep or unrelated background loop from upstream is needed.
- Every new route enforces authentication and the existing users:get/users:manage or current-profile rule; primordial super-admin semantics stay compatible. Minimal owner role lookup/permission functions are real and reused by M1.4, not an always-allow stub. Lower-permission and wrong-type users cannot manage accounts or turn a profile update into role/type/permission escalation. Full role/list-permission API tests remain M1.4.
- Authenticated header-only logout returns the normal success shape without pretending to revoke the API token, instead of upstream's missing-cookie-session failure. Verify the reference outcome and mark D26. Unauthenticated logout remains forbidden. Cookies and API tokens must not accidentally become interchangeable authorities.
- Sanitize next redirects against the pinned helper's behavior and prevent cross-origin or header/control injection. Keep body/field work bounded, values escaped and failures safe. Do not leak passwords, token digests, session IDs or raw Authorization in errors/logs. Preserve existing error attention-only logging and public health/assets/fallback behavior.

If another upstream behavior is demonstrably poor or conflicts with the design, capture the actual reference failure and propose the smallest concrete change in the PR. Do not silently copy a known security failure, invent a broad exception or ask the owner. The lead decides further API-policy changes; all accepted differences require precise contract markers.
