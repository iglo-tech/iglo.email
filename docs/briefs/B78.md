## Design (D98)

1. **Generated from the API document.** `src/openapi/operations.ts` (`export const operations`, line 1477) documents every route, with path, query, body schema and permissions. Generate one MCP tool per allowed operation from that table, so a new endpoint documented there becomes a tool and can never drift. No hand-written list of ~100 tools.
   - Tool name: the operation `id` in snake_case (`getSubscribers` → `get_subscribers`). Description: `summary` plus `description`, plus "Needs: <permissions>".
   - `inputSchema`: path parameters and query parameters as top-level properties (path ones required), and the JSON request body under `body` (required when the operation requires one). Inline every `$ref` from `src/openapi/schemas.ts` (`schemas`), so the schema is self-contained; guard against cycles.
   - Execution: as today, in-process through `router.handle(app, request, peerAddress)` with the caller's authorization header and peer address (see `executeTool`, `src/mcp/tools.ts:577`). So the caller's role and list roles decide what an agent may do; refusals come back as `isError: true` with the API's message. `src/mcp` still owns no SQL.
   - Multipart operations (`POST /api/media`, `POST /api/import/subscribers`): take `filename` and `content_base64` (plus the operation's other form fields) and build the multipart body. Bound the decoded size by the endpoint's own limit; the MCP body limit is 2 MiB today (`src/mcp/routes.ts:9`), so raise it for `tools/call` only as far as the largest such endpoint accepts, or document the limit. Pick one and say which in D98.
   - Non-JSON answers (CSV exports, HTML previews): return the text as the tool's text content.
2. **Hand-written tools stay.** The 20 existing tools keep their names and read-modify-write behaviour (agents already use them). A generated tool is not emitted when a hand-written tool fully covers the same operation (e.g. `GET /api/templates` is `list_templates`; no `get_templates`). `update_sequence_step` covers only one step, so the full `PUT /api/sequences/{id}` is still generated (`update_sequence`) along with `POST /api/sequences` (`create_sequence`), triggers, status, enrollments etc. State the coverage map in one place in code.
3. **Excluded: borderline dangerous or not an agent action.** Not exposed even to an admin credential:
   - Privilege: `POST/PUT/DELETE /api/users*`, `POST/PUT/DELETE /api/roles*`, `PUT /api/profile`, every `session` operation (2FA), `POST /api/logout`. Reads of users and roles stay. An agent must not grant itself or anyone access.
   - Bulk and irreversible: `DELETE /api/subscribers`, `DELETE /api/subscribers/external`, `POST /api/subscribers/query/delete`, `PUT /api/subscribers/query/blocklist`, `PUT /api/subscribers/query/lists`, `DELETE /api/campaigns`, `DELETE /api/lists`, `DELETE /api/bounces`, every `DELETE /api/maintenance/*`.
   - Whole-settings replace `PUT /api/settings`: settings change one key at a time through `PUT /api/settings/{key}` (one way per job). `GET /api/settings` and `POST /api/settings/smtp/test` stay.
   - Not agent actions: `anonymous` operations, `/api/mcp`, `/api/health`, `/api/openapi.json`, `POST /webhooks/bounce`.
   - Keep the exclusion list as one explicit list of operation ids with a one-line reason each. A test asserts that every operation in `operations` is either a tool (generated or hand-written) or on that list, so a new endpoint is a deliberate choice.
   - Everything else is exposed, including single-item deletes, sending (`PUT /api/campaigns/{id}/status`, `POST /api/tx`, `POST /api/sends/{id}/resend`, enrollments, events), settings by key, webhooks, import, exports.
4. **Tool annotations** (MCP `annotations`, so clients can ask the user before risky calls): `readOnlyHint: true` for GET and for preview/text/validate POSTs; `destructiveHint: true` for every DELETE, blocklist, campaign status change, `PUT /api/settings/{key}`, and subscriber activity deletion; `openWorldHint: true` for operations that send email or call outside (campaign status, test sends, tx, resend, enrollments, events, SMTP test). Hand-written tools get annotations too.
