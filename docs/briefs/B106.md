# B106: replace marked with a linear-time CommonMark parser

Branch `task/B106-markdown-parser`. PR title "B106: linear-time CommonMark parser for Markdown". Decision record: D113 (lead, 2026-11-19; recorded on main, complete it with the evidence). Read `docs/briefs/_B97-common.md` first. Source: B105 round-3 review and lead decision on PR #157.

## Why

marked is a regex lexer; B104 and three B105 rounds each found new super-linear shapes (link titles, block rescans, reflink search, `~` runs, hard-break lookahead `(?!\s*$)`, failed-attempt rescans), and charging each regex either missed a shape or refused ordinary documents. Remaining on main: a paragraph followed by whitespace-only lines takes 0.65 s at 64 KiB literal and 2.44 s at the 128 KiB cap; some ordinary 7-20 KiB line lists ending in `!`, `[...]`, `~`, a lone backtick are refused.

## Task

1. **Choose the parser with evidence.** Requirements: CommonMark-compliant (listmonk uses goldmark), running time linear in input by design with an upstream pathological-input/ReDoS test suite, maintained, AGPL-compatible licence, usable from Bun without a build step, bounded memory, renders to HTML string. Evaluate at least micromark (with its GFM table/strikethrough/autolink extensions if our current Markdown supports those; check what marked options we enable today) and one alternative. Record the comparison in D113: licence, size, CommonMark spec pass rate, timing on the B104/B105 pathological families and the reviewer shapes at 128 KiB.
2. **Replace marked** in `src/templates/markdown.ts` and `src/campaigns/content.ts` (convert path; check what the convert path needs, e.g. HTML to Markdown is a different library, keep it if separate). Remove `patches/marked@15.0.12.patch` and the marked dependency if nothing else uses it. Keep the 128 KiB cap, the 1 MiB output limit, and a true `reserve()` bound (output ≤ reserved, tested on a random corpus); drop the per-regex work charges if the parser is linear, or keep one simple linear charge per input byte.
3. **Output.** Compare against today for the 33 B104 pins, the B105 newsletter pins and a random corpus; every difference must be either CommonMark-correct (matches goldmark with listmonk's options; run goldmark v1.8.6 as B104 r2 did) or listed as a deliberate difference with its reason in 07-api-and-ui.md and `src/openapi/differences.ts`. Update the pins to the new output only with that evidence.
4. **Targets** (container, over HTTP): every B104/B105 family, the marker matrix, the 37 Liquid shapes and the B105 r3 reviewer's shapes at 128 KiB render or refuse within 100 ms; five concurrent such previews delay a GET sent before them by at most 1 s; every ordinary document from the B105 tests and the r3 reviewer's line lists (7-20 KiB) renders.
5. Remove the unreachable over-cap branch at `src/templates/routes.ts:177` (tx/sequence never render Markdown). Convert path shows the cap message instead of "invalid markdown"; archive preview shows the cap message instead of its generic failure page (B105 r3 backlog).
