# B80: `order` in any case; MCP `is_default`; B79 nits

## Changes

1. **`order` in any case (deliberate difference, D57).** The API document lists `order` as `["ASC", "DESC", "asc", "desc"]` (`src/openapi/operations.ts:54`, upstream's own docs do the same), but the stores, like upstream's, compare lowercase only. So `ASC` sorts descending, for lists, templates and campaigns at least. A realistic client (an MCP agent or SDK that reads the enum) gets the wrong order with no error. Make every endpoint that takes `order` accept it in any case (`ASC`, `asc`, `Asc` sort ascending). Find each reader of `order` across the ported list endpoints (lists, templates, campaigns, subscribers, bounces, media, users, any other); do not assume the three above are all. Record it as a deliberate difference: a row or sentence in `docs/design/07-api-and-ui.md` (deliberate differences) and `src/openapi/differences.ts`, with the reason "upstream's documented `ASC` sorts descending". Mark it in the contract suite the way other deliberate differences are marked (read `test/reference/README.md`, and `test/contract/` for an existing marked difference); run `bun run contract:normal` and `bun run contract:fixture`. Do not run the Docker reference.
2. **MCP `is_default`** (`src/mcp/tools.ts:141`, `:163`, `:753`, `:764`): no endpoint reads `is_default` on template create or update, so the argument does nothing. When it is `true`, the tool calls `PUT /api/templates/{id}/default` after a successful save and reports both results. A failed default call after a successful save is a tool error that says the template was saved. Drop `false` from the schema description: it means "do not change the default", because a default is unset only by making another template the default. Test through `POST /api/mcp` and check that `get_template` shows `is_default`.
3. **B79 nits:**
   - The schema test in `test/mcp/handwritten-fields.test.ts` must assert that it found fields for each covered operation, so an `allOf` or nested `$ref` body cannot make it pass empty.
   - Fix the cap-test comment: the cap is reached in the first batch, not the second.
   - Build `create_campaign`'s field list once, not on every call.
   - Remove the `type` argument from `update_campaign`, because the endpoint keeps the stored type. Keep the coverage test passing: exclude that one field explicitly, with a reason.
   - `queryFor` must not turn an object or array argument into `[object Object]`. Send arrays as repeated parameters, as the API takes them, and refuse objects with a tool error.
