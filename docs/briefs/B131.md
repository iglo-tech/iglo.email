## Items and D129

1. **Address conflicts on event ingest:** an event for `external_id` X with address E returns 409 when E belongs to another subscriber; every adopter builds a search-then-PATCH/DELETE repair. D129: inside the event's transaction, (a) if the holder of E has no `external_id` (imported or form-subscribed), the event claims it: the holder gets `external_id` X (and the event's other identity fields), keeping its lists and history; (b) if the holder has a different `external_id`, answer 409 with a JSON body naming the conflict: `{"message": …, "code": "email_conflict", "conflict": {"external_id": "<holder's>"}}` (the caller already has `subscribers:manage`; it could find this by search). Same rule for the batch item and `PUT /api/subscribers/by-external-id` if it has the same 409. Documented with both cases. Scope check: a claim is refused if the caller lacks manage scope on the holder's lists (D99/D103 rules), answering the 409 without naming the holder.
2. **Stable error codes:** every API error JSON keeps `message` (listmonk's shape) and gains a stable machine-readable `code` (snake_case, from a fixed enumerated list in one module; e.g. `invalid_fields`, `not_found`, `permission_denied`, `email_conflict`, `rate_limited`, `held`, `payload_too_large`). Additive: no listmonk client breaks. OpenAPI documents the enum per response.
3. **Retry guidance:** every 429 and 503 sends `Retry-After` (seconds). `docs/operations.md` and the OpenAPI description list which statuses are permanent (400, 401, 403, 404, 409, 413, 422) and which are worth retrying with backoff (429, 503, 5xx, network errors), and that writes carrying an `idempotency_key` are safe to retry.

## Tests

Through HTTP: claim of an external-id-less holder (lists and history kept, one subscriber, `external_id` set); conflict with another external_id (409 body with `code` and `conflict.external_id`, nothing written); scoped caller without manage on the holder's lists gets 409 without the holder's id; every error path in a sample of routes carries a `code`; 429 and 503 carry `Retry-After`. Contract suites keep listmonk's `message` unchanged.
