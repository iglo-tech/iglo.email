# B17: Campaign runner state guards

Common rules: [_state-common.md](_state-common.md). Branch `task/B17-runner-guards`.

## Owns

`src/campaigns/runner/*` (including `store.sql`), `migrations/` only if needed, and the runner tests.

## Behavior

1. **First pickup must send.** `acquire-campaign` (`runner/store.sql:12`) returns `runner_generation`. `start-campaign` (`:27`) then flips scheduled → running, and the trigger in `migrations/0007_campaign_runner.sql:9` bumps the generation. The pipe keeps the old value (`runner.ts:259`), so the first `next()` releases (`runner.ts:278`). A scheduled campaign therefore sends nothing until the next scan, about 5 s later. The same happens on a resume while `send_at` is set.
   - Fix: `start-campaign` returns the new generation and the pipe uses it.
   - Test: a due scheduled campaign delivers its first batch on the first scan, with the clock advanced by less than one scan interval.
2. **A stale runner must not write.** These statements check neither the lease nor the status:
   - `add-sent` (`:54`)
   - `set-delivery` (`:62`)
   - `unclaim-delivery` (`:65`)
   - `advance-cursor` (`:47`)

   A runner whose lease has passed to another holder can unclaim subscribers who are already behind the cursor, and those subscribers are never sent.
   - Guard each statement by `runner_lease = token`. Also guard `set-delivery` and `unclaim-delivery` by `status = 'claimed'`.
   - When a guarded write matches nothing, the pipe drops without further writes.
3. **The runner's own pause must not stop a newer run.** `pause-campaign` (`:87`, called at `runner.ts:452` and `:629`) checks only `status = 'running'`. A user can pause and resume between the claim and that write, and the stale pipe then pauses the new run.
   - Guard the runner's pause by the lease and by `runner_generation`.
   - The HTTP pause in `src/campaigns/store.ts` stays as it is.

## Out of scope (upstream parity, decided)

- `finished` can be set from any state.
- `updateStatus` returns the requested status.
- A running campaign can be deleted.
- Resume recomputes the audience.

## Measurements

Campaign throughput before and after, or the one-paragraph argument for a guard-only change, in `docs/perf/`.
