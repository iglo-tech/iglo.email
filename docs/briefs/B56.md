# B56: Settings secret residuals

Common rules: [_state-common.md](_state-common.md). Branch `task/B56-secret-residuals`. Lines from main at the commit that queued this brief.

## Source

These are the B51 round-2 backlog items (#102: `gh pr view 102 --comments`). Verify each against `main` first.

1. **A server switched to auth `none` keeps its stored password.** If it is later switched back to login without the password being retyped, the old password goes to whatever host it now has, for example after a provider template was applied. **Lead decision:** in `src/settings/validate.ts`, when an SMTP item's (or bounce mailbox's) `auth_protocol` is `none`, do not preserve a stored password: drop it. A server with no authentication has no use for one, and a later switch back to login then needs a new password. Check the auth field name and values for each item type in `src/settings/defaults.ts`. This is a deliberate difference from upstream (which preserves): add it to the B51 row in `docs/design/07-api-and-ui.md` and `src/openapi/differences.ts`.
2. **Two items with the same uuid in one save share a secret.** Refuse a save in which two items of the same array (SMTP, bounce mailboxes, messengers) carry the same non-empty uuid, with 400 and a clear message. Check that the settings page can never send duplicates. For example, does "duplicate server" copy the uuid? If it does, clear the uuid on duplicate in `assets/admin/js/views/settings.js`.
3. **A disabled server cannot take a password until re-enabled.** On the settings page, the password input for a disabled SMTP item is disabled. Let the password be typed whatever the enabled state, unless auth is `none`.

## Tests (test-first, public boundaries)

1. Through `PUT /api/settings`: a saved SMTP item with a stored password, switched to `auth_protocol: "none"` with a blank password, has no password afterwards (masked GET). Switching it back to login with a blank password stores none. The same for a bounce mailbox, if it has an auth field.
2. A save with two SMTP items sharing one uuid returns 400 and changes nothing.
3. In the settings e2e (`test/e2e/specs/settings.e2e.js`): duplicating a server, if the page offers that, produces a distinct uuid on save. A disabled server's password can be typed and saved.
4. The normal masked save, where an existing authenticated item is saved with a blank password, still keeps the stored password. This must not regress.
