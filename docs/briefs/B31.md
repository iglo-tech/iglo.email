## What to do

1. **Measure by cause.** Under `bun run perf:mixed` (one run is enough per variant, record host load), attribute main-thread time during the event tail: the event writer's own transaction (split into insert vs sequence evaluation), JSON parse/validation of the request, other loops' synchronous work (campaign render, outbox finish, analytics child I/O), and GC pauses. Use a sampling or `performance.now()`-bracket probe enabled only by an env var in the perf harness, not in production paths, or Bun's `--cpu-prof` on the compiled server if that works.
2. **Decide (D88).**
   - If one cause dominates and has a cheap fix inside `src/events`/`src/sequences` (for example, sequence evaluation work that can move out of the accept transaction without changing durability, at-most-once or D22/D86), implement it with a before/after measurement and tests.
   - If the tail is spread across main-thread work with no cheap fix, record that a process-model change (moving loops to workers) is not justified at the current target, with the numbers, and close the line.
3. Update the backlog line (remove it or replace it with the D88 outcome).
