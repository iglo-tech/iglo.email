# B50: Fix the probe-then-bind port race in test fixtures

Common rules: [_state-common.md](_state-common.md). Branch `task/B50-port-race`. Lines from main at the commit that queued this brief.

## Source

The #100 review ran `bun run check` twice. Both runs failed on a port collision in a different backup test: `test/backup/backup.test.ts`, then `hold.test.ts`. Both files pass alone. The cause is in `test/backup/fixture.ts:58-62` (`startServer`): it opens a listener on port 0, reads the port, closes the listener, then starts the compiled server on that port. Under 4 parallel workers another test can take the port in between. AGENTS.md: "New tests must not use fixed ports". A probed-and-released port is a race of the same kind.

## What to do

1. Find every test helper that probes a free port and then hands it to a separate process or listener. Candidates from `grep -rln "port: 0" test`: `test/backup/fixture.ts`, `test/backup/hold.test.ts`, `test/server/fixture.ts`, `test/subscribers/fixture.ts`, `test/scheduler/fixture.ts`, `test/events/fixture.ts`, `test/e2e/run.ts`. Check how each uses the port. A listener that binds port 0 and keeps it is fine; only probe-close-reuse is the bug.
2. Fix it the race-free way. Look first at how other compiled-server helpers already do it (for example `withProduction` in `test/contract/`, or the bootstrap tests). Options:
   - **(a)** start the server with `--port 0` and read the port it actually bound, from its log output or a ready line, if the executable supports that (check `src/main.ts` serve and `test/bootstrap/cli.test.ts:441`);
   - **(b)** retry on `EADDRINUSE`: start, and if the server exits with an address-in-use error, probe a new port and start again, a bounded number of times.

   Prefer (a) if the executable already reports its bound port; do not add a product feature only for tests unless it is tiny and useful to operators, such as logging the bound address at startup. Otherwise use (b).
3. One shared helper is better than seven copies. Put it where the others can import it, without creating a barrel file (AGENTS.md).
