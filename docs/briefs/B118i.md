## B118i: the CLI binds port 0 and reports the port it bound

Branch `task/B118i-port-zero`. PR title "B118i: serve on port 0 and report the bound port". Decision D144 (lead, 2026-11-25): append it at the end of `09-decisions.md`.

Today the CLI refuses `--port 0` (`src/config/bootstrap.ts`, 1 to 65535). So `scripts/release.ts` (`availablePort()`) and `test/bootstrap/cli.test.ts` pick a free port, close it, and start the child on it, and a parallel test can take the port in between. B118a added a bounded fresh-port retry. That is the `release verify` watch item, and a retry never clears it.

1. **Product.**
   - `--port 0` (and `IGLO_EMAIL_PORT=0`) binds a port the OS chooses.
   - After the bind, the server writes one line to stdout naming the bound port. It is CLI output, so AGENTS.md's logging rule allows it, and it is printed only when the port was 0.
   - The default root URL uses the bound port. Choose how and record it in D144: derive the root URL after the bind, or require `--root-url` with port 0.
   - `--help` and `docs/operations.md` say so.
   - Keep the order from B52: wire, then bind, then start the loops.
2. **Release script.** `scripts/release.ts` starts the child with port 0 and reads the bound port from its line. `availablePort()`, the fresh-port retry and `RELEASE_VERIFY_FIRST_PORT` go. `test/release/release.test.ts` follows.
3. **CLI tests.** `test/bootstrap/cli.test.ts` starts its servers with port 0 and reads the port, and `startOnFreePort` and its retry go. Its `shutDown` (around `:248`) stops the child with a fixed 3,000 ms SIGKILL. Replace that with a stop that fails only when the child stops making progress (CPU time, as `test/serve-port.ts` does), or with a budget above the product's 5 s shutdown drain (D104), with the reason in a comment.
4. **`cli.test.ts:717`, one budget per CLI start.** "a half-set API pair, a malformed token or a clashing user name fails startup" runs seven CLI starts in a row inside one per-test budget (12 s). Under load they took 9.4–11.5 s, and one captured run failed with `CLI did not exit before its budget ended` (investigation on #211, 2026-11-25). Split it into one test per case (`test.each`), so each start has its own budget. A wider budget does not clear it.
5. **Other servers in tests.** `test/serve-port.ts`, `withProduction` and the e2e stacks use port 0 too if they pick and close a port today. List the ones changed and the ones left, with a reason for each one left.

## B118j: four test items

Branch `task/B118j-test-items`. PR title "B118j: test-send settle, stack stop, claimBatch timing, health bound". Test files and `docs/perf/` only; no product change. Containers start with `b118j-`.

1. **`test/messaging/test-send-trace.test.ts:327` and `:359`.** Each has `await Bun.sleep(50)` before `expect(f.sink.messages).toHaveLength(0)`.
