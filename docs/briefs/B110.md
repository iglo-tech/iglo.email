# B110: plain attention lines; Coolify network wording

Branch `task/B110-plain-attention`. PR title "B110: plain attention lines; proxy network docs". Read `docs/briefs/_B97-common.md` first (container recipes, file rules, acceptance = the whole `ci.yml` check job). Source: the first adopter's v1.3.1 recheck (all items passed).

## 1. Attention lines print as plain lines

On v1.3.1 the B108 test-bounce line (and, check, every other attention line: B98 untrusted forwarding, B101 failed test send, scheduler/sequence attention) reaches stderr as a logged `Error` object, so Bun prints about five lines of bundled source with a caret and the stack around it, and `GET /api/logs` shows the fixed text with " (Error)" appended. AGENTS.md: application code logs only errors and things that need attention; an attention line is a message, not an exception.

- Make every attention line one plain line on stderr (the message text exactly as today, no source excerpt, no stack) and its `/api/logs` entry the fixed text without the "(Error)" suffix. Real unexpected errors keep their stack on stderr and their current `/api/logs` form. Find the logger API that attention callers use (`attention(…)`, `app.logger.error(new Error(…))`, the log buffer's fixed messages) and give attention lines their own path rather than special-casing call sites.
- Tests through public boundaries: stderr of the compiled server (existing bootstrap/server harness) shows exactly one line for a triggered attention event (use the untrusted-forwarding warning and a test-send bounce via the SES fixture), with no `at ` stack lines and no source excerpt; `/api/logs` shows the fixed text without "(Error)"; an unexpected handler error still logs with its stack.

## 2. Proxy network wording

`docs/operations.md`, "Deploying behind a reverse proxy or PaaS": the CIDR advice names the `coolify` network. On Coolify a Compose service gets its own network (named by the service uuid) which the proxy joins; say "the network the proxy and the app share" and show how to find it: `docker inspect <app-container> --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'`, then the existing `docker network inspect` subnet command on that name.
