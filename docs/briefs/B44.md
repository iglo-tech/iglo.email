## Items

1. **Manage without get.** The read-merge tools (`update_campaign`, `send_campaign_test`, `preview_campaign`, `campaign_text`, `update_sequence_step`) first GET the stored object. A role with `campaigns:manage` but no `campaigns:get*` (or the sequences equivalent) fails at that GET, with the API's 403 for the read. Decide:
   - **(a)** keep it, and return a clear tool error naming the missing read permission (a read-merge tool needs both); or
   - **(b)** for tools whose full input is given, skip the read.

   Prefer (a), since it is simple and honest, unless (b) is trivial for one tool. Document the choice in D91. Add a test.
2. **`update_campaign` cannot clear `send_at`.** Allow an explicit `send_at: null` to clear the schedule, passed through to the PUT. Omitting `send_at` keeps the stored value. Test both cases.
3. **No-op `update_sequence_step`.** A call with neither `subject` nor `template_id` currently saves and bumps the timestamp. Refuse it with a tool error ("nothing to change") and no write. Test.
4. **Tests:**
   - a cookie-session MCP call with a foreign `Origin` is refused (403) and writes nothing;
   - `update_campaign` on a campaign whose list was deleted (one of two lists) still works and keeps the other list;
   - `update_sequence_step` on an active sequence with a live enrollment (a subscriber partway through) updates the step in place, without resetting or ending the enrollment, checked through the API.
