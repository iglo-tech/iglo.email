## Goal

Today's `main()` wiring in `src/main.ts` (about 1000 lines) becomes `createProject(…)` in a new `src/projects/compose.ts`, for one database. `main()` calls it once. There is no instance, no `instance.db`, no routing and no new behaviour. B138b builds the instance on top of this seam.

## Owns

`src/main.ts` and the new `src/projects/compose.ts`. Touch no other module. If a module's constructor has to change, stop and report it in the PR for the lead.

## Behaviour

- `createProject(services, options)` receives what `main()` passes in today: the clock, logger, configuration, data directory and process-wide budgets, as explicit arguments (no process-global state). It opens the database and wires every store, route and loop exactly as `main()` does now. It returns `{ router, start(), stop(), db, … }`, with what `main()` needs to bind, start and shut down.
- `main()` keeps CLI parsing, bootstrap, bind, signal handling and the order: wire, then bind, then `start()`, then on shutdown `stop()`.
- The start-up and shutdown order, log lines, exit codes and every timing stay the same.
