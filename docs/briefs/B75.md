# B75: wake the campaign runner on start and resume

Common rules: [_state-common.md](_state-common.md). Branch `task/B75-runner-wake`. Source: the lead's backlog line from the B64 review (status.md work queue). Lines are from main at 538e274; re-check them.

## Problem

`createCampaignRunner` returns `wake: () => loop.wake()` (`src/campaigns/runner/runner.ts:783`), but nothing calls it. A campaign set to `running` (from draft or paused) or `scheduled` with a `send_at` already due waits for the next idle scan, up to 5 s (`scanInterval`, `runner.ts:109`). The outbox, webhooks and sequence scheduler already wake on their own events (`src/messaging/outbox.ts:66`, `src/webhooks/delivery.ts:226`, `src/main.ts:684`).

Upstream listmonk 6fcd95f also waits for its scan (`internal/manager/manager.go:455`, `cmd/campaigns.go:553–578` only calls `StopCampaign` on pause/cancel). The HTTP response does not change, so this is not an API difference. The benefit is that a start or resume begins sending at once instead of up to 5 s later.

## Change

1. `src/campaigns/routes.ts`: add an optional `wakeRunner?: () => void` to `CampaignDeps` (line 63). In the `status` handler (around line 550), after `store.updateStatus` succeeds, call it when the new status is `running`, or `scheduled` with a `send_at` at or before the clock's now. Call it outside any transaction (it already is) and guard it like `notify` (a throw is logged, never turned into an error response).
2. `src/main.ts:484`: pass `wakeRunner: () => runner?.wake()` to `registerCampaignRoutes` (the runner is created later, at line 553, so read it lazily).
3. Look for any other path that sets a campaign to `running` or due `scheduled` through `campaigns/store.ts` (for example a create or update that schedules with a past `send_at`, the MCP tools that go through the HTTP routes, or a sequence path). Wake on those too, only if they exist; list in the PR what you checked.
4. `docs/design/02-architecture.md:29`: the runner row says "5 s scan"; add that a start, resume or due schedule wakes it.
5. Add **D97. The campaign runner wakes on start (lead, 2026-11-13)** to `docs/design/09-decisions.md`: one short paragraph (same as listmonk's result, sending just starts sooner; pause and cancel are unchanged and still take effect at the next batch or lease check).

Do not change the scan interval, the loop primitive, pause/cancel handling or anything else in the runner.
