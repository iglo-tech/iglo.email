# B18: Outbox lease and stuck sends

Common rules: [_state-common.md](_state-common.md). Branch `task/B18-outbox-lease`. Decision record: **D80**.

## Owns

`src/messaging/*` (`sends.ts`, `outbox.ts`, `anonymize.ts`), `src/tx/routes.ts` only where `dispatch` is called, and the tests.

## Behavior

1. **A `sends` lease is checked while the server runs (D80).** `claimed_until` is written, but nothing reads it. A row stuck in `sending` stays there until the next restart's `recover` (`sends.ts:856`). Meanwhile it holds the subscriber's marketing cap (`sends.ts:337`).
   - Each outbox pass moves `sending` rows with an expired `claimed_until` to `unknown`/`interrupted`. Use exactly the transition, guard and `ended` webhook of `recover`. Never move a row back to `queued`, because sends are at-most-once.
   - Startup `recover` stays.
   - The lease must outlast the longest possible SMTP push. Check the configured messenger timeouts against the lease lengths (dispatch uses 60 s, `outbox.ts:112`; also check the loop). Lengthen the lease, or renew it, so that a healthy push never expires.
2. **A rejected `dispatch` push must not leave rows in `sending`.** In `outbox.ts:114-117` the error is only logged, and the claimed rows stay in `sending`.
   - Rows claimed by a rejected push that are not finished become `unknown`/`uncertain`. This matches how the campaign runner treats a rejected push.
   - Make the loop path (`outbox.ts:78-91`) settle its rows the same way before it fails.
3. **One claim path.** `claimOne` (`sends.ts:238-241`) updates by `WHERE id=?` only, while `claimQueued` (`:759`) also checks status. Guard `claimOne` with `status='queued'`, or route it through the guarded statement.
4. **An anonymized row must not come back.** If a subscriber is deleted while their transactional send is in `sending`, `finish` re-queues it on a transient error (`sends.ts:291-296`) with a NULL payload. It is then reclaimed, fails as `payload_unavailable`, and fires a `send.failed` webhook for a deleted subscriber (see the comment at `anonymize.ts:7`).
   - Re-queue only when `payload IS NOT NULL`. Otherwise the row becomes `skipped`/`subscriber_unavailable`, with no webhook.
