## Items and D130

1. **Secret rotation:** `PUT` of a webhook ignores the secret today. Add `POST /api/webhooks/{id}/rotate-secret` (`webhooks:manage`): generates a new secret, returns it once, and for an overlap window (default 24 h, body field `overlap_hours` 0–168) signs each delivery with both secrets (the existing signature header carries both signatures in a documented form, e.g. comma-separated `v1=` values, as common webhook providers do); after the window only the new secret signs. Stored secrets stay encrypted/hashed as today; the old one is deleted at the window's end (retention loop, injected clock). MCP gets the tool through the OpenAPI document (D98).
2. **Reference receiver docs** (`docs/operations.md`, webhooks section): verify the HMAC over the exact raw body with a constant-time compare, accept any of the listed signatures (rotation), timestamp tolerance (state the header and a 5-minute default), a replay window keyed on the delivery id, a body size cap, and return 2xx only after a durable write (iglo.email retries otherwise). Include a ~30-line verification helper in TypeScript in the docs (no new package), tested: `test/webhooks/` imports the documented snippet from a fixture file kept in sync with the docs by a test that compares them.

## Tests

Rotation: deliveries during the window carry both signatures and verify with either secret; after the window (advance the injected clock) only the new; overlap 0 switches at once; a non-manager gets 403. The documented helper verifies a real delivery and rejects a tampered body, a stale timestamp and a replay.
