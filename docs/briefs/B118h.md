# B118h: one exit per event on the Events tab

Branch `task/B118h-exit-event`. PR title "B118h: an exit is shown on one event". Read [`_B97-common.md`](_B97-common.md) first. Found by the B118g review on PR #210 (comment 7127188362, point 4).

## Problem

`eventLinks` in `src/sequences/enrollments.ts` (about line 597) attaches an enrollment's event exit to every event that has the exit's name and the same `receivedAt`. One call to `POST /api/subscriber-events/batch` gives every item the same `receivedAt` (`src/events/routes.ts:133`). So two events with the same name in one batch both show the same exit on the subscriber's Events tab, as if each had ended the enrollment.

## Decision (lead, 2026-11-25)

The rule needs no migration (option B in the review). Of the events with the exit's name and time, the exit is shown on exactly one:
- the event with the lowest id;
- or, when the enrollment was started by an event at the same time, the lowest-id matching event after that one.

Any of these events would have ended the enrollment, so a fixed rule gives one stable answer. The choice is made across all of the subscriber's events, not only those on the current page. That way the same exit never shows on two pages, and an exit whose event is on another page is not shown here. Put the choice in a function of the module that owns the events table; `enrollments.ts` does not query that table itself (AGENTS.md).

Rejected: a migration that records `exit_event_id` at exit time. It is exact, but it adds a column and a write to the exit path, and an old row would still need the rule.

Write the rule in `docs/design/05-sequences.md`, in the section that describes the Events tab or the exit reasons.

## Tests (test first)

Through HTTP or the rendered admin page:
- two same-named events in one batch: the exit shows on one event only, the lowest id;
- an enrollment started by an event in the same batch: the exit shows on the next matching event;
- the matching event is on another page of the Events tab: the exit does not show on this page.

Show a mutant for each that fails.
