# B107: ready for Bun 1.4.5 (webhook `list_ids` root cause, release pin)

Branch `task/B107-bun-1.4.5`. PR title "B107: Bun 1.4.5 upgrade". Decision record: D115 (lead, 2026-11-20) if a product behaviour or format rule is decided. Read `docs/briefs/_B97-common.md` first (container recipes, file rules, acceptance = the whole `ci.yml` check job, image matches `packageManager`).

## Background

c3e681c bumped Bun to 1.4.5 directly on main (no PR, not Renovate) and was reverted by B107a (#158) for v1.3.0 because:

1. `scripts/release.ts:143` pins `runtime = { bun: "1.4.4", webkit: "<rev>" }` and `notices()` throws for any other Bun, so `release:package` fails.
2. On Bun 1.4.5, four webhook/bounce tests see `list_ids` serialized as the JSON string `"[1]"` instead of the array `[1]` (`a stored bounce delivery is cleared…`, `every listed event reaches the receiver…`, `a public wipe stores and delivers…`, `bulk actions queue the bytes…`). The shipped binary embeds Bun, so on 1.4.5 every webhook receiver would get a different payload format: a wire-format regression.

Renovate (`renovate.json`, `config:recommended`) owns dependency updates (AGENTS.md). This task makes the code correct on 1.4.5 and performs the upgrade in one PR, since the version bump and the fixes cannot pass separately.

## Task

1. **Root cause of `list_ids`** with evidence: find where the webhook payload builds `list_ids` (likely a SQLite `json(...)`/`json_group_array` column or a JSON-text column read through `bun:sqlite` and spliced into the payload), and which Bun 1.4.4 → 1.4.5 change alters it (bun:sqlite value typing, JSON subtype handling, `JSON.parse` of a column, SQLite version bundled with Bun). Reproduce on both images (`oven/bun:1.4.4`, `oven/bun:1.4.5`) with a minimal script and the failing tests. Read Bun's 1.4.5 release notes / changelog via the web if needed.
2. **Fix it so the wire format is identical on both Bun versions**: the payload must carry a JSON array, as the API document and listmonk's webhook contract specify. Make the conversion explicit (do not rely on runtime/driver typing). Audit every other place that splices JSON text from SQLite into a response or payload for the same dependency, and fix those too; list them in the PR.
3. **Release pin**: update `scripts/release.ts` `runtime` to Bun 1.4.5 with the correct WebKit revision for 1.4.5 (find it from Bun's source/release metadata; record the source in the PR), keeping the check that a mismatched Bun fails packaging.
4. **Bump** `package.json` `packageManager` to `bun@1.4.5` (and `engines` only if needed), `@types/bun` if Renovate would, and refresh `bun.lock` with `bun install` under 1.4.5. Update the container image references in `docs/briefs/_B97-common.md` recipes to `oven/bun:1.4.5`.
5. Tests: the four failing tests pass unchanged on 1.4.5 (they assert the documented format; do not loosen them); add one test that asserts `list_ids` is an array in a delivered webhook body for each event type that carries it, run on 1.4.5.

## Owns

The module that builds webhook payloads and any module the audit in item 2 finds (only the JSON-splicing code), `scripts/release.ts` (runtime pin), `package.json`, `bun.lock`, `docs/briefs/_B97-common.md` (image tag), tests, D115 if needed.

## Acceptance (on `oven/bun:1.4.5`)

The whole `ci.yml` check job, the release gate's 10 valid `bun run check` runs (load recorded), `bun run release:verify`, `bun run release:package` with the packaged `--version`, and `bun run sends:production`. Also run `bun run check` once on `oven/bun:1.4.4` against the item-2 fix alone (before the bump commit) to show the fix is version-independent.
