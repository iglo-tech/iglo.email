## Items and D124

1. **Future `occurred_at`:** an event dated in the future is accepted and its first step scheduled for that future time. D124: `occurred_at` more than 15 minutes ahead of the server clock is refused with `400 Invalid fields: occurred_at` (single and batch item), nothing written; within the skew it is accepted as given. Considered: clamping silently (changes the app's data without telling it).
2. **Late transactional steps:** a 6-day-old order still starts transactional step 1 six days late; only marketing steps are skipped as `late`. D124: the per-step `max_late` (or the sequence-level field, whichever exists for marketing) also applies to transactional steps when the author sets it; unset keeps today's behaviour (transactional mail is never skipped by default). Document it in `05-sequences.md`.
3. **Campaign test subject:** step tests prefix `[Test] `, campaign tests do not. D124: campaign test sends prefix `[Test] ` too (deliberate difference from listmonk: a recipient must recognise a test; D117 already makes them inert).

## Tests

Events API: +14 min accepted, +16 min refused (single and batch, nothing written, idempotency key not consumed); a transactional step with `max_late` set and an old event is skipped `late` (with B116's reason), without it it sends; a campaign test mail's subject starts with `[Test] `.
