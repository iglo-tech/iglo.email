# B118l: the last two pick-then-close ports in tests

Branch `task/B118l-last-ports`. PR title "B118l: no pick-then-close port in messaging TLS and the journal refusal test". Read [`_B97-common.md`](_B97-common.md) first. Test files only; no product change. Containers start with `b118l-`. Found by the B118i r2 review on #214.

The release gate rule in [`chief-of-staff.md`](../chief-of-staff.md) applies: the race is cleared by removing the mechanism, not by a retry.

1. **`test/messaging/tls.ts:20-34`.** `port()` binds port 0, closes it, and Mailpit is then spawned on that port (SMTP and HTTP, lines 46-56). A parallel test can take the port in between. Remove the race: for example, start Mailpit with `127.0.0.1:0` and read the ports it bound (from its own output, its API, or the process's listening sockets as `listensOn` in `test/serve-port.ts` does), or hold the port another way the pinned Mailpit supports. Check what the pinned Mailpit binary does with port 0 before choosing. If no race-free way exists, say exactly why in the PR and make a collision fail by name (the `--label` run id already identifies the owner) instead of passing or failing obscurely.
2. **`test/sends/journal.test.ts:297-308`** ("actual TCP refusal…"). It binds port 0, closes it, and expects connections to that port to be refused. If another process takes the port, the connection succeeds and the test fails for the wrong reason. Make the refusal certain, for example a target that refuses by construction (a port held by a socket that is bound but not listening, if Bun or Node allows it; or another mechanism), or, if none exists, detect a non-refusal and fail by name.

Mutant per item: show the test fails by name when its port is taken (or when the guard is removed). Test scope (D145): the two files and `lint`, `typecheck`, `format:check`; `bun run messaging:tls` or whatever `ci.yml` step runs `tls.ts`. The lead diff-checks this round instead of a review round if it stays test-only and small.
