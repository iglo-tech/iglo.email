# B114: settings reference contract races upstream's SIGHUP restart

Branch `task/B114-settings-reference-race`. PR title "B114: settings reference contract without the reload race". Test-harness only, no product code. Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, reference recipe: root, Docker socket, host network, `git`; file rules). Source: B113 (v1.4.1) pre-flight, `bun run contract:settings:reference` exit 1:

```
FAIL settings-fetch-GET-refused (attempts=158 waited=5009ms code=ECONNREFUSED reference=true log=... error loading app config: ... 'batch_size' cannot parse value as 'int': strconv.ParseInt: invalid syntax)
```

B111's pre-flight passed the same step on the same test and reference, so it is intermittent; the release gate requires the cause fixed or the nondeterminism removed, never a retry or a wider wait.

## Mechanism (lead reading; prove or refute)

`test/contract/settings.ts:404-407`: in reference mode the test PUTs `"not-an-integer"` to `app.batch_size` (upstream accepts, 200, D44 difference), then GETs `/api/settings` and expects upstream's 500. Upstream schedules a SIGHUP self-restart after an accepted settings write (`test/contract/settings-reference-fetch.ts:22-23`); the restarted process fails to load the config (`batch_size … cannot parse`) and exits. If the GET reaches the old process before the restart, it gets 500 (pass); if the restart wins, the server is gone and every retry is refused until the 5 s deadline (fail). The outcome depends on timing.

## Task

Reproduce both outcomes deterministically if possible (for example a delay before the GET in a scratch copy makes it fail every time; none makes it pass more often), and count failures over 20 runs of `contract:settings:reference` before the fix if time allows.
2. **Make the reference-mode assertion timing-independent**, keeping what the contract proves (upstream accepts the invalid value and the install becomes unusable for settings reads; iglo.email refuses it, D44):
   - Preferred: in reference mode, after the 200, assert the upstream end state deterministically: either the GET answers 500, or the reference process has exited with the `cannot parse value as 'int'` line in its log (read through the existing log tail). Both are the documented upstream failure for this input; record which occurred. In reference mode this step is the last of `runSettingsContract` (everything after line 407 is normal-mode only), so no later step needs the server; confirm this and keep it the last reference step.
   - Normal mode (iglo.email) is unchanged: 400, value unchanged, survives restart.
   - Show the change catches a regression: a scratch mutation where the reference accepts and stays healthy (GET 200) must fail the assertion.
3. Run `contract:settings:reference` 20 times in a row after the fix (record pass count), plus `contract:settings` (normal) and `contract:reference`.
