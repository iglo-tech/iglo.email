## Items

1. **Notification addresses in the admin form** (B117a r1, pre-existing). The admin settings form splits `app.notify_emails` on commas. An address whose display name contains a comma (`"Ops, Team" <ops@example.test>`, stored through the API) then becomes two broken entries, and since B117a it gets a 400 on every form save. Parse addresses, not commas: one entry per address, display names kept. The API stays an array. Amend D136.
2. **From-address reorder** (B117a r2). Reordering `app.from_email` entries can move an already-stored entry that the new rule refuses into first place, where it becomes the default sender. Check the entry that becomes first, even if it is already stored. Amend D136.
3. **Liquid: bare `forloop` as `limit:` or `offset:` inside a loop** (B117e r2). It saves, then every send with items fails. Refuse it at save. Amend D134.
4. **Liquid: decimal division** (B117e r2). `10 | divided_by: 4.0` gives 2.5, but a literal `10.0 | divided_by: 4` gives 2, as does Shopify's `times: 1.0` idiom (`x | times: 1.0 | divided_by: 4`). LiquidJS and Shopify give a decimal. The rule becomes: the result is a decimal when either operand is a decimal, whether literal, text or the result of `times: 1.0`. It is whole-number division only when both operands are integers. Check the installed LiquidJS source and Shopify's documented examples. Amend D134 and 06.
5. **Liquid: a loop object stored with `assign`** (`{% assign f = forloop %}{{ f.parentloop }}`, B117e). It saves, then fails at send. Refuse at save an `assign` or `capture` whose value is `forloop` or one of its properties that the renderer does not expose, and the reads through that name. If that cannot be done exactly, refuse `assign x = forloop` itself, and say so in 06. Amend D134.
6. **Placeholder one-click copy** (B117b r1). The old placeholder link's one-click POST says "You have been unsubscribed" when nothing was pending, which now also happens for subscribers with only single opt-in lists. When nothing changed, say so in every bundled locale, using an existing key if one fits. Amend D137.
7. **D137's locale claim** (B117b r1). D137 says every bundled locale has the "Your email settings" label, but only `en.json` does. Add the label to the other locales, in English until translated, as `i18n/README.md` says, or correct D137's wording. Pick whichever matches how other new labels were handled (B127 kept English in each pack).
8. **The placeholder-link difference is marked in the contract suite** (B117b r1, AGENTS rule). The placeholder link ends pending double opt-ins only, while upstream ends every unconfirmed row. Add a contract case that runs on both targets and marks the expected difference, as `plain-alternative-d118` does in `test/contract/tx.ts`.
9. **B119 wording** (B119 r2). The perf note `docs/perf/B119-media-buffer.md` and the comment in `test/media/upload-retention.test.ts` say a large Blob's bytes live in a memfd that `external` does not see. That is true for the `File` from `formData()`, but the Blob that `formFile` builds is counted by `external`. Correct both texts. No behaviour change.
