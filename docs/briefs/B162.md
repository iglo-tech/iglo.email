# B162: sources as a module, a connector list and iglo.base (three tasks)

Owner direction 2026-11-26 (relayed by another agent): external sources must not hardcode PocketBase. They become a module the instance turns on or off, each project picks a connector, iglo.base is a second connector built the same way as PocketBase, and adding a connector later is easy. Umbrella decision [D187](../design/09-decisions.md#d187-sources-module-and-connectors-owner-2026-11-26) (amends D169 and D170). Spec: [15-external-sources.md](../design/15-external-sources.md). Target: 2.3.0. Read [`_B97-common.md`](_B97-common.md) first; decision records go in as "(B162x, lead, <date>)" with the number below. Keep any adopter or product name out of code, docs, commits and PRs. Each task: one worker, branch `task/B162<x>-<name>`, base `origin/main`, PR title "B162<x>: <title>". Each task adds an "As built (B162x)" note to the spec section it changes and updates `05-sequences.md`, `07-api-and-ui.md`, `docs/operations.md` and the OpenAPI document for anything it changes there.

**Order.** B162a and B162b in parallel (D133: b only adds test files and a script). Then B162c (needs both). Then the 2.3.0 release.

**Shared rules.** Existing PocketBase behavior does not change when the module is on and the connector is `pocketbase`: every existing test under `test/sources`, `test/conditions` and `test/sequences` passes unedited, except an edit the PR lists with its reason (an import path or a renamed type counts; a changed expectation needs a reason). No network call inside a SQLite transaction. Every loop and timer takes the injected clock. Marketing sends stay at-most-once. No new runtime dependency. Tests run against real release binaries; no protocol mocks except to force a transport error a binary cannot produce (say which). ## B162a: the module switch and the connector list (D188)

Owns `src/sources/**` (except new connector files B162c adds), the `sources.enabled` instance key and the `source.connector` project key with their validation and migrations, the source section of the settings views, the source routes and MCP tools' absent answers, the sequences validation path that refuses `"source": "external"` while off, `test/sources/**` except the files B162b and B162c own, D188.

1. **Connector-neutral types.** `src/sources/source.ts` keeps the `ExternalSource` interface and gains a connector-neutral `SourceConfig` (URL, service account, collections and field map, users, grant rules) and a typed error classification (`transient | permanent | notFound`, replacing `isNotSourceId`). `check.ts`, `project.ts`, `records-stream.ts`, `stream.ts`, `recipient-sync.ts`, `settings.ts`, `src/conditions/**`, `src/sequences/**`, the scheduler and the campaign runner reach a source only through these types. Filter syntax, token confirmation, realtime topic limits and the id format stay inside `src/sources/pocketbase*.ts`. Whatever the stream needs from a connector (SSE topics, catch-up pages) goes through a typed connector method, not a PocketBase import.
2. **The connector list.** One module, `src/sources/connectors.ts`, exports a typed `const connectors` map keyed by connector name; each entry has `displayName`, `create(options) → ExternalSource`, and a settings validator for anything connector-specific. Entries are imported statically. Nothing else constructs a source. Record in D188 why this is a deliberate exception to AGENTS.md's "no generic registries": a closed, statically imported, typed list with no runtime registration, no string lookup outside settings validation, and one place to read. Adding a connector is one module plus one line in this map.
3. **`source.connector` (project key).** Values: `""` (none) or a key of `connectors`; this task adds `pocketbase` only (B162c adds `iglo.base`). A source is configured when the connector is set and the URL is non-empty. Validation messages and the settings fieldset name the chosen connector's `displayName`; the fieldset title is "External source" with a connector select. Upgrade: a project whose `source.url` is non-empty gets `source.connector = "pocketbase"` (project migration, idempotent, no other change).
4. **`sources.enabled` (instance key).** Boolean, instance settings page and `/api/instance/settings` only (a project `PUT /api/settings` naming it is a 400). Default: `false` on a new instance; the upgrade sets it `true` when any project has a non-empty `source.url`, so a running deployment keeps working. While off: no stream, catch-up or retry loop starts for any project; the source routes and MCP tools answer as if absent (404 with the same body as an unknown route, MCP tool not listed); the project settings page shows no source section; `PUT /api/settings` naming `source.*` keys is a 400 that says sources are off; creating a sequence or changing one to `"source": "external"` is a 400; Test connection is absent. Data and consent are never lost: `source.*` settings, stream markers, dedupe and retry rows stay untouched; existing external sequences and their enrollments are held (not advanced, not exited, no `source_error`, the 72-hour transient clock does not run while off) and the sequence UI says sources are off. Turning it on again resumes each stream from its marker (normal catch-up) and the held enrollments continue. Turning it off stops running streams within one loop tick without writing attention lines. Record the key name, defaults and the held behavior in D188.
5. **Measurements.** Idle cost per project with the module off vs on with no connector vs on with a connected source: loops started, timers, RSS and CPU over 10 minutes of injected-clock time with 20 projects, before (main) and after, into `docs/perf/B162a-module.md`. Off must start no source loop or timer.
6. **Tests.** Upgrade (a 2.2.1 data directory with a source → module on, connector `pocketbase`, stream resumes); off → routes 404, MCP tools absent, settings section absent, `source.*` PUT refused, external sequence create refused, existing enrollments held across days of injected clock with no `source_error`, nothing written to stream tables; on again → catch-up delivers records created while off exactly once; a project `PUT` naming `sources.enabled` is a 400; error messages name the connector.

Acceptance: shared rules; `contract:settings` and `:reference`; `contract:sequences` and `:reference` if present; `E2E_WORKERS=2 bun run e2e`; every `sends:*`; an `agent-browser` pass over the instance switch, the connector select, a project with sources off, and an external sequence held then resumed.

## B162c: the iglo.base connector and the connector contract suite (D190)

Owns `src/sources/iglo-base*.ts`, the `iglo.base` line in `src/sources/connectors.ts`, `test/sources/connector-contract*.ts`, the "Adding a connector" section of `15-external-sources.md`, D190. Needs B162a and B162b merged.

1. **Connector.** `iglo.base` as a connector that reuses the PocketBase connector's code (call it with iglo.base's options; copy nothing). Handle every difference from B162b's D189 that reaches us; each handled difference gets its own test against the iglo.base binary.
2. **Contract suite.** One shared suite every connector passes, parameterized by connector name and harness: settings validation, Test connection (including the guest-readable check), every adapter operation (`recipient`, `record`, `latest`, `count`, `exists`, `scan` paging and `skipTotal`), hostile filter literals, token refresh and 401, transient vs permanent errors, the private-address rule with `sources.private_hosts`, the realtime stream (live delivery, disconnect and catch-up with nothing lost or doubled, a reset treated as routine), the record handler (subscriber upsert, a grant and its refusals, leaving), and a send-time lookup. Run against both binaries. Existing PocketBase tests stay; the suite adds to them.
3. **Docs.** "Adding a connector" in `15-external-sources.md`: implement `ExternalSource` in one module, add one line to `connectors`, add a harness and run the contract suite; what may and may not be connector-specific. `docs/operations.md` "External sources" names both connectors and how to choose. If something only iglo.base offers is useful to us later (for example its schema as code, `iglo.schema.json`), list it in D190 as a possible follow-up; do not build it.
4. **Measurements.** Catch-up throughput and a 10,000-recipient campaign with lookups, PocketBase vs iglo.base, into `docs/perf/B162c-connectors.md`.

Acceptance: shared rules; `contract:settings` and `:reference`; every `sends:*`; `E2E_WORKERS=2 bun run e2e`; an `agent-browser` pass over choosing iglo.base, Test connection against a running iglo.base and a source-backed sequence to a received mail through Mailpit.
