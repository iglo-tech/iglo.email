Each fix has a test against the real PocketBase binary (or the injected clock) that fails without it; revert with Edit, run, restore, and report. D194's rule still holds.

1. **Test connection's guest check passes on any non-200 answer** (major, `check.ts` `guestCheck`, `pocketbase.ts` `guestProbe`). It fails the step only on a `200` with rows; a `429`, `5xx`, `400` or `3xx` from a proxy or a broken rule passes, contrary to spec section 2 ("a `200` with no rows, a `403` or a `404` passes") and D172's requirement that guests cannot read `events` or `recipients`. Fix: pass only on `200` with no rows, `403` or `404` (decide `401` and record it in D199); any other answer fails the step naming the status and its reason. Tests through a proxy: `503`, `429` and `400` on the guest probe fail the step; `403`, `404` and an empty `200` pass.
2. **A persistent `401` on `POST /api/realtime` is treated as transient** (minor, `pocketbase.ts` `stream.realtime`). The `attempt === 0` guard covers only `403`, so a `401` after a fresh sign-in drops the new token and ends as a transient "did not confirm the token": no refusal attention line, retries every minute with a sign-in each. Fix: retry a `401` or `403` once; the second is that status's permanent failure. Test: a proxy answering `401` twice on the subscription → the stream refuses (refusal line, 5-minute retry).
3. **A leaving filter that saves and passes Test connection can make the stream unsubscribable** (minor, `settings.ts`, `check.ts`, `stream-reads.ts` `usersTopic`). Settings allow 2,000 characters and Test connection probes it as a list filter, but the encoded users topic must fit `TOPIC_LIMIT` (2,500) or the stream throws a permanent error before connecting and stalls every topic. Fix: refuse on save (400 naming the key) and fail the Test connection users step when the encoded topic would exceed the limit, with the same encoding the stream uses (one function, not a copy). Tests: a ~1,200-character filter of short clauses is a 400 on save and fails the check; a filter that fits still saves.
4. **`eventsSchema()` accepts a list whose items are not objects** (minor, `pocketbase.ts`). Every other list check requires `items.every(isSourceObject)`; a `200 {"items": ["x"]}` makes a condition's own 400 look like the condition's and the record is committed. Fix: the same check. Test through a proxy: the stream waits, nothing committed.
5. **Going idle keeps stale failure state** (minor, `stream.ts`). The idle branch resets `delay` and drops markers but keeps `failingSince`, `warned` and `refusals`, so after reactivation a one-second blip writes "cannot connect" at once, or a refusal from before is never reported. Fix: clear them when going idle. Injected-clock test: fail once, go idle for 20 minutes, reactivate with one short failure → no attention line; a refusal recorded before idle is reported again after reactivation.
