# B32: cheaper `settings.read()` (D88)

Common rules: [_state-common.md](_state-common.md). Branch `task/B32-settings-read`. Lines cited from main at c964261.

## Source

Backlog line "Event latency tail" and D88 ([evidence](../perf/B31-event-tail.md)): `settings.read()` is the largest main-thread cost under the mixed load, about 17,000 reads in 130 s at roughly 2.6-2.9 ms each. A precomputed fold map in `bindFull` gave event p95 about −35 % in two disturbed runs.

## Owns

- `src/settings/validate.ts`, `src/settings/store.ts`, `src/settings/stored.ts`, `src/settings/hold.ts` (only to keep a cache coherent)
- tests under `test/settings/*`, `docs/perf/B32-settings-read.md` (new), a D88 note

## What to do

1. **Remove the quadratic lookups.** `bindFull` (`src/settings/validate.ts:198-207`) and the nested shape match at `:164` and `:171` call `foldField` (`:126`) inside `find` for every key. The shapes are static: build a folded-name map once at module load (a constant, not process state) and look names up in it. Keep exact semantics: first matching shape wins, same folding (`ſ`→`s`, Kelvin `K`→`k`, then lower-case). Test first: a settings API test that already pins a folded or odd-cased key must still pass; add one for a key that differs only by `ſ`/`K` folding if none exists.
2. **Measure**, then decide whether to cache. Run `bun run perf:mixed` (compiled) before and after item 1, 3 runs each if the host allows, with load and hashes recorded; mark disturbed runs. If `settings.read()` is still a top-3 main-thread cost (the B31 probe, `M61_TAIL_PROBE`), add a cache of the projected result in `createSettings`:
   - invalidate it on **every** write to the `settings` table: `update` in `store.ts`, `writeStoredValue` in `stored.ts` (used by `hold.ts` and `backup/snapshot.ts`), and the seed. A writer that bypasses the store connection (another process, restore of a snapshot) must not leave a stale value: use a version that changes on any write to the table, for example a trigger-maintained counter row read with one cheap query, or prove every writer goes through the store.
   - return values callers cannot mutate into the cache (check whether any caller mutates the result).
   - no process-global state (AGENTS.md): the cache lives in the store instance.
     If item 1 alone removes it from the top 3, skip the cache and say so.
3. **Log** before/after and the outcome in D88; update the backlog line (remove it if the remaining tail is commit fsync waits only, which D86 accepts).

Acceptance: `bun run check` (verify lock), `test/settings/*`, `bun run contract:normal`, `bun run contract:roles`.
