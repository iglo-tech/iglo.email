# B115: campaign test sends cannot unsubscribe or track a real subscriber

Branch `task/B115-campaign-test-links`. PR title "B115: campaign test sends are inert". Decision record: D117 (lead, 2026-11-20), appended at the end of `09-decisions.md`. Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, file rules, task-PR acceptance). Source: owner directive 2026-11-20 (no known gap open before go-live) and the B112 review.

## Defect

`POST /api/campaigns/:id/test` resolves each address to a real subscriber and renders the mail with the real campaign UUID and that subscriber's UUID, plus the one-click `List-Unsubscribe` / `List-Unsubscribe-Post` headers when `privacy.unsubscribe_header` is on. Clicking Unsubscribe in a test mail (the page form, or a mail client's one-click) therefore unsubscribes that real subscriber from the campaign's lists and fires the webhook. Tracked links and the view pixel may likewise record clicks and views against the real campaign and subscriber (check). A test is a preview for a person; it must change nothing (D105 for step tests, D116 for their unsubscribe page).

## D117 (implement exactly this)

- A campaign test message carries the nil send placeholder in every per-message link exactly as a step test does (D105/D116): `unsubscribe_url`, `manage_url`, the archive/message link if it embeds the send or subscriber, and the `List-Unsubscribe` headers. Those links open the B112 "test send" page; one-click POST is a 200 no-op. Campaign mail uses listmonk's `/subscription/{campaignUUID}/{subscriberUUID}` path (`src/campaigns/routes.ts:795`), not `/m/…`: give the test the nil UUID as the campaign UUID on that same path and make `/subscription/00000000-0000-0000-0000-000000000000/:subUUID` (GET, form POST, one-click POST, `?manage=true`) answer the same test page with the same rules as D116 (no lookup, no write, identical bodies), so real `/subscription/…` links are unchanged. No other per-subscriber link in a test may identify a real subscriber in a way that can change state.
- Tracked links and the view pixel in a test: rendered untracked, as step tests are (`track_link` returns the URL unchanged, `track_view` renders nothing), so a click or open on a test records nothing. If listmonk renders tracked links in tests, this is a deliberate difference: list it in `07-api-and-ui.md` with the reason (a test must not change real data or statistics) and mark it in the contract suite as the rules require.
- Unchanged: who receives a test (listmonk's rule: known, non-blocklisted subscribers in the caller's scope), the `[Test]`-less campaign subject (listmonk), the B108 Message-ID recording and bounce handling, sending path (D109 test pool).
- Read the pinned upstream campaign test-send code (`cmd/campaigns.go` / `internal/manager` at 6fcd95f, from GitHub) and state in D117 exactly what upstream does for links and tracking in tests.

## Tests (first, through HTTP + SMTP sink)

A campaign test to a subscriber on the campaign's list: the received mail's unsubscribe and manage links and `List-Unsubscribe` headers point at the nil-UUID test page; GET/POST/one-click on them leave the subscriber's lists unchanged, queue no webhook; tracked links in the body are the plain target URLs and there is no view pixel; `GET /api/campaigns/:id` statistics (views, clicks) unchanged after following the links. A real campaign send to the same subscriber still unsubscribes and tracks as before (existing tests keep passing).
