1. **A gone holder re-pointed to a suppressed user keeps its marketing** (major, `recipient-sync.ts`, the `gone && !now` branch). B166's `took()` applies D125's all-lists withdrawal when a row takes a suppressed address, but the re-point gives the holder row a new `external_id` (the incoming user) without checking whether that user ID is suppressed. A user who unsubscribed or wiped and left, then returns under the same ID with an address an unlinked holder has, gets the holder's marketing memberships, and campaigns reach them. Fix: after the re-point, when the row is now suppressed (by address or by the user ID it took), apply the same withdrawal `took()` applies, in the same transaction. Record in D196 why this does not conflict with D194's "Considered" note on D99 overrides (the row never belonged to that user). Test: the scenario above sends no marketing; a re-point onto an unsuppressed user keeps memberships as now.
2. **Catch-up can build a filter over PocketBase's 3,500-byte limit and stall the stream for good** (major, `stream.ts` `catchUp` and `stream-reads.ts`). A topic packs names up to 2,500 URL characters, and catch-up sends one filter with one clause per distinct marker; with ~58+ names with distinct markers the filter (plus the keyset and the confirming `id =` read) passes 3,500 bytes, PocketBase answers 400, and the session retries the same filter every 5 minutes forever. Fix: bound every catch-up filter (with the keyset and the confirming read's clause) below the limit with headroom, chunking marker groups so each chunk advances only its own names' markers and no marker moves past an un-caught-up group. Test: 65 short names with distinct markers catch up fully, each record delivered once.
3. **`one()`'s collection probe accepts a non-list 200, so a live user is deleted as leaving** (major, `pocketbase.ts` `one()`). After a 404 by ID and a passing token check, the probe only checks status and size; a proxy answering `200 {}` or an empty 200 makes `recipient()` return null, and `leaveUser` deletes the live subscriber and ends its enrollments (`record()` gives `trigger_missing`). Fix: require a PocketBase list body as `list()` and `eventsSchema()` do; otherwise a permanent error (→ SettingsMismatch). Test through a proxy: nothing deleted, the stream waits / the campaign pauses.
4. **Record attention dedupe is unbounded and keyed by per-user text** (minor, `stream.ts` `recordWarned`). The key strips only the event record ID, while per-record errors interpolate the user or subscriber ID, so N users in a blocklisted domain write N "failed for good" lines and grow the set without bound. Fix: dedupe by a stable cause (strip or avoid the interpolated IDs) and cap the set as `records.ts` does (`MAX_WARNED`). Test: many users failing for one cause write one attention line.
5. **A listed private host resolving to a zoned IPv6 address loses its pinning** (minor, `connect.ts`). `privateAddress()` strips `%zone`, but assigning a zoned literal to `URL.hostname` is silently ignored, so the request goes out to the unpinned host name with a second, unguarded DNS lookup. Fix: refuse zoned addresses for sources (WHATWG URLs cannot carry them), or check the pin took before sending; refuse is simpler. Test with an injected resolver answering `fe80::1%eth0`: refused, no request sent.
