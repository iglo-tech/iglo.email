## Tests (new `test/e2e/specs/analytics.e2e.js`, about 10 tests)

Generate every view and click by following the pixel and tracked-link URLs **from received mail** (as B68 does). Fix the range with `from` and `to`.

1. Campaign clicks chart and the links chart count real clicks, per link URL.
2. The bounces chart counts a bounce posted to `/webhooks/bounce` for that campaign.
3. The `unique` toggle with `privacy.individual_tracking` on: two opens by one person count 2 total and 1 unique; restore the setting in `afterEach`.
4. Interval day, week and month change the buckets as expected for events on known dates (events land "now"; assert the bucket that contains today and that totals match across intervals).
5. A `from`/`to` range that excludes today shows no data ("Nothing here") and one that includes it shows the counts.
6. The list unsubscriptions chart counts a real unsubscribe through a mail link.
7. Dashboard charts and counts move after real views and clicks (read the dashboard API fields and the page).
8. Two campaigns selected together show both series with their own counts.
9. **Individual tracking, stronger (B68 review):** send with `privacy.individual_tracking` on, then turn it off, then follow that mail's pixel and link: the events are counted but not tied to the subscriber (check the subscriber-level data the API exposes). This catches a pixel or click route that ignores the setting.
10. Any chart or page error is a test failure (collect `pageerror`, as `maintenance.e2e.js:186` does).

If a test reveals a real product bug, do not fix product code: mark it `test.fail()` naming the bug and report it prominently in the PR.
