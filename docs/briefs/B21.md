# B21: Auth, bounce settings and webhook postpone

Common rules: [_state-common.md](_state-common.md). Branch `task/B21-small-state-fixes`.

## Owns

`src/users/*`, `src/settings/validate.ts` (only the `bounce.actions` part), `src/webhooks/store.sql` and `src/webhooks/store.ts`, `docs/operations.md` and the tests.

## Behavior

1. **Recover from a lost TOTP device.** No admin or CLI path clears another user's TOTP. `set-twofa` is called only from `src/users/factor.ts`, and the CLI only sets a password (`src/users/cli.ts:55-66`).
   - Add a CLI command, next to the existing password command, that turns TOTP off for a named user and revokes their sessions.
   - Document it in `docs/operations.md`.
2. **TOTP does not come back.** `update-user` never touches the TOTP columns (`src/users/queries.sql:30`). A user→api conversion keeps the TOTP pair, and turning `password_login` off and on later revives an old key.
   - Clear `twofa_type` and `twofa_key` when `password_login` is turned off or `type` becomes `api`.
3. **Validate `bounce.actions`.** The settings check is shape-only (`src/settings/validate.ts:74`). With `count: 0`, no bounce rows are stored and the action fires on every bounce. An unknown `action` silently does nothing.
   - Read upstream's allowed actions and count range.
   - Refuse values outside them with 400, as other settings are refused. This tightens input only, as D57 allows.
4. **A webhook postpone keeps its guard.** `delivery-postpone` (`src/webhooks/store.sql:59`) updates by `WHERE id = ?` only and leaves a stale `claimed_until`. A restart's recovery then puts postponed rows back to due.
   - Guard it by `status = 'queued'` and clear `claimed_until`.
   - Check the NULL-lease branch of `delivery-end` (`:69`) at the same call site.
