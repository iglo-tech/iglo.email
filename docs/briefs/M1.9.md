## Behavior

1. **API:** `GET /api/import/subscribers`, `GET /api/import/subscribers/logs`, `POST /api/import/subscribers`, `DELETE /api/import/subscribers`, with upstream's `subscribers:import` permission, multipart `file` and `params` fields, status and log shape, and states (`none`, `importing`, `stopping`, `finished`, `failed`). One import runs at a time, as upstream.
2. **Parameters:** `mode` (`subscribe`, `blocklist`), `subscription_status`, `delim`, `lists`, `overwrite`, with upstream's validation. List IDs respect list-scoped permissions wherever upstream does.
3. **CSV:** the columns `email`, `name`, `attributes` and optional others as upstream, header handling, attribute JSON, row validation, duplicate handling within a file, and upstream's per-row skip and logging. Upstream reads ZIP too, but 01 puts ZIP after v1: refuse it cleanly and list that in 07. Malformed input is safe: a bad row is skipped and logged, and a bad file fails the import.
4. **Writing:** rows go in short batches through the subscriber store, so the single writer stays available between them, and `overwrite` follows upstream. Nothing blocks the event loop for long: yield between batches. Subscriber attributes obey the existing validation and size limits. Blocklist mode and any status change obey consent rules: `overwrite: false` never re-enables a blocklisted or unsubscribed person. Search and list counts stay correct afterwards.
5. **Webhooks:** blocklist mode and any other consent change must queue the same outbound webhooks as the API does, inside each batch's transaction, under the bulk delivery budget of D61. Decide what happens when a file exceeds that budget, and say so. An import refused or stopped partway leaves a consistent state.
6. **Upload and memory:** bound the upload size and state it. Stream the file from disk or the request so memory does not grow with row count. Temporary files are removed on finish, stop, failure and at startup, within an application-owned directory. Bound the retained log.
7. **Lifecycle:** a `DELETE` stops the import between batches. Shutdown stops it in order. After a crash nothing resumes, and the status says what happened, or says `none` if upstream's in-memory status is what clients expect; choose and say why.
