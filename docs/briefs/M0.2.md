## Required behavior

### Preparation and platforms

- `bun run reference:prepare` fetches source at the exact pinned commit and native listmonk/Mailpit binaries under this checkout's ignored `upstream/` directory. Verify the source commit and archive checksums before executing anything. Cache verified downloads; fail clearly on wrong/corrupt cache entries without overwriting unrelated files.
- Support Linux and macOS, x64 and arm64, with clear errors for unsupported platforms. Use Bun/Node standard APIs and portable Git/Docker commands; no `/proc` dependency, GNU-only shell utilities or new system package installation.
- Do not change `/home/t3-code/upstream/listmonk`, global Git/Docker settings or any other checkout.

### Lifecycle

- `bun run reference:run -- <command> [args...]` prepares as necessary, starts the reference services, waits for bounded readiness, executes that exact argument vector with the test environment below, and cleans up after the command exits. No shell interpolation. Propagate command failure.
- The wrapper must stop its own listmonk/Mailpit/test-command child processes and its own webhook server, then remove only its own Postgres container and volume, on success, startup failure, command failure, SIGTERM or SIGINT. Use subprocess handles and exact owned container IDs/labels. Never use `pkill`, global prune, broad name matching or unverified saved PIDs. Repeated cleanup must be safe.
- Give each run unique resource names and disposable state. Bind service ports to loopback, choose available ports instead of taking an existing service's fixed port, and permit independent checkouts to run without sharing database/mail/webhook state.
- Use the existing Docker daemon, including rootless Docker or Docker Desktop. Add conservative Postgres resource limits appropriate to the host (for example 256 MiB and one CPU). Do not restart/configure the daemon or run Docker disk accounting. Remove only this run's resources; downloaded caches can remain.
- Run the published native listmonk binary with its embedded assets, environment-only bootstrap configuration and `--install --yes --config ''` against the newly created Postgres database. Seed only synthetic admin and API users. Capture generated API credentials for the child command, avoiding printing tokens or unrelated inherited environment values.
- Configure reference SMTP exclusively to this run's Mailpit. Do not inherit potentially external `LISTMONK_*`, Mailpit relay/forwarding or Postgres settings into the managed services. No real SMTP or webhook endpoint can be used.

### Test services and environment

- Mailpit receives local SMTP and exposes its local HTTP API for assertions. No outbound relay or forwarding.
- A small `Bun.serve` webhook receiver records request headers and the original body and exposes documented HTTP endpoints to read/reset captured deliveries. Keep state local to the owned receiver instance. Include a simple way for later tests to select a response status; delivery retries themselves are outside this task.
- Export and document `REFERENCE_URL`, `REFERENCE_API_USER`, `REFERENCE_API_TOKEN`, `MAILPIT_URL`, `MAILPIT_SMTP_HOST`, `MAILPIT_SMTP_PORT`, `WEBHOOK_URL` (delivery endpoint) and `WEBHOOK_RECEIVER_URL` (capture/control API) to the child command. Endpoints must describe the services actually started. Do not put generated tokens in committed files.
- Store synthetic manual credentials/data in `test/reference/fixtures.md`. No production data or existing database. Normal CLI command output is allowed; application logging rules remain unchanged.

### Validation

- `bun run reference:smoke` uses the real runner and validates pinned binary versions/source, upstream `GET /health`, an authenticated API read, an email received in Mailpit, and a delivery captured by the webhook receiver. Verify owned resource cleanup after the run.
- Exercise command failure, partial startup failure and signal cleanup through the runner's public CLI. Prove an unrelated local sentinel process/resource survives teardown. Tests must observe public HTTP/SMTP/subprocess/container boundaries, never source text or private helper implementation details.
- Bounded readiness retries are allowed for process startup. No sleeping to test domain time. Ensure subprocesses and Docker operations have practical deadlines, and failed tests leave their resources cleaned up.
- Ordinary `bun test` and `bun run check` must continue to work without a Docker daemon or downloads. Put explicit integration behind the reference command/opt-in and run it in a dedicated Linux CI job with Docker. Do not silently skip the required reference smoke in that job.
- Add native macOS preparation/version validation in CI if feasible without new host services. Full Docker-backed lifecycle must be portable to macOS with Docker available. Distinguish actual Linux lifecycle results, native macOS checks and any untested full macOS lifecycle in the PR; do not claim this Linux host tested macOS.
