## The problem

B6 measured peak RSS growth at about 8x the counted bytes ([evidence](../perf/B6-send-media-safety.md), lines 34-41): the journal's base64 payload, the SMTP library's own encoding and uncollected garbage are outside the count, so the 64 MiB "budget" is really about 500 MiB of growth at worst. A host with 2 GiB minimum memory (like this one) can be pushed into swap or OOM by realistic concurrent API clients sending large attachments.

## What to do

1. **Measure where the bytes go.** With `bun run tx:measure` (extend it if needed), find the peak RSS growth per counted byte for: multipart upload with attachments, JSON send with base64 attachments, 1 and several synchronous recipients. Attribute it to each copy (read chunks, joined body, form, decoded copies per recipient, journal payload, SMTP encoding) as far as a heap snapshot or `Bun.gc(true)` sampling allows.
2. **Remove copies that are not needed**, where it is cheap and keeps at-most-once and no network inside a transaction. Examples to check: dropping references to the parsed form/body before SMTP starts, sharing one decoded copy across recipients, letting the journal hold only base64 while the SMTP call gets the same buffer.
3. **Then make the count honest.** Charge what is actually held (adjust `PARSE_COPIES` and the per-recipient charge to the measured multiplier after item 2), and pick the budget so measured peak growth stays under a stated bound (target: about 256 MiB growth at worst, so a 2 GiB host stays safe). Keep the 429/413 behavior and the fairness rules of D78 unchanged in kind; a realistic client still gets 2xx for one large send on an idle server (the existing limits on a single attachment must still fit).
4. **Log D87** with the measured before/after peaks, the chosen numbers and the refusal trade-off; update D74 and the backlog line (remove it, or keep only the 380 rows/s retention note, which D74 already justifies).

Sending is changed, so `docs/perf/B26-tx-memory.md` needs before/after runs with source/executable hashes. Hold `flock ~/.local/state/iglo-email-cos/measurement.lock` for measurements and the verify lock for full suites. Acceptance: `bun run check`, `test/tx/*`, `bun run contract:normal`.
