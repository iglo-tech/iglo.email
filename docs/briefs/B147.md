## Goal

The public manage view becomes a preference center: subscribers edit admin-chosen profile fields with types and validation, and opt in as well as out per public list the admin exposes, with descriptions, without weakening any consent rule.

## Behaviour

1. **Editable profile fields.** A new project setting lists which `attribs` keys the public page shows and which it lets subscribers edit, each with a label, a type (D160 picks a small set, e.g. text, number, boolean, date, one-of) and validation (required, length/range, allowed values). The public form writes only those keys, validated server-side; any other key in the form is ignored or refused (D160) and never written. Name stays editable as today; email is not editable (D160 confirms).
2. **Consent per list.** The page shows every public list the admin exposes on the manage view (D160: reuse the list's existing public flag, or an explicit setting if needed), each with its description, grouped only if a simple existing field allows it. A subscriber can opt in to lists they are not on and opt out of lists they are on. Double opt-in lists still need confirmation: opting in creates an unconfirmed subscription and sends today's opt-in mail (Mailpit). Blocklisted subscribers and marketing-suppressed subscribers (D125/D128) cannot opt in; verify what "unsubscribe from all" does today and keep it. Lists are the only consent mechanism (D89); no second category model.
3. **Reaching the page.** Verify whether `manage_url` (or an equivalent tag) already reaches the page from any email, including transactional mail and sequence steps; add a Liquid variable or tag only if one is missing, under D126's pairing rule for public state changes and the transactional manage view (D126/D137). D160 records the outcome.
4. **Existing behaviour kept:** `privacy.allow_preferences` gates the page; export and wipe (`privacy.allow_export`, `privacy.allow_wipe`) unchanged; the unsubscribe page and RFC 8058 POST unchanged; rate limits and captcha on public forms as today (shared budgets, D151).
5. **Admin UI:** the settings section to choose and type the fields, and a list-level way to expose a list on the manage view if D160 needs one. Server-rendered TSX, Alpine.js, Oat.
