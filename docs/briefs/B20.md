# B20: Sequence enrollment endings

Common rules: [_state-common.md](_state-common.md). Branch `task/B20-enrollment-endings`.

## Owns

`src/sequences/*`, `src/scheduler/scheduler.ts`, `docs/design/05-sequences.md` and the tests.

## Behavior

1. **`exit_on` ends enrollments whatever the sequence status is.**
   - Today `exit-by-event` (`src/sequences/enrollments.sql:6`) matches only `s.status='active'`.
   - The unsubscribe and blocklist exits (`:37`, `:41`) have no such filter.
   - So if you pause a sequence, the exit event arrives, and you resume, the enrollment carries on.
   - Fix: exits by event also apply to draft and paused sequences.
2. **One reason, one status.** The same reason gives different statuses depending on the path. Follow `docs/design/05-sequences.md` (around :143) and use one status per reason on every path.
   - `sequence_archived`: `exited` from the archive path (`enrollments.sql:44`), but `canceled` from the scheduler (`scheduler.ts:120`, `:169`).
   - `blocklisted`: `exited` from subscriber effects (`enrollments.sql:41`), but `canceled` from the scheduler (`scheduler.ts:175`, `:308`).

   If the document doesn't settle one of them, choose, and record it there.
3. **An ended enrollment carries no lease.** These statements leave `claimed_until` and `retry_at` set on rows they end:
   - `enrollments.sql:6`, `:34`, `:37`, `:41`, `:44`

   Clear them, as the `claimed-*` statements already do. Show it through the enrollment API or timeline if those expose it; otherwise argue it in the PR.

## Out of scope

- `defer` moving the lateness baseline (backlog).
- Parked enrollments when a sequence goes back to draft or paused (intended).
- Unreachable archived and deleted branches.

## Measurements

One scheduler run before and after, or the one-paragraph argument for a guard-only change, in `docs/perf/`.
