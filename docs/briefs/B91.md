## Changes

1. **`POST /api/enrollments` ignores the caller's subscriber list scope (defect).** `src/sequences/routes.ts:356-414`: inside the transaction it calls `subscribers.get(subscriberId)` and enrolls whoever exists. A role with `sequences:manage` but subscriber access limited to some lists (no `subscribers:get_all`, list permissions on list A only) can enroll, and so mail, a subscriber who is only on list B, and with `trigger_event_id` can make a test step render that subscriber's event data. The GET routes in the same file already hide such subscribers through `readable` (`routes.ts:133`, which calls `readableSubscribers` from `src/subscribers/routes.ts:56`).
   Fix (D103): after `auth.revalidate` and the existence check, a subscriber the caller cannot read under that same rule (`readableSubscribers(roles, subscribers, identity(c), [subscriberId])` has no entry) answers `404 Subscriber not found`, exactly like an absent one (no existence leak), and writes nothing. Checked inside the same transaction. `DELETE /api/enrollments/:id` and step reschedule are sequence operations and stay as they are (state that in D103).
   Tests (`test/sequences/`, through the HTTP API with a scoped role/user or API token, using the existing role fixtures): scoped caller enrolls a subscriber on its list → 200; a subscriber only on another list → 404 with the absent body, no enrollment row (check via an all-access `GET /api/enrollments`), no mail in the sink after driving the scheduler; same with `test: true` and with `trigger_event_id`; `subscribers:get_all` caller unaffected.
2. **B84 grant tests** (`test/events/` or wherever the B84 `grant_lists` tests live): (a) the grant permission is revoked mid-request (follow the existing mid-request revocation pattern used for other event/subscriber writes) → 403, no grant, no event row; (b) a list-limited API token that was allowed to grant, replayed after the role lost that list → 403 and nothing written.
3. **B85 `fn: null`** (`src/sequences/input.ts:188`): `choice(spec.fn, …, "count")` treats `null` as absent, so `{"fn": null}` saves as `count`. Absent stays `count`; `null` (and any non-string) → `400 Invalid fields: <path>.fn` with no write. Test via sequence create and step update.
4. **B86 reschedule tests**: a test enrollment and a forced manual enrollment, each with `trigger_event_id` naming an older event, rescheduled through `POST /api/sequences/:id/steps/:step/reschedule`: the wait counts from the enrollment's creation (D101), and a test keeps its one-minute cap. Advance the injected clock; no sleeps.

Docs: D103 in `docs/design/09-decisions.md` (enroll scope rule; delete/reschedule unchanged and why; `fn: null` refused). Update `docs/design/05-sequences.md` (manual enroll sentence) and the OpenAPI `POST /api/enrollments` 404 description (`src/openapi/operations.ts:949`).
