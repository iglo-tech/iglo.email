## Behavior

1. **Route:** `GET /api/openapi.json` serves OpenAPI 3.1 JSON. Upstream's document is the starting point for ported routes. Native routes (events, sequences, enrollments, sends, webhooks, analytics, maintenance, Mailgun) are added. Permissions follow the existing auth rules; decide whether it needs a session and say why, comparing with upstream. It holds no secrets and no instance data.
2. **Coverage is a test, not a promise:** a test enumerates every route in the router and fails if one is missing from the document or the document names one that does not exist. Public pages and static assets are listed as excluded with a reason.
3. **Accuracy:** the contract suite validates real responses against the schemas for each documented JSON API, on the compiled executable, including the error envelope. The validator stays in tests, and no validator ships in the binary. Deliberate differences from upstream in 07 show in the document.
4. **Size and cost:** the document is built once, and it doesn't slow startup noticeably. State its size.
5. **Keeping it true:** adding a route without documenting it fails `bun run check`.

## Acceptance

Serially on this host: `bun install --frozen-lockfile`, `bun run check`, `bun test test/openapi`, the OpenAPI contract, `bun run contract:normal`. The contract suite validates responses against the document, and every route in the router is in it.
