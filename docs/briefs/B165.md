Each fix has a test that fails without it (say how you checked: revert the fix, run, restore).

1. **`backup --verify` passes things that are not backups** (major, `snapshot.ts` `inspect` and `inspectWhole`, `cli.ts` `verdict`). `inspect()` returns early for `user_version` 0, skipping the manifest and uploads, and `verdict()` reads 0 as an older schema the server migrates, so an empty or schema-less `iglo-email.db` (in a whole backup's `projects/<slug>/`, a project backup or a bare file) prints "Integrity: ok; the server migrates this backup to version 38" and exits 0. `inspectWhole` also accepts `projects/<slug>` as a regular file (`inspect` takes files as bare snapshots), so a whole backup that cannot be restored verifies. And `inspect()` reads the hold record whenever `user_version` is not 0, so a database with a version but no `settings` table fails with a raw `no such table: settings`. Fix: schema version 0 is "has no schema: not a backup" in `inspect()` for every kind (as B164 did for `instance.db`); `projects/<slug>` in a whole backup must be a directory; the hold read is guarded as `heldNow`/`releaseHold` guard it (a project or instance database without `settings` at a version that should have it is not a backup, by name). `createBackup` already refuses version 0 sources; keep that. Tests through the compiled CLI: each case above refused by name with a non-zero exit; a valid backup still verifies.
2. **A full `PUT /api/settings` resets native project keys it leaves out** (major, `settings/routes.ts` `nativeKeys`). `nativeKeys.project` keeps native keys a listmonk client's full write omits, but it misses `privacy.preference_fields` (B147, D160), `app.site_url` and `appearance.brand.accent`, `.font`, `.header`, so such a write silently empties the preference center and the branding. Fix: list every native project key that is not a listmonk key (check `src/settings/keys.ts` and `defaults.ts` against listmonk's settings at the pinned upstream commit, and do the same for `nativeKeys.instance`); keep `source.password` out as now. Prefer a check that cannot drift: a test that walks every project and instance key, classifies it as listmonk or native from the upstream reference list, and fails when a native key is missing from `nativeKeys`. Contract: a full PUT without the native keys keeps each one (`contract:settings`).
3. **The deleted-project archive writes broken tar headers for pre-1970 times and files of 8 GiB or more** (minor, `deleted.ts` `header`). `octal()` has no bounds: a negative mtime writes `000000000-1` and GNU `tar` refuses the archive the operations guide tells operators to unpack; a size over `0o77777777777` overflows into the mtime field. Fix: clamp the mtime to the ustar range (or a PAX `mtime` record) and carry an oversized size in a PAX `size` record, as long names already use PAX. Test: an archive with a 1969 file lists and extracts with the system `tar`; the size case may be tested on the header function's output through the archive with a sparse file if cheap, else state why not.
