# B22: `send.failed` after a subscriber wipe

Common rules: [_state-common.md](_state-common.md). Branch `task/B22-wiped-send-webhook`.

## Source

PR #70 review, backlog item 2.

## Owns

- the `ended` hook in `src/messaging/sends.ts` and its webhook producer, where `send.failed` is built (see `main.ts`, where `ended` is wired, and `src/webhooks/effects.ts`)
- tests

## Behavior

**The problem.** A send can be in flight while its subscriber is deleted, so it is anonymized (`src/messaging/anonymize.ts`). If it then ends `failed` or `unknown`, it still queues `send.failed` with the subscriber's list ID. That conflicts with D61: a wipe keeps only the numeric ID and UUID. B18 handled only one case, a transient failure before the 5th attempt.

**What to do.**
1. Read D61 and the `subscriber.deleted` handling in `src/webhooks`.
2. Pick one rule and apply it to every `ended` outcome for an anonymized row (`to_email = ''`):
   - either send no webhook, as B18 does for the skipped case,
   - or send a `send.failed` that carries only what D61 allows.
3. Record the choice in D61, or in a short new decision record if D61 does not cover it.
4. Test both `failed` and `unknown` through the webhook receiver.

## Added: legacy enrollment statuses (PR #72 review, backlog 1)

Before B20, the scheduler stored the `blocklisted` and `sequence_archived` endings as `canceled`. D83 now stores them as `exited`, so a `status=exited` filter and the exited count miss the old rows.

Add the next migration after B19's 0016. It sets `status='exited'` on enrollments with `status='canceled'` whose `exit_reason` is `blocklisted` or `sequence_archived`. Leave `updated_at` and `finished_at` as they are. Follow `migrations/README.md`, bump the schema version assertions, and record the change in D83. Test it through the enrollment API filter.
