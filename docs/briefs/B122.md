# B122: every contract script runs in CI and the release pre-flight, and passes

Branch `task/B122-contracts-in-ci`. PR title "B122: run every contract script in CI". Read `docs/briefs/_B97-common.md` first (container `oven/bun:1.4.5`, reference recipe, file rules). Source: B115 found `contract:campaigns` failing `campaigns-status-pause` on origin/main; the lead then found that 22 scripts in `package.json` are run by neither `ci.yml` nor `release.yml`:

`sends:batch-crash`, `contract:analytics`, `contract:analytics:reference`, `contract:campaigns`, `contract:campaigns:reference`, `contract:tx`, `contract:tx:reference`, `contract:unsubscribe`, `contract:public`, `contract:public:reference`, `contract:openapi`, `contract:events`, `contract:sequences`, `contract:bounces`, `contract:bounces:reference`, `contract:maintenance`, `contract:maintenance:reference`, `contract:media`, `contract:media:reference`, `contract:import`, `contract:import:reference`, `contract:webhooks`.

Owner directive 2026-11-20: no known gap open. A contract nobody runs is an unknown state.

## Task

1. **Run each one** on current origin/main (after B115 if merged first; say which commit) in the container (production ones as `bun`; reference ones as root with the reference recipe). Record pass/fail per script with its failure line.
2. **Each failure: diagnose and fix at the right place.** A product defect is fixed in the owning module with a test (decision record if behaviour changes, appended at the end of `09-decisions.md`, numbered after the last existing one). A stale contract expectation is corrected to the documented behaviour (cite the decision). An upstream (reference) difference that is deliberate is marked as the contract rules require. `campaigns-status-pause` first. If a failure is large, stop and report it with its diagnosis before fixing; the lead may split it into its own task.
3. **Wire them in**: add every production contract script to the `ci.yml` `check` job and every reference one to the `reference-linux` job, in a sensible order next to their siblings, so the release pre-flight (which runs every `ci.yml` step, B100) covers them. If a script cannot run in CI (needs something CI lacks), say why and add it to the release pre-flight list in `docs/briefs/B100.md` instead, or remove it if it is obsolete (with reason).
4. Make `scripts`-vs-workflow drift impossible to repeat: a small test (in `test/` through files only as data, e.g. a `test/release/workflow-coverage.test.ts` that parses `package.json` and the workflow YAML) asserting every `contract:*`, `messaging:*`, `sends:*`, `templates:*`, `reference:*` and `server:*` script is either run by a workflow step or listed in an explicit exclusion with a reason. (Workflow files and package.json are configuration, not implementation; this does not violate "never read source files".)

## Owns

`.github/workflows/ci.yml` (run steps only; no trigger change, CI stays `workflow_dispatch`), `package.json` scripts (only removals with reason), `test/contract/*`, product modules only for proven defects, the new coverage test, `docs/briefs/B100.md`, decision records as needed.

## Acceptance

All the newly wired scripts pass in the container; the whole `ci.yml` check job and the whole `reference-linux` job in order; one valid `bun run check`.
