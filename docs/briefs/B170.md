Each fix has a test through a public boundary (compiled CLI, HTTP, injected clock) that fails without it; revert with Edit, run, restore, and report.

1. **A backup publishes although a project was deleted while it ran** (major, `snapshot.ts` `createBackup`). The success path compares the registry only against the `instance.db` snapshot taken at the start; the live registry is re-read only on failure, and missing upload files are skipped, so deleting a project during `copyUploads` publishes a whole backup with that project registered and its uploads missing, contrary to "A project created or deleted while the backup runs fails it" (14-projects, operations). Fix: re-read the live registry just before publishing; a whole backup fails with the existing "registered projects changed" error when it differs; `--project <slug>` fails when the slug is gone. Test: delete a project during the upload copy (hook or a slow file), the backup fails and publishes nothing.
2. **`backup` runs on a database ahead of this executable** (major, `openSource`, `openStopped`). Only version 0 is refused, so an older executable backs up a newer-schema database, seals the snapshot (writes into a schema it does not know), skips verification, reports `Uploads: 0` and exits 0 with a backup its own `--verify` refuses. `openStopped` also accepts negative versions. Fix: refuse version ≤ 0 or above the supported version (instance and project each by their own count) before creating any folder or sealing; `openStopped` refuses negative versions. Tests through the compiled CLI: an ahead project db and an ahead instance.db are refused with nothing written; `--release-hold` on version -1 is refused.
3. **`fresh()` returns stale or empty state while a read is in flight** (major, `ses-account.ts`). `read()` sets `lastAttempt` before awaiting, so a concurrent `fresh()` sees a young age and returns at once instead of sharing the read: right after start or a key change, or two capacity requests together, the second answers `not_read` or a stale snapshot. Fix: `fresh()` awaits the in-flight read when there is one. Injected-clock test: two concurrent `fresh()` calls both get the read's snapshot, one `GetAccount`.
4. **The capacity endpoint leaks which campaign IDs exist** (minor, `GET /api/sending/capacity?campaign_id=`). It looks the campaign up (404) before the list-scope check (403), unlike every other campaign endpoint. Fix: `checkCampaign` first. Contract or HTTP test: a list-scoped user gets 403 for both an existing unpermitted ID and a missing one.
5. **`PUT /api/instance/projects/<slug>` ignores `slug`, `hostname` and `primary`** (minor). 14-projects says they cannot be sent; the handler returns 200 and ignores them. Fix: 400 naming the field for any field other than `name` and `extra`. Test.
6. **A preference field label with `$` corrupts the invalid-fields message** (minor, `preferences.tsx`). `replaceAll` with a string interprets `$$`, `$&`; use a function replacer as `t.Ts` does (D123). Test: a label `Budget ($$)` shows as written.
7. **MCP instructions keep a renamed project's old name until restart** (minor, `compose.ts`, `mcp/routes.ts`). The name is passed by value at wiring time. Fix: read the current name when answering `initialize`. Test: rename, then `initialize` names the new name.
