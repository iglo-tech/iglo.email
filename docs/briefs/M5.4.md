## Behavior

1. **Loop.** Every 15 s on the injected clock, and promptly after an event or manual enroll creates a due-now enrollment, claim up to 100 due enrollments in `BEGIN IMMEDIATE` with a 5-minute lease. A loop failure must surface, not leave a healthy-looking server with a dead scheduler.
2. **Decisions.** Implement every row of the decision table in order, reading the current sequence and step definition: paused; archived, blocklisted or deleted subscriber; deleted step; `max_late` (defaults: no limit for transactional, `P2D` for marketing); marketing without permission; condition false with `on_false`; cap with `cap_policy`; send.
   - Conditions use M5.2 `evaluate` outside any write transaction. A condition error (timeout or limit) releases the claim and retries later with a bounded backoff, and is logged for attention. It never sends.
   - **Missing template (required):** a step whose `template_id` is null because its template was deleted ends the enrollment with a clear reason (or records a skipped send with a safe reason; choose and document one), logs one attention message, and never strands the enrollment or sends anything.
3. **Sends.** Render the step's tx template with the 05 Template data (`subscriber`, `trigger`, `sequence`, `step`, plus `unsubscribe_url` for marketing, `manage_url`, `track_link`, `track_view`). Marketing steps get the unsubscribe URL and headers and count toward the cap.
   - Insert the queued send keyed by `(enrollment_id, step_id)` and advance in one short write transaction. The outbox delivers it.
   - A rendering failure is a recorded failed/skipped send with a safe reason, not a crash.
   - Marketing stays at-most-once and never retries automatically.
4. **Crash safety.** If the process dies between inserting the send and advancing, the next run sees the existing send and only advances. Leases expire and are re-claimed. No duplicate sends at any kill point.
5. **Advance.** Move to the next active step with `due_at = now + wait` (deleted steps are skipped without waiting), or mark the enrollment `completed`.
