## Behavior

1. **Policy:** every admin HTML response carries a CSP with no `unsafe-eval` and no `unsafe-inline` for scripts, `object-src 'none'`, `base-uri 'none'` or `'self'`, `frame-ancestors`, and `form-action` and `connect-src` limited to what the admin uses. Alpine must keep working: its standard build needs `unsafe-eval`, so use the CSP build, which has a real expression limit, or another route that keeps the same result. Say which and why. `style-src` may keep what authored content and Oat require; justify any `unsafe-inline` there. Prefer a policy with nonces or hashes only if static hosting of assets would not do. Public pages are outside this task unless they share the shell.
2. **Screens:** every admin screen keeps working under the policy: browser console shows no CSP violation on any screen in normal use. Move inline handlers and scripts into served assets where they block the policy.
3. **Editor containment:** authored HTML shown in the admin stays unable to run script, load remote resources without intent, or reach the admin session. If the rich-text surface can move into a sandboxed frame without losing the upstream result, do so; if a same-document surface with the allow-list is the better choice, record why.
4. **Sanitizer:** a dedicated hostile test corpus goes through the allow-list in a real browser: script forms, event handlers, `javascript:` and `data:` URLs, SVG and MathML namespace confusion, `<base>`, `<meta refresh>`, DOM clobbering, and mutation XSS shapes. Decide DOMPurify or keep the allow-list, as part of the decision record. A runtime dependency needs that record.
5. **Editor items:** head content is named in the removal warning; a foreign-content and undo regression corpus exists; a refused URL shows an inline message.
