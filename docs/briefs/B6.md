## Behavior

1. **`POST /api/tx` with attachments:** synchronous sends that carry caller attachments run under a bounded concurrency limit and a bounded total in-memory attachment size. Over the limit, the request waits briefly or gets a clear 429 or 503, never unbounded memory. Requests without attachments and async sends keep today's behavior and listmonk's results.
2. **`finishAll` regressions:** permanent tests for mixed retry outcomes in one batch, the same-subscriber batch cap, and a COMMIT that fails and rolls back. They go through public boundaries (the SMTP sink, the API) or the module's own exported functions, never source text.
3. **Media in the crash runner:** `runner:crash` includes a campaign with a media attachment, and still shows at-most-once delivery across a crash.
4. **`data-embed` contract:** a compiled-executable contract test covers the `data-embed` media path end to end.
5. **Event retention pacing:** event retention joins B2's paced loop pattern (bounded batch, pause between passes), so a backlog cannot delay sends. Measure the send lateness during an event purge before and after.
6. **Send body expiry:** decide whether bodies expire 30 days from `created_at` or from finishing, make `04-sending.md` and the code agree, and record the choice in the decision log if it changes D70.

Out of scope: PDF viewer support, which needs real devices; leave that line in the backlog.
