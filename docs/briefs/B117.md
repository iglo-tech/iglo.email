## B117d: send journal scope and names kept on delete

Branch `task/B117d-send-journal`, PR title "B117d: send journal list scope and names kept on delete". Decision D139 (lead, 2026-11-23), amending D53 and D135 in its own record. Migration: the next free number after main's highest (0030 once B130 merges; renumber at merge if another lands first).

1. Privacy (B127 r1): a list-scoped user with `sends:get` reads the whole send journal, including addresses, subjects and sequence names of subscribers outside its lists. That covers `/api/sends?subscriber_id=…`, `?list_id=…`, `/api/sends/:id` and the `/admin/sends` page. Limit `sends:get` reads to subscribers in the caller's lists when the caller is list-scoped, as subscriber reads already are. Test through HTTP and the admin page with a scoped role and an unscoped one, including a by-id read of an out-of-scope send (answer as not found, not 403, if that is how subscriber reads answer).
2. Deleting a template, sequence or step drops its name from the send log (`ON DELETE SET NULL`). Write the names onto each send when it is queued, so a delete keeps them, as a wipe already does. Add before and after measurements of the write path under `docs/perf/` (claim, insert and settle at a million sends, three repetitions, with the production statements).

Owns: `src/sends/*`, the send-log page in `src/admin/*`, the queue writes that create sends (`src/campaigns`, `src/sequences`, `src/tx` through the sends module's functions only), migration, tests, D139, `04-sending.md`, OpenAPI. Acceptance: `contract:sends`, `contract:roles`, `contract:roles:reference`, `contract:messaging`, `contract:tx`, `contract:normal`, `E2E_WORKERS=2 bun run e2e` (the send-log page).
