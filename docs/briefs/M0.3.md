## Required behavior

### Context and clock

- Modules receive explicit typed dependencies; no process-global mutable state, service locator, generic dependency registry, barrel or re-export layer. Keep per-request state separate from per-application dependencies.
- Define the concrete context for dependencies that exist now: bootstrap configuration, injected clock, error logger and translation instance. Do not invent empty database/settings/mailer services or use `any`/`unknown` dependency slots. Their real owning modules are implemented later; document this staged construction in the architecture note so types and design agree.
- The clock contract is `now(): Date` and `sleep(milliseconds: number, signal?: AbortSignal): Promise<void>`. The real implementation uses real time only inside its owning module. Sleep must support cancellation, including an already-aborted signal. Test time by advancing an injected test clock rather than sleeping.
- Default application logging emits only errors/attention items. Unexpected request exceptions use the injected logger and return a safe 500 response; never put stack traces, internal exception details or initial-admin inputs into an HTTP response.

### Router, middleware and responses

- Use `Bun.serve`, native `Request`/`Response` and a small explicit router. Support the methods and named `:param` segments later modules need, exact static paths, query access, deterministic route precedence, and a middleware chain supporting both short-circuiting and async errors. No external HTTP framework or speculative route features.
- Expose handlers/context and middleware from the modules that own them. Registration must be explicit. Test static routes versus parameter routes, method mismatch, middleware order/short-circuit, async exception handling and isolation between concurrent requests/app instances through HTTP.
- Preserve the existing compiled executable's `GET /health`: HTTP 200, `application/json`, and `{"data":true}` plus newline. Preserve the existing bootstrap options, silent successful startup, standalone execution and SIGTERM/SIGINT cleanup.
- Implement reusable `{ "data": ... }` success and `{ "message": "..." }` error helpers with upstream-compatible status, content type and body serialization. API fallback must use the pinned upstream API 404 behavior, not M0.1's plain-text placeholder. Public HTML 404 pages wait for the JSX/public-page tasks.
- Handle explicit HTTP errors and unexpected errors centrally. A middleware-created error must pass through the same serializer as a handler error. Match upstream behavior for HEAD/method errors as verified, rather than assuming Bun and Echo treat them identically.
- Add small ID/input validation helpers needed for the boundary cases. Do not implement domain list/subscriber validation or a general schema-validation framework. Do not add new dependencies.
- No production test/probe routes, unauthenticated substitute for upstream protected routes, or placeholder API controllers. `/api/health` and `/api/lang/:lang` remain protected API endpoints for later auth work; do not make them public to simplify this task.

### Translation

- Keep upstream's recognizable `T`, `Ts` and `Tc` behavior: English fallback, missing-key fallback, parameter substitution and singular/plural selection. Translation data/instances must not be mutated globally or shared as mutable request state.
- Include the English data in the compiled executable; it must work from an unrelated temporary directory with an empty `PATH`. Carry all upstream language packs and document their origin. If other packs are exposed by the internal translation API, embed them as well; no hidden dependency on a source checkout at runtime.
- Do not copy unbounded recursive substitution: detect cycles or bound resolution so cyclic/missing references cannot hang a request. Document a deterministic fallback for those cases. Exercise substitution, fallback, pluralization and a cyclic synthetic map through the test-only HTTP fixture.

### Reference-first evidence and tests

- Before porting helpers, write and run focused HTTP contract cases against the real upstream runner. Commit the initial cases and record that reference run in the PR before the implementation. Do not claim M0.5's general contract/normalization framework exists.
- Required reference cases include `GET /health`; an unknown `/api/...` route (404); an authenticated invalid-ID route such as `GET /api/lists/not-an-id` (400); and an authenticated invalid-field request that fails before any write, such as `POST /api/lists` with an empty name (400). Obtain API credentials only from the runner's exported synthetic values. Assert actual status, content type and JSON body; no application-table assertions or source-text tests.
- Confirm exact upstream results first. For helpers without a production endpoint yet, register representative test-only routes on a test fixture server using the real router/middleware/error/i18n modules, and drive that fixture over HTTP. A test may exercise the public server-building boundary; it must not assert private helpers, implementation internals or source text. This fixture is not a port of list CRUD and is never registered by the compiled application.
- Add fixtures for generic validation errors, response envelopes, safe 500 handling, middleware propagation and the injected clock. Verify deterministic time through observable responses/completions while advancing a fake clock, not waiting for real domain time. Bounded process-readiness checks and request/test timeouts are allowed.
- Keep this comparison focused on flat error/health cases: no normalization engine, deliberate-difference registry or general harness until M0.5. Ordinary `bun test` and `bun run check` must work without Docker/downloads. The explicit reference check runs in the Linux reference CI job and must not silently skip.
