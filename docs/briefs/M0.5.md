## Runner and transport

- Explicit immutable per-case definitions and per-run target/context state; no process-global mutable bindings, global service locator, plugin discovery, generic framework or new dependency.
- The same cases and assertions select documented reference/normal expectations. A target/profile must be explicit, never detected from response success. Restrict owned test targets to loopback, reject malformed modes/profiles/URLs/credentials before requests, and never contact production or external HTTP services.
- Accept a base URL for the reusable runner/CLI. Reference defaults to M0.2 REFERENCE_URL and synthetic API credentials. Normal orchestration supplies an owned local origin and fixture context. No secrets in URL userinfo or diagnostics.
- Construct Basic and listmonk token Authorization headers from injected synthetic credentials, only for cases requiring them. Confirm actual upstream authenticated GET /api/health and bad-token results before implementing the fixture subset; do not infer auth errors from memory.
- Bound requests, readiness and child lifetimes. Propagate nonzero/failing test status, cancellation and shutdown, then clean up only the child processes and directories this invocation created. Reuse the existing safe process-ownership helper where appropriate; no saved stale PIDs or broad process kills.
- Normal production execution uses the compiled executable from an unrelated temporary directory with an empty PATH and fresh dataDir. Do not depend on a source checkout or install a production probe route.
- Exact-target URI cases must bypass client URL normalization. Preserve dot-segment/backslash/invalid-percent behavior already observed in M0.3, and close or independently own transport connections.
- Fail on unexpected status, content type, body/field/type or unlisted differences. Match established wire envelopes/newlines where those are the case's contract. Missing/extra fields and invalid JSON must not be hidden by normalization.
- Output a concise deterministic report with case IDs, mode, target/profile, pass/failure and declared deliberate differences. Pending production groups must be visibly separate from passes. Error output is actionable but redacts credentials/Authorization, including echoed secrets in synthetic response/argument failures. Do not log environment dumps.

## Normalization and deliberate differences

- Normalize only explicit volatile field paths declared by a case. Never recursively erase every id/date-like key, strip arbitrary fields or replace substrings in unrelated text.
- Validate field presence, type and format before replacing generated IDs/timestamps. Unsafe numeric IDs must fail rather than silently round. Preserve identity/equality/reference relationships within a run using explicit typed bindings; different entities must not collapse onto one placeholder accidentally.
- Timestamp rules must reject malformed values and preserve any equality/order constraint a case actually asserts. Normalize only the variability needed by that case; do not hide meaningful time or ordering changes.
- Exercise normalization through HTTP/CLI fixture targets with independently generated IDs and timestamps, plus negative cases for wrong type, missing fields, invalid/unsafe values, inconsistent references and changes to ordinary payload fields. These synthetic harness probes are clearly labelled and never claimed as upstream domain ports.
- Carry D17 and D18 as explicit deliberate-difference metadata linked to the API-policy/decision reason. Each marked case asserts the real reference result and the accepted normal-helper result. Unknown IDs, orphaned/duplicate markers and unexpected results fail; a marker never grants blanket permission to ignore a mismatch.
- D17 remains upstream positive route-ID overflow 500 versus the shared validator's 400. D18 covers Bun's pre-handler dot-segment removal and literal-backslash rewrite. Reference/domain paths versus representative helper-fixture paths must be explicit; no path adaptation is applied to production to make unported endpoints seem implemented.
- Retain relevant 28 M0.3 reference cases when moving the flat script into the shared corpus. Production core cases run only on actual production boundaries; protected/domain validation examples run reference plus labelled helper fixtures until their owning M1 tasks port them.
- The temporary public HTML 404 gap is still deferred to M0.6/public pages. It is not a permanent D17/D18-style API difference and must not be normalized away or advertised as implemented.

## Tests and commands

Tests use public HTTP/process boundaries. No source-text assertions, private-helper tests, production data or real SMTP/webhooks. The contract harness itself is verified by invoking its public runner/CLI against isolated loopback test targets, checking outcomes/reports and process cleanup.

Cover reference/normal target selection, credentials actually sent, failure propagation, clear unsupported-profile refusal, malformed target inputs, secret redaction, strict comparisons, scoped normalization and difference metadata, raw request targets, compiled standalone production coverage and cleanup after failure/signal. Domain time tests use an injected clock; request/readiness/process timeouts are bounded infrastructure checks, not sleeps used to simulate features.

Required commands:

    bun install --frozen-lockfile
    bun test test/contract
    bun run contract:normal
    bun run contract:fixture
    bun run contract:reference
    bun run server:reference
    bun run reference:smoke
    bun run check

- contract:normal starts/stops an owned compiled production process and executes the actually ported core profile, with explicit production coverage reporting.
- contract:fixture starts/stops the labelled normal fixture, executes the protected-read/shared-helper profile (including D17/D18) and reports its staged scope.
- contract:reference uses the existing M0.2 runner to execute the corresponding corpus against real pinned upstream, including the new protected read. Reference-first run and commit are recorded in the PR.
- server:reference remains working as a compatibility entry point to the consolidated corpus. Do not start a second disposable service stack from inside an existing reference:run child.
- Ordinary bun test/check and normal/fixture profiles remain Docker/download-free. Reference CI remains explicit and cannot silently skip. No CI benchmark threshold.

Measurements: none required; this task changes test infrastructure only, not application sending, scheduling or storage behavior. Retain M0.4 measurements without rerunning or weakening their disk-backed requirement.
