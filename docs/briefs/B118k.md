# B118k: `contract:settings:reference` writes nothing upstream cannot reload

Branch `task/B118k-settings-reference`. PR title "B118k: settings reference run writes only reloadable values". Read [`_B97-common.md`](_B97-common.md) first. Test harness only; no product change. Containers start with `b118k-`.

The release gate rule in [`chief-of-staff.md`](../chief-of-staff.md) applies: the item clears only by a fixed root cause or by removing the nondeterministic mechanism. A retry or a wider wait never clears it.

## What is known (captured runs on #211, 2026-11-25)

- `bun run contract:settings:reference` failed in 1 of 28 runs (run 8 of the first 10).
- The listmonk log shows the reloaded upstream process exiting at boot because an enabled SMTP item's `idle_timeout` or `wait_timeout` did not decode (upstream `cmd/init.go:747`).
- No kept log shows which write stored that value. `test/contract/settings.ts` already avoids some writes against the reference (comments at about `:102` and `:282`), so either one write still stores an SMTP item with an empty or unreadable duration, or a reload reads the settings while a later write is half applied.

## Work

1. **Find the write.** Make the reference run fail by name at the first write that leaves upstream's stored settings unreloadable: after each accepted settings write against the reference, read the stored SMTP items from upstream's database (through the reference harness, not from the app's HTTP output) and check that every enabled item's `idle_timeout` and `wait_timeout` parse as Go durations. Name the case label in the failure. Read upstream's settings write and reload code from the pinned checkout to see which fields it stores as `""`.
2. **Fix the cause.** Either send that write complete, skip it against the reference with a comment that says why (as `:282` does), or wait for upstream's reload to finish before the next write, using a state upstream exposes. Say in the PR which one it was and why.
3. **Show it.** A mutant that reintroduces the bad write fails by its case label. Then 10 runs of `contract:settings:reference` with load recorded, all passing, and the output searched for `exit`, `fatal` and `invalid duration`.
