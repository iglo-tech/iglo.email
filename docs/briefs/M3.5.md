## Behavior

1. **API:** `GET /api/media`, `GET /api/media/:id`, `POST /api/media`, `DELETE /api/media/:id`, with upstream's permissions (`media:get`, `media:manage`), multipart field names, query search, paging, envelopes and `url` and `thumb_url` values. Extension checks follow `upload.extensions`, including `*`.
2. **Storage:** the filesystem provider under the data directory's `uploads`, honoring `upload.filesystem.upload_path` and `upload.filesystem.upload_uri`. Filenames are made safe and unique as upstream does. A path can never leave the upload directory, through the name, an encoded separator or a symlink. Write to a temporary file and rename, and bound upload size with a stated limit, so a failed upload leaves nothing behind. Keep the database and the file consistent: say what happens when each side fails and on a crash between them. No file I/O inside a database transaction.
3. **Serving:** files are served at `upload_uri` with correct types and caching, without authentication as upstream. `svg` is in the default extensions, so an uploaded SVG or HTML file must not run script on the application's origin: use a restrictive CSP, `nosniff` and attachment disposition where needed, and list any difference in 07. Range requests only if upstream's are used by a real client.
4. **Thumbnails:** 01 puts generated thumbnails after v1, and no image library is in the design. `thumb` stores what the API needs, and `thumb_url` points at something that renders in the admin UI. List the difference in 07. Add no runtime dependency.
5. **Other providers:** S3 is out of scope. `upload.provider: s3` is refused safely when used, and stored S3 settings keep round-tripping. List this in 07.
6. **Deletion and references:** deleting media removes its file and follows `campaign_media`'s `ON DELETE SET NULL` as upstream. Campaign reads keep their shape.
7. **Attachments:** if upstream attaches a campaign's media to its messages and the runner here does not, add it within the existing send path, with sizes bounded and at-most-once sending unchanged. If that is more than a narrow seam, stop and report it instead of expanding scope.
