## Reference-first behavior and contracts

Write and commit common list specifications, run them against pinned upstream, then implement production. Use invocation-owned synthetic names/UUIDs/users/roles, generate API tokens through public APIs and clean only owned objects in finally blocks. Never bulk-delete an unbounded reference dataset or touch another invocation's records. Prefix every query-delete fixture with a unique name/tag; all=true safety tests use only their own disposable target or a narrowly scoped permitted role.

Endpoints: GET/POST/DELETE /api/lists; GET/PUT/DELETE /api/lists/:id. There is no standalone tags endpoint in the pinned list registrations; tag normalization/filtering lives on these resources. /api/lists/analytics/:type stays unported; do not let the generic :id path accidentally claim analytics behavior.

Preserve exact list response keys/nulls/timestamps, default private/single/active on create, active collection filter defaults, enum validation, names/description behavior, UUID generation, normalized tag arrays and all-tag containment. Cover missing/null/[] tag payloads separately; D32's user-role rule does not change list tag replacement. Query whitespace, percent/underscore and stemming use precise D33 markers; read/query-delete share the same predicate. Explicit description empty clears under D33, while omission/null keeps the stored text. Other supplied-empty/default behavior stays as the pinned source actually implements it.

Test full and minimal list shapes, including empty-minimal [] versus PageResults, counts/null projections, filter validation, pagination (default/max/all/invalid/out-of-range), accepted and invalid sorts, ties without accidentally asserting unspecified order, repeated tag/id parameters, UTF-8 byte lengths, malformed/empty JSON and content types, numeric path/query-ID syntax and overflow under D17/D18. Unknown list GET is upstream 400, not a generic invented 404. Inspect actual update/delete affected-row behavior. Add every deliberate difference precisely to the common corpus and API policy; D33 is not a blanket search/body/error exception.

Authentication/permissions: unauthenticated requests fail; Super Admin and blanket lists:get_all/lists:manage_all semantics match source; list:get and list:manage remain distinct. A lower-permission token and a retained cookie session see only currently readable lists, including minimal/count/total output. Collection enumeration does not leak names, tags, descriptions or counts of inaccessible lists. Per-list write permission does not grant global creation. Bulk ID deletion is all-or-nothing for permission failures; query deletion filters current manage scope and all supplied filters. Role/list grants changed during an asynchronous body read must be revalidated before the write transaction; do not trust a stale captured identity or read-only scope. No network in transactions. Test positive and denied routes after grant changes/revocation for both token/session transports, plus cookie CSRF/origin denials.

Counts must match the membership status aggregate through the subscriber owner. Ordinary compiled production with no subscriber endpoint verifies correct empty counts; positive membership counts use a clearly labelled fixture with confirmed/unconfirmed/unsubscribed memberships and global subscriber status controls. Counts and subscriber_count ordering must be applied before pagination, not fabricated after slicing. Do not seed a production SQLite file to claim real subscriber acceptance. Minimal projection matches source and should not do unnecessary count work. Preserve automatic non-reusing IDs and injected timestamps.

List deletion must remove role-child grants/memberships as the schema declares, preserve unrelated lists/users/roles, keep a campaign's stored list name with a nullable link, and never delete subscribers or users as an accidental cascade. A rename preserves the campaign snapshot contract through its owner. Positive cross-domain lifecycle cases remain labelled fixtures until the future APIs exist; assertions go through HTTP/fixture projections, never private SQL. Refresh current role projections on the next real request. No broad new cleanup service.

Promote the D20 list validation helpers to compiled production now that routes exist, including overflow/transport/path markers without weakening exact-target behavior. Keep the shared auth and roles corpora running; use the real lists API to strengthen previously fixture-only positive role list grants where appropriate. Preserve genuine helper-only probes and distinguish their coverage in reports.

If pinned behavior is demonstrably poor, capture the exact reference outcome and the smallest useful correction in the PR for lead decision.
