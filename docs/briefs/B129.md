## Items

1. **Owner decision (not open): remove the public-page footer "Powered by iglo.email. Based on listmonk."** (`src/public/layout.tsx`) and any similar credit in system mails (opt-in, export, notifications; check every template, including built-in and default ones). Removed, not hidden behind a setting. **Licence:** AGPL-3.0 §13 asks a modified version to offer its source to users interacting over a network; the footer was the public pages' offer. Keep the offer where it does not burden the operator's brand: a "Source code" link in the admin UI (footer or About) to the repository, and a sentence in `docs/operations.md` that operators who modify iglo.email must keep offering their source (§13). Record the owner decision and this in D127.
2. **Brand settings:** `appearance.brand.accent` (a CSS colour, validated: hex `#rgb`/`#rrggbb` only, so nothing can inject CSS) and `appearance.brand.font` (one of a fixed list: system sans, system serif, system mono, plus a validated Google Fonts family name that is loaded with a `<link>` from fonts.googleapis.com only when set; document the privacy implication: subscribers' browsers then contact Google). Applied to public pages (buttons, links, the top border) through CSS custom properties in the shared shell, and to subscriber-facing system mails (opt-in, the B126 export mail) as inline styles. Defaults reproduce today's look exactly.
3. **Header:** a setting `appearance.brand.header` = `logo` | `name` | `logo_and_name` (default `logo` if a logo is set, else `name`): shows `app.site_name` as text next to or instead of the logo. The logo/name links to `app.site_url` (D123) when set, else is not a link (no empty `href`; B126 may already have fixed the href, keep it consistent).
4. **Logo and favicon by upload:** the admin settings page offers "Upload" for `app.logo_url` and `app.favicon_url`, storing the file in media (existing media module and permissions, `media:manage`) and setting the URL to the media URL; remove/replace works. API callers keep setting the URLs directly (no new API needed if the admin uses the existing media upload and settings PUT).
