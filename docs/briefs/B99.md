# B99: MCP is the agent path for content; make it discoverable

Branch `task/B99-agent-path`. PR title "B99: agent guidance, MCP instructions and client config". Decision record: D108 (lead, 2026-11-17). Runs after B97 merged (its tools are named here). Read `docs/briefs/_B97-common.md` first.

## Problem (adopter report, item 7, and the owner's question)

An integrating agent worked only through REST and believed the MCP had about ten tools (campaigns, templates, lists, `list_media`, sequence get/list/`update_sequence_step`, `template_reference`, `preview_template`, `send_campaign_test`). Since D98 (v1.1.0) it exposes every operation except a short exclusion list: `upload_media`, `create_sequence`, `update_sequence`, `get_subscriber_events`, `get_sends`, `get_bounces` and, after B97, step preview and test send. The first sentence of the MCP section in `docs/operations.md` still describes the D91 scope, the README says only "an MCP endpoint at `/api/mcp`", and nothing tells an agent when to use which.

## D108: the split, and how agents find it

- **Split.** REST is for the application: code that runs in the app or its deploy (events, transactional sends, subscriber sync, a provisioning script checked into the app's repository) uses the HTTP API with an API user; it is versioned, scriptable and documented in `/api/openapi.json`. The MCP is for an agent working on the instance for a person: authoring and testing content (templates, sequence steps, campaigns), uploading media, inspecting subscribers, events, sends and bounces, and changing settings. Both run the same operations with the same permissions (D98); neither has a capability the other lacks. Agents default to the MCP for those tasks when it is connected, and fall back to REST otherwise.
- **Server instructions.** The MCP `initialize` result carries `instructions` (a field of the MCP spec; check `src/mcp/routes.ts` and the protocol versions it negotiates) of at most ~1,500 characters: what the server is, read `template_reference` before writing Liquid, the authoring loop (`get_sequence` → edit with `update_sequence_step` or `update_template` → `preview_sequence_step` with a real `subscriber_id` or `sample` → `test_sequence_step` to the person's inbox → `get_sends`/`get_bounces`), that tool errors carry the API's message, and that bulk/irreversible and user/role operations are not tools. Use the tool names that actually exist after B97 (check `tools/list`).
- **Tool descriptions.** Every hand-written tool that takes Liquid (`update_template`, `create_template` if hand-written, `update_campaign`, `create_campaign`, `update_sequence_step`, `preview_template`, and the generated sequence create/update tools through their OpenAPI descriptions) says in one sentence to read `template_reference` first.
- **README.** A section "If you are an AI agent" near the top: the split above in four lines, a ready-to-paste `.mcp.json` (`{"mcpServers": {"iglo-email": {"type": "http", "url": "https://<root>/api/mcp", "headers": {"Authorization": "token <api-user>:<token>"}}}}`, verify the shape against the current Claude Code docs for HTTP servers) and the `claude mcp add` line, the role to create (link to operations.md), and links to `/api/openapi.json` and the operations MCP section.
- **operations.md MCP section** rewritten to the D98 + B97 scope: first paragraph states the split; the "Sample agent role" stays the reference; add the authoring loop.
- Considered: a separate CLI or SDK for agents (a second way to do the same job, D89); bundling a Claude Code skill or plugin in the repo (client-specific, and the server instructions reach every MCP client); dropping REST guidance for agents (apps must not depend on an agent's MCP session).
