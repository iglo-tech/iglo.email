# B35: Amazon SES is the only sending and bounce provider (D89)

Common rules: [_state-common.md](_state-common.md). Branch `task/B35-ses-only`. Lines from main at d769746.

## Source

Owner, 2026-11-07 ([D89](../design/09-decisions.md#d89-narrow-complete-product-scope-owner-2026-11-07)): for now only AWS SES for sending, bounces etc.; one way to do each thing. Sending through SES is already ordinary SMTP. Bounces through SES/SNS shipped in B9 (`POST /webhooks/service/ses`). The Mailgun webhook (M3.4, D63) is a second way to do the same job, and the admin UI also offers bounce providers that do nothing.

## Lead findings (verify, then act)

- **Mailgun is iglo-native, not upstream.** `src/bounces/mailgun.ts`, the route `POST /webhooks/bounce/mailgun` (`src/bounces/routes.ts:342-398`, import at :7, deps type at :42), wiring at `src/main.ts:498`, setting `bounce.mailgun` (`src/settings/defaults.ts:156-160`, `src/settings/validate.ts:343-346` and :425), admin fieldset `src/admin/views/settings.tsx:973-990` and the provider label at :19, `assets/admin/js/views/settings.js`, i18n keys `settings.bounces.enableMailgun` / `mailgunKey` in `i18n/en.json`, OpenAPI (`src/openapi/operations.ts`, `src/openapi/schemas.ts`), tests (`test/bounces/bounces.test.ts`, `test/bounces/measure.ts`, `test/contract/bounces.ts:11, 623, 648-690…`, `test/contract/openapi.ts`, `test/tx/fixture.ts`, `test/e2e/specs/settings.e2e.js`). Check whether upstream listmonk v7.0.0-beta.1 has a `bounce.mailgun` setting key or route (local checkout at the pinned commit, see `test/reference/README.md`; never from memory). If upstream has none, remove all of it.
- **`bounce_receipts` stays.** SES uses it too (`src/bounces/routes.ts:329-332`, `sns:<MessageId>` keys, `src/bounces/store.ts:243-247`). Do NOT drop the table or migration 0012. Update the migration's comment only if comments in applied migrations may change (check `migrations/README.md`; if they must not change, leave it). Remove the Mailgun `token:`/`event:` key handling. Existing rows expire on their own.
- **Stored data.** A database that already has `bounce.mailgun` stored (enabled or with a key) must still start, and `GET`/`PUT /api/settings` must still work. If settings are stored per key, add a forward migration (next number after `0018`) that deletes the stored `bounce.mailgun` row. It holds a secret key, so do not leave it orphaned. Existing bounce rows with `source = 'mailgun'` stay as history: they must still list, export and wipe correctly.
- **Inert providers in the admin UI.** `src/admin/views/settings.tsx:19-24, 992-1011` show switches for Sendgrid, Postmark, Forward Email, Lettermint, Azure and POP bounce mailboxes. Only SES is handled (`routes.ts` `service` handler; the others answer "Unknown service"), and nothing reads `bounce.mailboxes`. Lead decision: the admin Bounces settings show only the SES section (plus the general bounce actions/thresholds). Remove the inert provider switches, the mailbox editor, their i18n keys and the matching keywords (`settings.tsx:654, 992`). The settings API keeps the upstream keys (`bounce.sendgrid_enabled`, `bounce.postmark`, `bounce.forwardemail`, `bounce.lettermint`, `bounce.mailboxes`, …) for listmonk API parity (D57), stored but with no effect. List them as a deliberate difference in `docs/design/07-api-and-ui.md` ("accepted and stored for listmonk API compatibility; no effect; SES is the only provider, D89"). Remove any iglo-native key among them that upstream does not have.
- **Docs.** `docs/operations.md:166` and the SES section from :305: SES over SMTP and SNS bounces/complaints become the one documented setup. Add how to set a SES configuration set through SMTP headers (`X-SES-CONFIGURATION-SET` in the SMTP server's custom headers, if the SMTP settings support per-server headers; check). Remove Mailgun everywhere in `docs/` except history: `docs/perf/`, old `docs/briefs/` and decision records. Add a short note to D63 that the Mailgun parts are superseded by D89/B35 and receipts now serve SNS only. Update `docs/design/04-sending.md`, `01-scope.md`, `07-api-and-ui.md`, `08-port-plan.md` and `11-work-plan.md` where they name Mailgun as current.
