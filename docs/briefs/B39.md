# B39: MCP completeness (D89, D91)

Common rules: [_state-common.md](_state-common.md). Branch `task/B39-mcp-complete`. Lines from main at 90e8474.

## Source

D89 makes MCP the way to edit templates and campaign content instead of a visual editor, and D91 records the endpoint (`src/mcp/routes.ts`, `src/mcp/tools.ts`, tests in `test/mcp/mcp.test.ts`). The B36 audit (#88) found that an agent still cannot do a whole editing job through MCP:
- it cannot create a campaign;
- it cannot find list IDs to target one;
- it cannot find media to attach;
- it cannot read or edit sequence step content, which is message content just as campaign bodies are.

## Tools to add

Same design as the existing 14 tools (D91). Each tool calls existing API endpoints in-process through `router.handle(app, request, peer)` with the caller's credentials (authorization, cookie, CSRF, origin; see `callEndpoint`/`invoke` in `tools.ts`). The endpoint's own permission check applies. A partial edit reads the stored object first and merges, so it never clears fields (the `update_campaign` pattern). Caller-supplied values go to the endpoint unchanged, so the endpoint validates them; filter only values read back from storage (see `extractPositiveIds` and the B34 review history on #86).

1. `create_campaign` → `POST /api/campaigns` (`src/campaigns/routes.ts:858`). The schema has the fields a new campaign needs: name, subject, lists, from_email, content_type, body, template_id, optional altbody, headers, attribs, tags, send_at, messenger (email only). Declare required fields as the endpoint requires them. Return the created campaign.
2. `list_lists` → `GET /api/lists` (`src/lists/routes.ts:168`), with optional `query`, `page`, `per_page`. Returns id, name, type, optin and subscriber count, as the endpoint gives them.
3. `list_media` → `GET /api/media` (`src/media/routes.ts:303`), with optional `query`, `page`, `per_page`. Returns id, filename and url, so an agent can reference images in a body or attach media.
4. `list_sequences` → `GET /api/sequences`, and `get_sequence` → `GET /api/sequences/:id` (`src/sequences/routes.ts:141-170`).
5. `update_sequence_step` (lead decision: step content is message content under D89). Edit one step's content fields: subject, body, content_type, template_id, plus the alt body or headers if the step has them. It reads the sequence with GET, replaces only that step's given fields, and PUTs the whole sequence (`PUT /api/sequences/:id`). Identify the step by its id if steps have ids, otherwise by position. First read how PUT treats steps of an active sequence (`src/sequences/routes.ts`, `docs/design/05-sequences.md`). If editing steps of an active sequence is refused or has rules (for example, enrollments already past a step), the tool returns the endpoint's error unchanged. Do not add a new endpoint.

Update `tools/list` and its schemas (`additionalProperties: false`, complete for a client that sends only declared fields). Update D91's tool list and count in `docs/design/09-decisions.md`, the MCP section of `docs/operations.md`, `docs/design/07-api-and-ui.md` if it lists the tools, and the OpenAPI note if one exists.

## Tests (test-first, through the official MCP client SDK against the compiled server, as `test/mcp/mcp.test.ts` does)

1. `tools/list` returns all tools, with valid schemas.
2. `list_lists` and `list_media` return the items created through the HTTP API, and `query` filters them.
3. `create_campaign` with lists from `list_lists` creates a draft that is visible via `GET /api/campaigns/:id`. `update_campaign`, then `preview_campaign` and `send_campaign_test` on it, deliver to the sink. Invalid input, such as a list id that is not an integer, returns `isError` with the API's message, and nothing is created.
4. `get_sequence` and `list_sequences` match the HTTP API. `update_sequence_step` changing one step's subject leaves every other field and every other step unchanged (check via GET). An invalid body (bad Liquid) returns `isError`, and the sequence is unchanged.
5. Permissions: a user without `campaigns:manage` gets `isError` with 403 from `create_campaign`; a user without `sequences:get` (or the right name) gets it from `get_sequence`; nothing is written.
6. Cookie-session callers (login, CSRF token) can call `create_campaign`, as test 8 already does for writes.
