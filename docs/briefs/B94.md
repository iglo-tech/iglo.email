## Changes

1. **Code editors can store `undefined` (suspected defect, prove first).** Every `<code-editor>` binding reads `$event.target.value`: `src/admin/views/sequence.tsx:171` (condition, via `onCondition`), `:193` (step aggregates), `:430` (where), `src/admin/views/template.tsx:61` (template body), `src/admin/views/campaign.tsx:275` (campaign body). `<code-editor>` (`assets/admin/js/code-editor.js:24`, `value` getter at :108) dispatches its own bubbling `input` after each document change (:62), but CodeMirror's inner contenteditable also emits native `input` events that bubble through the custom element; for those `$event.target` is the inner div, its `value` is `undefined`, and the bound field becomes `undefined`. The B93 worker saw it: Playwright `fill` with multi-line JSON on the aggregates editor made save throw `Cannot read properties of undefined (reading 'trim')` (`assets/admin/js/views/sequences.js:88`, `parsed()`); keyboard typing worked.
   - **Test first** (Playwright, `test/e2e/specs/`): for the aggregates editor, the condition editor, the template body and the campaign body, enter multi-line content the way a user pastes it (Playwright `fill` on the editor's content, and a clipboard paste via `page.evaluate` + `ControlOrMeta+V` if the stack allows clipboard permissions), save, reload: the stored value equals what was entered and no page error is raised. Record which cases fail on main before the fix.
   - **Fix** in the views: read the element's own value (`$el.value`) instead of `$event.target.value`, or ignore events whose target is not the element, consistently for all five bindings. Do not change `code-editor.js` behaviour other users rely on unless the views cannot be fixed alone; say why if you do. `richtext.tsx:409` is a different element: check it the same way, fix only if a test shows the same failure.
   - If no case fails on main, report that with the evidence, keep the tests, and make no product change.
