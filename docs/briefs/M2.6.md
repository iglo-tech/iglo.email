# M2.6: Outbound webhooks

Goal: signed, retried webhooks for subscriber state and failed sends: the configuration API, durable deliveries queued atomically with the state change, a delivery loop with retries for 24 hours, and the `subscriber.unsubscribed` hook the worked example expects.

## Behavior

1. **API** per 07: `GET/POST /api/webhooks`, `PUT/DELETE /api/webhooks/:id`, `GET /api/webhooks/:id/deliveries`, requiring `webhooks:manage` and the usual auth and CSRF. Validate URLs (http/https, bounded length) and the event list. The secret is generated or supplied at create, shown once, and never returned afterwards. Bounded paging.
2. **Events:** `subscriber.unsubscribed`, `subscriber.blocklisted`, `subscriber.deleted`, `send.failed` as 04 describes. `bounce.recorded` is defined but only produced from M3.4, so leave the owner function ready for it. Each delivery row is inserted in the same transaction as the state change, so a rollback queues nothing and a commit can't lose one. One row per enabled webhook subscribed to the event. Bound fan-out.
3. **Payload and signature:** the body is exactly as 04 specifies, with the delivery UUID as `id`. `X-Iglo-Email-Signature: t=<unix>,v1=<hex HMAC-SHA256 of "t.body">` over the exact bytes sent, and the same `id` across retries. Payload snapshots are stored at queue time. **Privacy:** a wipe or subscriber delete must also clear personal data from pending and stored deliveries for that subscriber (D25), while still delivering `subscriber.deleted` itself with what 04 allows. Say exactly what you chose.
4. **Delivery loop:** lease-based claims with an injected clock, HTTP outside transactions, bounded concurrency, a request timeout and a bounded response read. Don't follow redirects. Success is any 2xx. Failures retry with backoff for up to 24 hours from first queueing, then become `failed` with a safe `last_error`. At-least-once is allowed (receivers dedupe by `id`); say where duplicates can occur. A failing receiver must not starve others or the rest of the app. Restart resumes from durable state. Log repeated failure for attention without logging secrets.
5. **Outbound safety:** URLs are admin-configured, so private addresses are allowed by default for self-hosted receivers, but a setting `webhooks.block_private_addresses` (default off) refuses loopback, link-local and private ranges at delivery time, after DNS resolution. Never send the secret itself.
