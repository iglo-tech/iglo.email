# B27: intermittent watch lines and the tx harness

Common rules: [_state-common.md](_state-common.md). Branch `task/B27-intermittent`. Lines cited from main at cc7f009.

## Source

The hardening backlog lines in `docs/status.md` that only watch for a repeat: `route-auth` held SMTP body, `users.e2e.js` reload races, `import.test.ts` SIGTERM restart, the `templates-campaigns` connection reset (B12), host load timeouts in the backup tests (B15), and the `maintenance.e2e.js:207` / `campaign-safety.e2e.js:281` stall (B13). Plus the B26 note that `test/tx/measure.ts` builds every request body up front.

## Owns

- the named test files and their fixtures/helpers, `test/tx/measure.ts`, `test/perf/*` only if needed
- `docs/perf/B27-intermittent.md` (new), `docs/status.md` backlog lines

## What to do

1. **One bounded attempt per watch line.** For each named case, run it a fixed number of times. The file alone, 10 runs; e2e specs with `E2E_WORKERS=1`, 5 runs. Do it once under load like the original failure (`stress`-style CPU burners, as B13 did) and once without. Record host load per batch. Hold the verify lock for each batch; never sleep-poll for a quiet host.
2. **On a failure:** the diagnostics added by B8/B13 should name the cause. Fix it (test-only fixes are fine if the product behaviour is correct; a product bug gets a test through a public boundary).
3. **On no failure:** decide per line. If the line's diagnostics are in place and the case has now passed every attempt since its last fix, close it. Close it by moving one sentence to a new "Known intermittent history" section at the end of `docs/perf/B27-intermittent.md`: case, last failure, fix or diagnostics, runs since. Then remove the backlog line. A line with no diagnostics yet gets the smallest diagnostic that would name the cause next time, then closes the same way.
4. **Host-load lines (B15 backup timeouts, B13 e2e stall):** these came from other projects' suites at load 12-43. Check that the affected tests use the 30 s parallel timeout and no fixed sleeps. If they already do, close them as host-capacity events. Otherwise fix the timeout or wait.
5. **`test/tx/measure.ts`:** build each request body when it is sent (or reuse one body) so many-request results are not inflated by pre-built bodies. Re-run only the many-request rows once and note the change in `docs/perf/B26-tx-memory.md`.

Acceptance: `bun run check`, each touched test file, and `bun run e2e` once if any e2e spec changed (under the verify lock).
