## Behaviour

1. **Create** (section 10): slug, name, hostname; primary only when none exists and the hostname is the instance host; validate, create and migrate, seed defaults as a fresh install plus the admin's copy (B140), wire, write the registry last, start loops. Failure before the registry write removes the directory. A leftover directory with no row is reported at start with an attention line and never served.
2. **Edit:** rename; add/remove extra hostnames (unique across projects, lowercase, no port), removal warns that old links to that host stop working. Slug and main hostname never change.
3. **Delete:** the admin types the slug; the project leaves the routing table, drains in-flight requests and sends under today's deadlines, then a final snapshot goes to `backups/deleted/<slug>-<timestamp>.db` (with a tarball of `uploads/` if present), then the directory is removed. Primary deletion: D157 decides (lead's default: allowed, the instance then has no primary and answers as D151 says).
4. **Concurrency:** add, edit and remove are serialized per instance; a same-slug race never deletes the winner. Remove waits for the project's in-flight requests before closing its database.
5. **API:** `GET/POST /api/instance/projects`, `PUT/DELETE /api/instance/projects/<slug>`, instance session plus CSRF, API credentials `401`, never in OpenAPI or MCP.
6. **Pages** (section 13): Projects list with name, hostnames, primary flag, queued marketing count, running campaigns and sent in the last 24 h (from narrow per-project functions returning counts only); create/edit/delete forms. Logs page with instance lines and every project's lines labelled by slug, bounded like today's buffer. The project header shows the project name and a switcher listing projects, each link going through `/admin/instance/open/<slug>`. Server-rendered TSX, Alpine.js, Oat.
