# B9: Amazon SES bounces and complaints

Goal: an operator who sends through Amazon SES gets hard bounces, soft bounces and complaints recorded and acted on automatically, as listmonk does, so the SES account's bounce and complaint rates stay low. Sending through SES already works over SMTP; this adds SES's bounce feedback, which reaches us as Amazon SNS notifications.

## Behavior

1. **Route and settings:** `POST /webhooks/service/ses`, enabled by upstream's setting key, with upstream's responses. Disabled, it answers as upstream does.
2. **SNS signature:** every message is verified before anything is read from it: signature versions 1 (SHA1) and 2 (SHA256), the signing certificate URL must match upstream's `sns.<region>.amazonaws.com` pattern exactly, the certificate is fetched over HTTPS with a timeout and a size cap and cached in memory with a bound. A message that fails any check is refused and changes nothing. Use Web Crypto/`node:crypto`; no new runtime dependency. Fetch URLs are injectable so tests never call AWS.
3. **Subscription confirmation:** a `SubscriptionConfirmation` with a valid signature confirms by fetching its `SubscribeURL`, which must itself be an `sns.<region>.amazonaws.com` HTTPS URL. Never fetch an unverified or off-pattern URL.
4. **Notifications:** `Bounce` (Permanent as hard, Transient as soft) and `Complaint` (as complaint) for each recipient become bounce records with upstream's fields and meta, through the existing bounce store and actions, so the configured soft/hard/complaint actions (blocklist, unsubscribe, delete) apply. A send is matched by the message's headers as upstream matches it. Both SES event-publishing (`eventType`) and feedback-notification (`notificationType`) shapes are accepted, as upstream accepts them.
5. **Duplicates:** SNS retries; a repeated `MessageId` is recorded once, using the durable receipt store from D63 within its bounded window.
6. **Limits:** request body is bounded; network calls never run inside a database transaction.
7. **Docs:** `docs/operations.md` explains the SES setup end to end: SMTP credentials for sending, an SNS topic for bounces and complaints, the HTTPS subscription to `/webhooks/service/ses`, and what to check in the bounce log. `01-scope.md` moves SES out of "later".
