## Items

1. **Data-export mail** shows listmonk's default look (96 px logo, "Powered by listmonk", Helvetica, rounded card), a bare subject "Your data", HTML only, and says "all data recorded on you" (overstated). Render it with the site's branding (logo, site name; the same branding inputs the public shell uses), subject "Your data from <site name>", the B120 text/plain part, and wording "the data this mailing service holds about you" (no "Powered by"). Check the other system mails (opt-in confirmation, password reset, notifications) for the same default look and brand those meant for subscribers the same way.
2. **Wipe copy** reads like cancelling a paid subscription ("Delete all your subscriptions and related data permanently"; confirm "delete all your subscription data permanently?"). Use: "Delete your email data: your address, name and list memberships here. This does not close your account with <site name>." and an in-page confirmation step (a second form/page), not `window.confirm`.
3. **Already unsubscribed:** revisiting the unsubscribe link after unsubscribing shows the same "Do you want to unsubscribe?" form. Show "You are already unsubscribed from these emails." (name the lists where the page knows them).
4. **Dead ends:** the header logo links to `href=""` when there is no subscription page. Add an optional setting `app.site_url` (the operator's own site, e.g. its homepage; validated absolute http(s), D107 rules); the logo links to it, else to nothing (no empty href). The "Done", "Unsubscribed" and "Data removed" pages get a "Back to <site name>" link when `app.site_url` is set.
5. **Error copy** (translations): "Invalid UUID(s)" → "This link is not valid."; "E-mail message not found" for an old link after a wipe → "This link has expired or the data was removed."; the bare "404 - Not found" (also at `/`) → a branded page "Page not found"; "Too many requests" → "Too many requests. Please try again in a minute."
6. **a11y** (adopter, B121 check): the manage page's Name input has no associated label; give it `<label for>`/`id` (this item moves here from B117).

Considered for item 4 (record in D123): reusing `app.root_url` (that is iglo.email's own address, not the operator's site); no link (a dead end on the last page a person sees).
